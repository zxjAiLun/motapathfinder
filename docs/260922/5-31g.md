## 问题与已有证据

接手审计（[cloud-progress-takeover](cloud-progress-takeover.md)）实测出两个可信度缺口：

1. **代码身份漂移**：云端名为 `20260920-5-29a-56f6c7d` 的生产 release 目录里，`dp-search.js` 已被替换成本地未提交的实验代码（`33457b4c…` vs 提交 HEAD `c7fb193a…`）。目录名不能证明实际执行了什么。
2. **fingerprint 覆盖不全**：`resumeSearchFingerprint` 只哈希 `problem/solver-tree/budgets/candidateLimit/limits/scoreFlag/scoreScale`。实测把 `config.dpPriorityMode` 从 `goal-relative` 改成 `resource-first`，fingerprint **不变**——而它确实改变搜索结果。`dpAgendaMode/fairnessEvery/fairOrderMode` 同理未覆盖。

`recoverJournal` 已能在 solver 代码树变化时抛 `SEARCH_SEMANTICS_DRIFT`（treeDigest 覆盖），这次实测正是靠它拦住了漂移账本。但它对“同一份代码、仅有效配置项不同”不敏感。

## 初始设计

- 新增单一权威 `searchSemantics(config)`：把所有真正改变 DP 搜索结果的有效选项规范化为一个对象，默认值严格等于当前生产行为。纳入 `resumeSearchFingerprint`。
- `runAttempt` 从同一个 `searchSemantics(config)` 取值传给 `searchDP`，使 **fingerprint 覆盖的选项 == 实际执行的选项**。当前 neko 配置只设 `dpPriorityMode`，其余取默认，故对现网络行为逐位保持（best-first / fairnessEvery 惰性 / maxActionsPerState 4096）。
- 新增 `executionProvenance(config, towerRoot)`：`{ schema, solverDigest, problemFingerprint, resumeSearchFingerprint, executionIdentity, searchSemantics }`。写入 journal（新建时）与 `status.json`，让 reviewer 不必靠 release 目录名猜执行内容。
- 覆盖字段（本轮）：`dpPriorityMode`、`dpAgendaMode`、`fairnessEvery`、`fairOrderMode`、`maxActionsPerState`，以及为 PR-5.32a 预留的 `continuationSlice { enabled, mode, budget }`。**不纳入** 日志路径、report 文件名、title、scoreLabel 等诊断/输出项。

### 为什么这不是搜索算法改动

`runAttempt` 目前把 `dpAgendaMode/fairnessEvery/fairOrderMode` 硬编码为缺省（等于 searchDP 默认），只从 config 读 `dpPriorityMode`。改成统一从 `searchSemantics(config)` 读取，默认值一一对应现有缺省，因此对当前生产 config 逐位等价。这是让“记录的语义 == 执行的语义”的接线，不改变 DP/键/支配/动作生成。

## 范围与非目标

### 本轮范围
- `searchSemantics` 提取器 + 纳入 `resumeSearchFingerprint`。
- `executionProvenance` + journal/status 记录 solver digest 与有效语义。
- `runAttempt` 从 `searchSemantics` 接线（行为保持）。
- 新增 checker：语义参数变→fingerprint 变；诊断/输出参数变→fingerprint 不变；语义不同→`recoverJournal` 拒绝。
- 运维文档：probe 使用独立目录/bundle，禁止覆盖生产 release。

### 不在本轮 / 未授权
- 不改 DP key、dominance、动作生成、agenda/公平算法本身。
- 不实现 PR-5.32a continuation slice 逻辑（仅在 fingerprint 预留字段）。
- 不重启云端、不迁移旧账本、不覆盖 release。
- 不做部署系统重构；probe 隔离先以 provenance 记录 + 运维约定落地。
- 不修 `shop1` 初态污染（下一轮，PR-5.32a 云端 A/B 之前完成）。

## 合同与不变量

- `problemFingerprint` 不变（初态/阶段/塔/受保护物未改）。
- `resumeSearchFingerprint` **有意改变**：现有 neko 生产账本（resume `a3f4f1b5…`）在干净代码上也将不再自动 resume。这是正确的 fail-closed；该账本云端已漂移，无有效 resume 被破坏。
- 当前生产 config 的搜索行为逐位保持；`check:durable-search` 合成门必须仍 `verified_route`。
- provenance 为记录用途，不进入任何 state key、DP 决策或剪枝。
- 默认值：`dpPriorityMode="default"`（注：neko config 显式设 `goal-relative`）、`dpAgendaMode="best-first"`、`fairnessEvery=32`、`fairOrderMode="fifo"`、`maxActionsPerState=4096`、`continuationSlice={enabled:false,mode:null,budget:null}`。
