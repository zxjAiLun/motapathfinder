# PR-5.31i — Replay Hero Array-Field Snapshot Parity

## 背景

PR-5.31h 把 `restoreRuntimeSnapshotStart` 改为 snapshot 权威恢复后，`shop1` 引导态泄漏消失（live 0 mentions）。但 live 59 步 witness 的整体通过被一个**此前被掩盖的、独立的 pre-existing 变量**阻塞：修复后首个 mismatch 从 `initial.flags.shop1` 变为 `initial.hero.followers: type mismatch (undefined !== object)`。

根因（与 flag 权威恢复无关，属 snapshot-schema normalization 家族）：

- 本路线 record 的 `start.snapshot.hero` 含 `equipment: []` 但**无 `followers` 键**；
- `captureRuntimeSnapshot` 总是输出 `followers: []`；
- `diffRouteSnapshot → diffSnapshots` 做严格 `typeof` 对比，`undefined !== object` 即报错；
- 顶层 diff 按键名排序（`flags` < `hero`），旧 `shop1` mismatch 先报，一直掩盖它。

## 目标 / 非目标

目标：让 `normalizeRuntimeSnapshotPair` 对 hero 数组型字段（`equipment`/`followers`）的“缺失 vs 空数组”做对称归一，使初态 diff 不再产生伪 `undefined !== object`。

非目标：不改任何搜索/DP 行为；不放宽真实差异（非空数组差异必须仍然暴露）；不动 flag 权威恢复、`triggeredAutoEvents` 成员、`deepStableObject`、方向敏感或其它 replay schema 历史。

## 实现

`shared-solver/lib/live-replay.js`：

- 新增 `equalizeEmptyHeroArrayFields(expectedHero, actualHero)`：对 `equipment`/`followers`，当一侧缺该键、另一侧为**空数组**时，把缺失侧补 `[]`；**非空数组**在任一侧都不触碰（真实差异仍暴露）；对 null/undefined hero 安全无操作。
- 在 `normalizeRuntimeSnapshotPair` 末尾（紧接已有“空 floor-record 对称补齐”之后）调用该函数——严格镜像既有 floor 语义。
- 导出 `normalizeRuntimeSnapshotPair` 与 `equalizeEmptyHeroArrayFields` 供契约检查复用。
