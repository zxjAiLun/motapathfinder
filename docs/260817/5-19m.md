## 授权与问题

PR-5.19l 已 `APPROVED / CLOSED`，verdict 为 `MECHANISM POSITIVE / NOT PROMOTED`。当前真实 frozen run 中第二个 opportunity recovery 已 materialize 并创建 parent continuation，但其后续 breakpoint 尚未正式冻结：尚不清楚 continuation 是否 resume、是否重新看到 lethal child、是否编译下一 prerequisite，以及未执行时的确切 scheduler reason。

本轮只回答第二个 recovery 之后实际发生了什么，不改变 solver 行为。

## 本轮范围

- 观察每个 survival-opportunity recovery 后的 continuation lifecycle。
- 记录 opportunity target、post exact fingerprint、post battle stage、HP、damage、survivalMargin。
- 记录 parentContinuationId、anchorNodeId、anchor floor、parent target floor、finalCreated。
- 记录 callsUsedAtRecovery、callsRemainingAtRecovery、totalWorkRemaining。
- 跟踪 continuation resumed、anchor expansion requested/selected、next boundary attribution、next prerequisite compile/schedule/execute。
- 将未执行原因明确分类为 `call-cap-exhausted`、`outstanding-barrier`、`attempt-deduplicated`、`anchor-not-expanded`、`waiting-for-parent-floor` 或 `no-next-prerequisite`。

## 非目标与未授权

- 不调整 call allocation、maxCalls、perCall、total work 或 lazy drain。
- 不新增 connector capability、generic predicate、recovery 行为或 scheduler 行为。
- 不连续抽取第三个 opportunity，不复用同一 witness graph 生成新行为。
- 不引入 scalar ranking、survivalMargin planner objective、known-route input、DP key、dominance 或 replay semantics 变化。

## Breakpoint gate

必须为第二个 witness recovery 提供可复核的 lifecycle attribution，并明确归入以下一种：

```text
Case A: resume → next lethal child compiled → call-cap-exhausted
Case B: waiting → anchor not expanded
Case C: resume → no next prerequisite
Case D: resume + compile → dedupe or another explicit barrier
```

若证据属于 Case A，后续才可另行讨论固定 8 calls 下的 deeper recovery 或已付费 witness graph evidence reuse。该后续工作本轮不授权。
