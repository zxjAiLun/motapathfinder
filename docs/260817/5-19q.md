## 初始设计

5.19o 已消费一次 paid residual：`O2 → O3`。5.19q 只允许在同一 materialized attempt 内再次推进一次：`O3 → O4`。第二次 selection 必须以 O3 为 root，使用同一 `captureComplete` snapshot，按 BFS discovery order 选择第一个 `[O2,O3]` exact-prefix 且 O3-rooted strict replay PASS 的 later named-positive candidate。

实现使用显式 bounded state，而不是开放式循环：

```text
paidResidualRecoveriesUsed = 0..2
5.19o = 1
5.19q = 2
```

即使 synthetic graph 追加 O5，也只能 materialize O4 并停止。

## 本轮范围

- Control 保留 5.19o：O2 materialized → O3 materialized → O3 parent continuation。
- Candidate 在同一 paid snapshot 上选择并 strict replay O4 suffix，然后验证 O4 discrete prerequisite，再 materialize O4。
- 第二次 selection 输入必须是 O3 witness prefix、O3 materialized final state、O3 exact post key 和 O3 discovery ordinal。
- 只有最终 O4 materialization 后创建一个 parent continuation；不创建 O3 intermediate continuation。

## Compatibility and fail-closed contract

Second selection uses:

```text
selectedPrefixEdges = [O2 witness] + [O3 suffix]
selectedPostState = O3 materialized final state
selectedPostExactStateKey = O3 paid post exact key
selectedDiscoveryOrdinal = O3 ordinal
```

For each later named-positive candidate, require:

```text
same originFailedAttemptId
snapshot.captureComplete == true
candidate.witnessEdges has exact [O2,O3] prefix
buildStateKey(selectedPostState) == selectedPostExactStateKey
verifyConnectorChain(O3 state, candidate suffix, expected O4 post key).valid
```

Any failure is fail-closed and preserves O3:

```text
capture incomplete
O3 post-key mismatch
branch-after-O2 / reroot-only
suffix replay failure
discrete completion false
materialization failure
```
