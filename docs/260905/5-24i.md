## 1. 问题定义（来自 5-24h 9.2s Formal Run 的实锤轨迹）

PR-5.24h Real Run 1（9.2s 提前自然返回）暴露的 admission 缺陷：

- depth-1 两个 normal primary ticket 均 `progressClass=SEGMENT_ADVANCE`（positive）；
- 但两个 ticket 均 **determinately exhausted**：`status=PROBE_COMPLETE_OR_GOAL`、`stopReason=exhausted`、`continuationEligible=false`、`goalReached=false`、零 pending；
- 全局还有 20.8s wall 未用；
- 旧规则 `positiveInitial > 0 ⇒ CF blocked`（reason=`normal-primary-progress`）把 CF 永久屏蔽。

这正是 solver 战略能力的核心缺口：**省血路线确实推进过一段，但最终确定走死时，solver 没有把剩余预算拿去尝试资源投资型替代历史**。

## 2. 实现（`shared-solver/lib/segment-dp.js`）

### 2.1 Pure helper `assessCounterfactualAdmission`（B1）

从 `tryAdaptiveCheckpointRepair` 的 inline admission 逻辑抽出，单一判定源，导出供 G31 独立测试。输入：`normalDepthTickets / deferredNormalDescriptors / depthGoalReached / globalStopReason / isTrustedCompleteFailure / failureExecutionDeterminateComplete / counterfactualAlreadyTriggered / intentGeneratorAvailable / normalFirstRoundComplete / realNormalProbedTickets`。输出：`trigger / reason / positiveTicketCount / actionablePositiveTicketCount / terminalPositiveTicketCount / hasPendingNormalWork / hasDeferredNormalWork / hasContinuationEligiblePositive / blockedBy{...} / deferredNormalPresent`。

### 2.2 ACTIONABLE vs TERMINAL positive（B2/B3）

```text
ACTIONABLE positive（仍阻止 CF）——任一：
  continuationEligible = true
  status = PROBE_PENDING
  stopReason = probe-limited
  lastProgress.goalReached = true

TERMINAL positive no-goal（不再单独阻止 CF）：
  progressClass ∈ {WITHIN_SEGMENT_PROGRESS, SEGMENT_ADVANCE}
  AND goalReached = false
  AND status ≠ PROBE_PENDING
  AND stopReason ≠ probe-limited
  AND continuationEligible ≠ true
```

### 2.3 新 admission 条件（B4）

```text
trusted normal tranche complete
AND no goal
AND no ACTIONABLE positive ticket
AND global stop clean
AND trusted failure class
AND failure determinately complete
→ CF triggers
```

reason 分开：`primary-normal-exhausted-no-progress`（历史 no-progress 路径）与 **`terminal-positive-no-goal`**（新路径）。

### 2.4 Deferred normal authority（B8/G31-D 修正）

初版实现曾把 `deferredNormalDescriptors.length > 0` 作为 blocker——**G24-K1 立即证伪**：PR-5.24e 的契约是 deferred secondary 是 *fallback* 工作（CF 先行，CF 无用时恢复 deferred，G24-K3），不是 blocker。已修正为保留原语义：`deferredNormalPresent` 仅作 telemetry 观测字段。

### 2.5 Telemetry（B12）

`counterfactualAdmission` 新增：`positiveTickets / actionablePositiveTickets / terminalPositiveTickets / pendingNormal / deferredNormal / continuationEligible`；`counterfactualRepair.admissionReason` 记录 helper 的 reason。
