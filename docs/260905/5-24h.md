## 目标与背景

在 PR-5.24g Combined Formal Run 2 中证实：
- 图块索引记忆化（Iteration 1）+ 战斗估算管道优化（Iteration 2）使 30s 预算内的有效扩展量从 3,025 提升至 4,642 (+53.5% OBSERVED)；

- 释放的墙钟被全额注入 MT3→MT4 主线探索，使得 MT3→MT4 扩展数翻倍（1,365 → 2,764 扩展），耗时达 13.74 秒；
- 瓶颈已明确转移至 **MT3→MT4 下游规范搜索本体成本**。

PR-5.24h 的目标是：直接针对 **MT3→MT4 这一真实下游瓶颈** 建立固定工作量测试基准，下钻分析其计算开销构成，实施单项安全通用优化。

## 3. MT2→MT3 与 MT3→MT4 每扩展工作量对比与核心归因

对比两者每扩展（per expansion）的结构化指标与耗时分布：

| 指标 (每扩展平均) | MT2→MT3 (520 exp) | MT3→MT4 (897 exp) | 对比与归因 |
|---|---|---|---|
| **Wall 耗时 / expansion** | **21.26 ms** | **11.77 ms** | **MT3 单步扩展反而比 MT2 快近一倍** |
| **CPU 耗时 / expansion** | **22.60 ms** | **12.52 ms** | 同样显著更低 |
| **Battle Resolver 调用 / expansion** | 105.4 次 | 36.6 次 | MT3 上怪物战斗密度相对较低 |
| **Hazard 扫描单元 / expansion** | 3,855 cells | 2,258 cells | MT3 单步危害扫描更少 |
| **Stabilization 通道 / expansion** | 19.7 次 | 11.9 次 | MT3 稳定化震荡更少 |
| **Stabilization 耗时 / expansion** | 14.63 ms | 6.84 ms | 单步稳定化耗时减半 |
| **Primitive 枚举耗时 / expansion** | 2.53 ms | 1.96 ms | 单步枚举耗时更少 |
| **Reachability 耗时 / expansion** | 2.07 ms | 1.42 ms | 单步可达性耗时更少 |

### 核心科学结论（Iteration 1 Repair 1 修正后口径）
- **不是“每步扩展变慢”**：candidate-0 的单位扩展计算成本（11.77 ms/exp）远低于 MT2→MT3（21.26 ms/exp）；
- **candidate-0 单状态搜索并非无法收敛**：在无墙钟限制下，candidate-0 在 897 expansions 即前沿耗尽、确定性完成（`searchComplete = true`）；
- **真实 Run 的 13.74 s / 2,764 expansions 发生在包含多条 MT3 repaired histories 的真实下游 workload**，不能从单一 candidate 的 ms/exp 反推：
  - `CANDIDATE_0_PER_EXP_COST = 11.77ms OBSERVED`；
  - `REAL_MULTI_CANDIDATE_PER_EXP_COST = NOT_DERIVED_FROM_CANDIDATE_0`；
  - `REAL_MT3_MT4_AGGREGATE_EXPANSIONS = 2764 OBSERVED`；
  - 真实 wall 分解应以 worker/process telemetry 为准，而非以单 candidate 的 ms/exp 外推（初稿中“2764 × 11.77 ms ≈ 32.5 s 经多进程压缩至 13.74 s”的推导不成立，已删除）；
- **首要新假设**：`MULTI_CANDIDATE_DOWNSTREAM_WORK_MULTIPLICATION` —— 多条 repaired MT3 histories 使下游重复执行多个规范搜索。该冗余度已在 Iteration 1 Repair 1 中实测（见第 7 节 G28-G）；
- **单 candidate 视角下的优化杠杆参考**（保留作为 per-exp hotspot 参考，不再作为当前主攻方向）：在 candidate-0 的 11.77 ms/exp 中，`stabilization` 占 57.9% (6.84 ms/exp)，其中 `battleScan` (3.28 ms/exp)、`hazardBuild` (1.74 ms/exp) 与 `pickupScan` (1.49 ms/exp) 占比最高。
