## 战斗合同（固定）

无先攻、无特殊技能。

```text
hero.atk <= monster.def                         → attack-blocked（非法动作）
hits          = ceil(monster.hp / (hero.atk - monster.def))
counterRounds = hits - 1
perRound      = max(0, monster.atk - hero.def)
totalDamage   = max(0, counterRounds * perRound - hero.mdef)   ← mdef 一次性抵扣
可战斗         ⇔ totalDamage < hero.hp
```

## 搜索合同

```text
自动 macro action：BFS 折叠无需决策的空地移动；
  当前可达区域边界上的属性资源与怪物作为动作；动作后重新计算可达区域。
结构桶 = 已消费交互 bitset + 当前可达区域 bitset
仅在同一结构桶内使用 [hp, atk, def, mdef] Pareto dominance：
  四维全部不差的状态才能淘汰另一状态
路线只保存 parentId / actionId，不在每个 state 复制完整 route
```

### 自适应调度

```text
默认 CONSERVE_HP 排序。
连续 4 次 expansion 未改善当前可达阻塞怪的词典序 deficit
（attackDeficit 优先，其次 survivalDeficit）
  → 自动切到 BREAK_BOTTLENECK 4 次 expansion → 再重新评估。

该模式只改变 frontier 调度，不改变合法动作，也不改变安全 dominance。
```

达到状态上限必须返回 `RESOURCE_LIMIT`，**不得**声称 `UNSOLVABLE`。

### Iteration 1 — 2026-08-21 — vertical slice implementation

新增 `shared-solver/lib/static-combat-economy-core.js`（11 个导出全部实现）、`shared-solver/fixtures/static-combat-economy-core.json`（5 个固定案例）、`shared-solver/check-static-combat-economy-core.js`、`package.json` 脚本、`solver-manifest.json` 条目。未修改 `strategic-d2-search.js`、任何 5.19 checker、现有 DP、H5Mota loader/event resolver 或 worker pool；未读取任何真实塔 JS。

实现要点：

```text
战斗：attack-blocked（atk<=def）为非法动作；hits=ceil(hp/(atk-def))；
      counterRounds=hits-1；perRound=max(0,monsterAtk-heroDef)；
      totalDamage=max(0, counterRounds*perRound - mdef)；可战斗 ⇔ damage<hp
      （damage==hp 不可战斗，checker 有专门用例）
移动：BFS 折叠。未消费的交互格阻挡通行，因此"走路"没有决策，
      唯一决策是"下一步消费哪个可达交互"。
结构桶：consumed bitset + reachable bitset，与消费顺序无关
        （checker 断言 key 对 Set 顺序不敏感）。
Pareto：同桶内 [hp,atk,def,mdef] 四维全部不差才淘汰；相等也算被淘汰（去重）。
路线：只存 parentId/actionId，回溯重建。
状态：SOLVED = frontier 穷尽且找到目标（hp 最优）；
      RESOURCE_LIMIT = 触到 expansion 上限（可能已有路线但不保证最优）；
      UNSOLVABLE = frontier 穷尽且无目标。上限触发从不写 UNSOLVABLE。
```

`dominated` 计数同时统计"被已有状态拒绝"与"淘汰已有状态"两个方向，否则该指标在真实运行里几乎恒为 0、失去意义。

### H1 — 固定案例 vs 无剪枝 exhaustive oracle（PASS）

四个案例接受 oracle 对照（要求 ≥3），`found` 与最优 final HP 全部一致：

```text
案例                              status       finalHp  oracleHp  route  expanded  dominated  peak  switches
optional-potion-before-gate       SOLVED           60        60      2         4          1     2         1
atk-gem-unblocks-guard            SOLVED           86        86      2         3          0     1         0
detour-for-def-beats-direct       SOLVED           64        64      3         6          2     3         1
permanently-attack-blocked        UNSOLVABLE     null      null      0         2          0     1         0
invest-before-conserve            SOLVED           23       n/a     13      4096      19457  1168       512
```

三个正例各锁一种能力：

```text
optional-potion-before-gate   支线药水可选，solver 必须选择去拿（60 > 直接过关的 10）
atk-gem-unblocks-guard        守卫在拿到 atk 宝石前完全无法造成伤害，宝石被迫成为前置
detour-for-def-beats-direct   直接击杀可行（final 40），但绕路免费小怪 → def 宝石 → 主守卫
                              得到 64。solver 必须放弃"先找到的那条路"，选真正最优的
```

`permanently-attack-blocked` 是反例控制：唯一通路后的守卫 def=50 恒不可破，地图上唯一资源不给 atk。solver 返回 `UNSOLVABLE`、`route=null`，oracle 同样 `found=false`。

`invest-before-conserve` 交互点 13 个，超出 oracle 的实用范围，因此不参与 oracle 对照（H1 只要求 ≥3 个案例对照）；它的作用是 H2。

### H2 — invest-before-conserve（PASS）

相同 `maxExpandedStates=32`，只切调度：

```text
conserveOnly : RESOURCE_LIMIT  foundGoal=false  expanded=32  modeSwitches=0  peakFrontier=71
adaptive     : RESOURCE_LIMIT  foundGoal=true   expanded=32  modeSwitches=4  peakFrontier=140
               finalHp=9  route=6 steps
               toll-guard → atk-gem → armoured-wall → potion-1 → potion-2 → potion-3
```

十个小药水（各 +2 hp）构成并行诱饵口袋。因为药水只会加 hp，**每一个**药水状态的 hp 都高于付过路费之后的状态，所以 `CONSERVE_HP` 必须先把药水子集展开完才肯付 hp；32 次 expansion 内根本走不到 atk 宝石。adaptive 在第 4 次 expansion 因 deficit 无改善切到 `BREAK_BOTTLENECK`，该排序偏好"愿意花 hp"的状态，立刻付过路费 → 拿宝石 → 破 armoured-wall（def=25，需 atk>25）→ 到达目标。

调度不改变合法性：同一问题在充裕预算下两种模式都 `SOLVED` 且最优 finalHp 相同（checker 断言）。

设计过程中的两次修正（记录以免重复踩）：

```text
6 个 +30 药水  → conserve-only 仍在 32 步内找到目标（Pareto 把子集排列折叠掉了，
                 贪心链只用 ~6 步就吃完药水）
8 个 +30 药水  → 仍然找到（懒生成 + 贪心直链，并未枚举 C(8,k) 全部子集）
10 个 +2 药水  → 成立。关键不是药水数量，而是"药水收益必须小于过路费"，
                 这样每个药水状态都排在过路状态之前
```
