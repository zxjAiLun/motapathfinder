## 这一轮证明什么、不证明什么

**证明**：一个语义已经落在静态子域内的原生 H5 楼层，可以被**机械地、逐格可审计地**映射成 `static-combat-economy-core.js` 的受限问题，并由 core 自动求出路线。

**不证明**：与任意 H5 `functions.js` 的语义等价。因此 manifest 中 adapter 记为 `experimental` 且 `correctnessSource=false`。这一点是本轮的边界，不是遗留的待办。

## 严格的数据边界

新增 `shared-solver/lib/static-combat-economy-h5-adapter.js`，只做数据映射：

```text
只接收已在内存中的 H5-shaped project object
不读文件、不 require project-loader、不 loadFunctionsRuntime
不调用 battle-resolver / simulator / event-resolver
不 eval、不用正则去猜某个 effect 字符串在做什么
```

三个导出：

```text
inspectH5StaticFloorEligibility(project)  只读探针，一次列出全部不支持原因
adaptH5StaticFloor(project)               成功返回 problem + provenance；否则 problem=null
mapStaticRouteToH5Steps(adaptation, route) 把 core 路线翻回 H5 格子步骤
```

`floorId` / `hero` / `start` 全部自动取自 `project.data.firstData.floorId` / `hero` / `hero.loc`；`goal` 自动取该层**唯一**的 `changeFloor` 坐标。不接受人工 checkpoint、目标拆分、路线或怪物顺序提示——checker 直接对 fixture 文本断言不存在 `route` / `checkpoint` / `order` / `sequence` 等键。

## 分类判据：`tile.trigger` 而不是猜测

```text
无 trigger + canPass === true    → 可通行地形
无 trigger + canPass === false   → 墙
trigger "battle"   + enemys 类   → monster（须为 plain）
trigger "getItem"  + items 类    → resource（须在 canonical allowlist 内）
trigger "changeFloor"            → 仅当它就是唯一登记出口时作为终止 goal
其它任何 trigger                 → 整层 fail-closed
canPass 既非 true 也非 false     → 整层 fail-closed（未知 tile 绝不当空地或墙）
```

interaction id 为 `floorId:x,y:tileId`，按构造唯一（每格至多一个 interaction），checker 另行断言唯一性与该构造式本身。

### 资源：精确 canonical string contract

只接受白名单内的标准宝石/药水，且 `itemEffect` 必须**逐字符**等于两种 canonical 形式之一：

```text
core.status.hero.<attr> += core.values.<key>
core.status.hero.<attr> += core.values.<key> * core.status.thisMap.ratio

redJewel→atk  blueJewel→def  greenJewel→mdef
redPotion / bluePotion / yellowPotion / greenPotion → hp
```

gain 只由 `project.values[key]` 与 `floor.ratio` 构造，必须是正安全整数。带 `useItemEffect` / `canUseItemEffect` / `equip` 的物品即使 id 在白名单内也拒绝——同一个 id 下的可用/可装备物品是另一套机制。

### 普通怪物

`hp/atk/def` 必须是安全整数（hp 为正），`special` 缺失/0/空数组，`money`/`exp`/`point` 为 0 或缺失，并对 19 个特殊能力字段（`firstAttack`、`vampire`、`counter`、`zoneSquare` …）逐一查空。

## Fail-closed：整层拒绝，绝不改写成障碍

任一不支持内容让**整个 floor** 返回 `eligible=false` / `problem=null`，并给出按 `floorId → y → x → reason` 稳定排序、每条带 `floorId/x/y/reason` 的列表。**不会**把出问题的格子改成 obstacle 后继续求解——那等于悄悄回答了另一个问题。

`changeFloor` 格是**终止** goal：本轮不执行下一层，`goalArchive` 也不得被当作跨层 continuation archive。地图上出现第二个未登记的楼梯 tile 会被拒绝（`unregistered-change-floor-tile`），不会被当成普通地形。

### 复现出的漏洞

复核方给出 7 个反例，全部被 Iteration 1 的 adapter 判为 `eligible=true`：

```text
删除 mapTilesByNumber["11"].trigger   → greenSlime 被当墙，interactions 22→21
删除 mapTilesByNumber["31"].trigger   → 所有 redJewel 被当墙，interactions 22→19
cls=animates + canPass=false + 无 trigger → 当成墙，整层照常适配
hero.mana                             → 静默忽略
enemy.customAura                      → 静默忽略
item.customPickupHook                 → 静默忽略
tile.customCollisionHook              → 静默忽略
```

前三条直接违反 A3 的核心合同——"子域外语义整层 fail-closed，绝不改写成墙"。第 1、2 条尤其严重：**删掉一个 trigger 就能让 interaction 静默消失，而适配依然"成功"**，这正是 A3 本该拦住的那类错误。

### 根因

```text
根因 1  analyzeH5StaticFloor 的 trigger==null 分支只看 canPass，完全没有限制 tile.cls。
        于是任何没有 trigger 的 tile——包括 enemys、items、animates、npcs——
        都会落进 floor/wall 分支。删除 trigger 等于把 interaction 变成地形。

根因 2  hero / enemy / item / tile 只拒绝"已知的危险字段"（开放式 denylist）。
        denylist 只能拦住已经想到的机制；任何未知 key 被静默忽略。
```

两者是同一个错误的两面：**用"看起来没影响"当作忽略的理由**。

### 修复

```text
1  为所有参与语义分类的对象建立封闭 allowlist（不再用开放式 denylist）：
     hero / hero.loc / floor / map tile / item / enemy / changeFloor entry
   allowlist = 本适配器读取的字段 + 显式校验并拒绝的字段 + 逐个列举的纯显示字段
   任何未知 key → unsupported-*-field:<key>，整层 eligible=false / problem=null

2  无 trigger 的 tile 只允许 cls==="terrains" 且 canPass 必须严格为 boolean。
     items / enemys / enemy48 / animates / npcs / 任何未知 cls 在缺 trigger 时
     直接 untriggered-non-terrain-tile，不再落入墙/地板分支。

3  每个 trigger 锁定其允许的 cls 与 canPass 组合，组合不匹配整层拒绝：
     battle              仅 enemys/enemy48 且 canPass===false
     getItem             仅 items          且 canPass===false
     changeFloor(terminal) 仅 terrains     且 canPass===true

4  map number 0 只能是 canonical empty cell。若 mapTilesByNumber["0"] 存在且声明
   trigger、非 terrain class、脚本字段、impassable 或未知字段，整层拒绝
   （否则该定义会静默作用于全图每一个空格）。

5  changeFloor entry 即使本轮不执行也按受限结构校验：
     floorId 必须非空字符串；loc 必须是两个非负安全整数；
     未知字段 / 缺失目标 / 非法 loc 全部拒绝。仍只作终止 goal，不加载目标层。

6  mapStaticRouteToH5Steps 先要求 Array.isArray(route)：
     非数组 → {ok:false, reason:"route-must-be-an-array", steps:[]}
     空数组仍可合法映射（起点已到 goal 的问题就是零步路线）。
```

七个反例复测后全部 fail-closed，且未改写成墙：

```text

delete tile[31].trigger      → untriggered-non-terrain-tile:redJewel:items
```

### 这次漏洞对 adapter 定位的影响

Iteration 1 文档里写的"逐格可审计"其实只在**有 trigger** 的格子上成立；无 trigger 的格子当时是靠 `canPass` 猜的，而猜测正是本轮反复要排除的东西。修复后分类不再有任何"猜"的分支：每一格要么落在锁定的 (trigger, cls, canPass) 组合上，要么整层拒绝。这也把 adapter 的价值边界说得更清楚——它的严格性来自**拒绝面**，而不是覆盖面。
