### 复现出的 false positive（本轮根因）

v1 用列表而不是集合承载 pre-charge flag：

```text
preChargeFlaggedRootCallOrdinals 由 push 收集 → 重复输入会得到 [2, 2]
shadowTimeline 用 Set 判断移除 → reclaimedSlots 只算 1
flaggedBeforeEvent 用同一个列表 filter → 长度 2 → 多扣 1 个 slot

于 maxCalls=8 / actualCallsExecuted=8 / queuedCount=1 / maxOutstanding=2：
  正确：shadowCallsExecuted=7，shadowCapacity=0 → 不可 selectable
  v1  ：shadowCallsExecuted=6，shadowCapacity=1 → shadowWouldBeSelectable=true（假正）
```

两处对同一事实使用了不同的去重语义，账本自相矛盾。Repair 1 把 flag 收集改为 `Set`，`flaggedBeforeEvent` 只从唯一 flagged set 计算，并把重复输入本身记为 fail-closed 证据。该用例已作为锁定 regression 写入 checker。

### 严格类型（移除 Number() 宽松转换）

```text
所有计数与 ordinal 必须 typeof number 且 Number.isSafeInteger
正整数：call/event ordinal、maxCalls、maxOutstanding
非负整数：hierarchyLevel、expansion、callsExecuted、queuedCount、callsRemainingAfter
"8" / true / NaN / Infinity / 负数 / 小数 一律不得进入完整证据
```

无效字段在输出中归一为 `null`，绝不把 malformed 值当作数字继续参与计算。

### 校验合同

```text
preChargeComparisons：callOrdinal 唯一正整数；classification ∈ 5.19w 完整 10 类集合
  输出 preChargeFlaggedRootCallOrdinals 去重并排序；重复值记入
  duplicatePreChargeCallOrdinals 并 fail-closed（结果仍只保留一次 ordinal）

chargedCalls：callOrdinal 唯一且严格 1..N，N<=maxCalls；attemptId 非空字符串；
  expansion 非递减；callsRemainingAfter === maxCalls - callOrdinal；
  flagged call 必须实际 charged 且 hierarchyLevel=0
  ledger 不完整 → 所有 event 的 shadowCallsExecuted/shadowCapacity 置 null、
  shadowWouldBeSelectable=false（accountable=false）

continuationSelectionEvents：eventOrdinal 唯一正整数；五个数值字段严格整数；
  continuationId/nextPrerequisiteId/nextPrerequisiteAttemptId 非空字符串；
  dedupeSeenBeforeSelection/actualSelected 为 boolean；
  event.maxCalls 严格等于顶层 maxCalls；actualCallsExecuted <= 实际 charged ledger

gate 一致性（镜像 live gate chain：cap → outstanding → dedupe）：
  selected=true  → reason=null 且 queued<maxOutstanding 且 capacity>0 且 dedupeSeen=false
  selected=false → reason ∈ {call-cap-exhausted, outstanding-barrier,
                             attempt-deduplicated, no-selection}
    call-cap-exhausted  → callsExecuted >= maxCalls
    outstanding-barrier → callsExecuted < maxCalls 且 queued >= maxOutstanding
    attempt-deduplicated→ callsExecuted < maxCalls 且 queued < maxOutstanding 且 dedupeSeen=true
    no-selection        → 前三类条件均不成立
  矛盾 snapshot 一律 fail-closed
```

保守边界（有意）：`shadowWouldBeSelectable` 仍**只**在 `actualBlockingReason = call-cap-exhausted` 时可能为 true。若某次阻塞被 live gates 记为 `no-selection`（capacity 恰好为 0 但三道 gate 条件都不成立），本轮不声称它可回收 —— 宁可少报，不可多报。真实 trace 不受影响（ev#4 就是 `call-cap-exhausted`）。
