### Continuation selection 事件（只读）

在 parent-continuation 编译 `nextPrerequisite` 并调用 `selectFeedbackAwareDependencyAttempts` 的位置增加只读事件，每条至少记录：

```text
eventOrdinal / expansionAtSelection / continuationId / hierarchyLevel

```

`actualBlockingReason` 必须与现有 selection gates 一致（直接取既有 `witness.statusReason`，不第二次调用 selector，不修改 dedupe）。

### Shadow accounting 合同

对每个事件：

```text
flaggedBeforeEvent   = 已在该事件前实际 charge 的 flagged root callOrdinals
shadowCallsExecuted  = actualCallsExecuted - flaggedBeforeEvent.length
shadowCapacity       = maxCalls - shadowCallsExecuted - queuedCount

shadowWouldBeSelectable = true 仅当
  actualBlockingReason === "call-cap-exhausted"
  且 shadowCapacity > 0
  且 queuedCount < maxOutstanding
  且 dedupeSeenBeforeSelection === false
  且 证据字段完整
```

8 个实际 call 的 accounting timeline：被 shadow 移除的 call 标记 `shadowCharged=false` / `shadowOrdinal=null`，其后未移除 call 的 `shadowOrdinal` 顺延减一。

这里只证明 accounting eligibility：不执行 next prerequisite，不生成 call #9。
