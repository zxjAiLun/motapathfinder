## 本轮范围（observation-only）

在 5.19q/r/s 同一 frozen A/B 上，按 charging 顺序记录 8 个 calls：

```text
call #1..#8:
  callOrdinal
  hierarchyLevel
  attemptId
  expansionAtCharge
  callsRemainingAfter
  firstHierarchyActivationOccurred（charge 时）
  activeContinuationCount（charge 时）
  productive（search-end 回绑，attemptId 主键）
  directSatisfied
```

锁定三个 checkpoint：

```text
A. first parent continuation created
B. first hierarchy-priority activation
C. first level-1 call charged
```

每个 checkpoint 输出：

```text
expansion
callOrdinal（当时已 charged 的 calls）
rootCallsSpent
callsRemaining
childCallsSpent
```

五个 root calls 分析：

```text
按 callOrdinal 列出 productive / directSatisfied / firstHierarchyActivationOccurredAtCharge
first hierarchy activation 前/后的 root calls 数量
```

## Key gate（回答后才有资格设计 reallocation）

```text
若 first hierarchy activation 时 root calls spent = 5、remaining = 3：
  → 解释为何最终只有 level1/2/3 三个 child slots，depth-4 必然撞 cap。

root call #5：
  若 charge 时无任何 hierarchy signal 且最终 unproductive
    → 支持下一轮测试 non-oracle static-reserve（root ceiling=4）
  若 root call #5 正是生成后续 productive chain 所需的 direct satisfied call
    → 简单 5→4 会剪掉整条 hierarchy
```

两者都不在本轮执行；本轮只出时序事实。
