## 本轮范围（observation-only）

对每个 root attempt 记录 charge 前就存在的语义向量：

```text
callOrdinal / attemptId（身份显示）
sourceNodeId / sourceDepth / sourceFloor
prerequisiteKind / stageGoal
parentDependencyKind / parentDependencyCapability
reachableAtCompileTime
boundary classification（enemyId/x/y 仅身份显示，不作为区分特征）
battle stage before connector / attackMargin / damage / survivalMargin
source terminal-blocker projection（progressScore）
compiledCandidateRank / compiledCandidateCount
queue/selection context（queuedCount、callsRemainingAfter、firstHierarchyActivationOccurred）
```

search-end 只绑定 hindsight label：

```text
directSatisfied
productive
```

禁止把以下任何一项作为 pre-charge discriminator：

```text
connector satisfied
connector expansions actually used
productive
future continuation
O1/O2/O3/O4 outcome
attemptId / enemyId / 坐标（只能身份显示）
```

## 分类合同

```text
U1 = SEMANTICALLY SEPARABLE
     ∃ 单个通用 semantic feature f：f(#5) != f(#i) 对所有 failed root i
U2 = FEATURE COLLISION
     #5 的冻结 semantic vector 与至少一个 failed root 完全相同
U3 = ONLY TEMPORALLY SEPARABLE
     semantic vectors 全同，只有 ordinal/expansion 能区分

```

组合可区分（每个 failed root 都与 #5 不同、但无单一 feature 全分离）如实报告为 `U1-COMBINATION-ONLY`，不冒充 U1。

## Repair 1 — Root Candidate-Pool Availability Attribution + Classification Hardening

Review verdict（原 5.19u）: REQUEST CHANGES。P1=1，P2=2。

- P1 根因：5.19u 只比较五次已 charged 的 root calls（五次全是各自 source 的 `compiledCandidateRank=1/compiledCandidateCount=4`），不是共同候选池；无法证明 productive #5 或同类正 attackMargin candidate 在前四次选择事件中已可用，也无法证明局部 reordering 能把 #5 提前。
- P2-1：分类混用 `JSON.stringify` 与字段级 `!==`。
- P2-2：checker 的 isolation A/B 与 second-residual feature A/B 耦合。

### Repair 1 变更（commit `e183599`）

- 提取 `buildRootAttemptSemanticVector` 纯 helper，charged call 与 compile-site candidate 共用，杜绝字段漂移；`enemyId/x/y` 仅身份显示，不进入 semantic。
- `enableRootAttemptSeparabilityAttribution` 开启时，root compile-site 在 `selectFeedbackAwareDependencyAttempts` 前后记录完整 `rootCompileEvents`（compileEventOrdinal/expansionAtCompile/source*/callsExecuted/callsRemainingBefore/queuedCount/maxOutstanding），每个 compiled prerequisite 含 dependencyAttemptId/prerequisiteId/localRank/selected/dedupeSeenBeforeSelection/identity/完整 semantic vector；记录只读，不改变候选排序、dedupe 顺序或 enqueue。
- search-end 将 charged root calls 按 attemptId 精确连接 selected compile candidate（`chargedToSelectedCandidate`，要求 matchedSelectedCandidateCount=1 且 matchedSemanticEqual=true），输出 `chargedEventSummaries`（五池紧凑结果）与 `availability`（更早池中正 attackMargin / 同 attempt / 同 identity 候选 + verdict）。
- 分类统一 `node:util` 的 `isDeepStrictEqual`；U2=部分 collision、U3=全部 collision（仅 temporal 可分）、U1=单一 feature 全分离、U1-COMBINATION-ONLY=组合可分、U4=其余；输出 `vectorEqualityDetails`；`classifyRootAttemptSeparability` 导出供 synthetic 测试。
- checker 增加 `runWithSeparabilityIsolation`：control/candidate 开启完全相同的 q/second-residual/hierarchy 行为，只切换 separability 观测；比较除 wallMs 与 attribution 字段外的 outcome/bestTerminalBlocker/核心 stats/8 个 charged witness identities/residual-materialization 结果。second-residual feature-off leak 继续由独立 q checker 负责。
