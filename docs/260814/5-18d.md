## 问题与已有证据

PR-5.18c 已把 connector 与 lazy-resolution 机制收口为 `VERIFIED / NOT_PROMOTED`：终端-directed connector 在 1000 strategic + 1979 connector = **2979 total search work** 下 `connectorResolved=0 / terminalActionGenerated=0`。机制正确，但“从当前 state 直接要求 bounded connector 接到 terminal action”是粒度错误。

终局 blueKing 在起点为 `attack-blocked`，ATK 缺口 `-1223`；战略 frontier 已经能找到 `-923`（5.18b），证明它能看到“朝正确方向”的状态，但直接把 connector 指向终局 action 距离太远，1979 次局部展开都接不出去。

因此问题不是“看不到局部收益”，而是需要把 connector 从“接终局 action”改成“接由 blocker 推导出的下一步中间目标”。

## 初始设计

把终局 blocker 读成一个**命名的中间依赖**，而不是二元 unbeatable：

```text
terminal blocker
    ↓ analyze
attack-blocked → combat-power 依赖 (raise ATK)
lethal         → survival     依赖 (raise HP/DEF)
viable         → 无需中间目标（terminal 已可达）
```

bloker-derived connector 运行一个**有界局部优化**，在预算内最大化该中间度量（默认就是 `terminalBattleProjection.progressScore`，与战略 agenda 已排序的量一致），返回最佳中间状态 + 严格可重放的 primitive chain，并**在该中间状态上重新评价 terminal blocker**。

```text
current state
    ↓ analyzeTerminalBlocker
intermediate metric (combat-power / survival)
    ↓ bounded local optimizer
best intermediate state + exact pre/post edges
    ↓ re-evaluate
terminal blocker 是否前移
```

`metric` 可注入，便于 synthetic control 独立验证优化语义，不必伪造 battle resolver。

## 范围与非目标

### 本轮范围

- `analyzeTerminalBlocker`：把终局战读取为 `stage/attackMargin/survivalMargin/progressScore`。
- `runBlockerDerivedConnector`：有界 local optimizer，返回最佳中间状态 + 边 + 重新评价后的 blocker。
- `connectorMode = terminal | blocker-derived`，并接入 `blocker-connector-choice` 惰性工作。
- 记录 `bestTerminalBlocker`（全局最佳 progressScore/attackMargin 及其 node）。
- `maxTotalSearchExpansions`：strategic + connector 共享的 total-search-work 预算。
- 相同 total-search-work A/B：strategic-only vs blocker-derived，比较最佳 terminal blocker progress、terminal action、connector resolution。

### 不在本轮 / 未授权

- 不进入 dominance / action-order normalization / D3。
- 不读取 known route、人工 milestone、人工事件顺序或资源阈值。
- 不硬编码 I894 / 坐标 / 装备。
- 不靠单独提高 connector 预算、总 expansions、wall 或 queue 权重掩盖缺口。

## 合同与不变量

- 输入仍为 tower、route-free current state 与 terminal goal。
- blocker 分析只用 simulator 的真实 battle evaluation，不引入手工阈值。
- connector 的 best chain 必须经 `verifyConnectorChain` 逐边 exact re-resolution。
- `bestTerminalBlocker` 只升不降；不能把“无进展”误写为“前移”。
- total-search-work = strategic + terminal-connector + blocker-connector expansions。
- 中间目标的度量与战略 agenda 的 terminal-blocker 评价使用同一 `progressScore`，避免两套口径。

## 结果与决定

当前状态：`VERIFIED / NOT_PROMOTED`。

blocker-derived intermediate connector 的机制正确（每次调用都能改进局部 blocker，`blockerConnectorImproved=8/8`），但在相同 total-search-work 下，全局最佳 terminal blocker progress 仍为 `-903`，与 strategic-only baseline 完全相同，且 wall 更慢（原实现本机约 1.9x；Repair 1 重跑约 1.6x，wall 仅方向性）。因此 terminal prerequisite 没有真正前移，不能晋级为默认 D2 路径。

云端 review（2026-08-15）认可 `VERIFIED / NOT_PROMOTED` 研究结论，但对新 shared-budget API 与收口证据提出 `REQUEST CHANGES`（P1×4 + P2×1）。Repair 1 已修复并本地复验；待云端复核通过后以 `VERIFIED / NOT_PROMOTED` 关闭。

## 已知限制与不宣称

- 中间度量默认就是战略 agenda 已经排序的 `progressScore`，因此 bounded local optimizer 只是在重复战略 frontier 已做的 terminal-blocker-progress 搜索，没有带来新的发现能力。
- connector 是 bounded local search，不是 canonical correctness proof。
- 本机 wall 只作方向性；同 total work 下不得只比较 wall。
- 当前不宣称 D2 closure；terminal action 仍为 0。
- Repair 1 的本地证据已通过；`qualification-strategic-blocker-connector` 的远端 CI 结果需在本次 marker push 后由云端 agent 复核绑定。
