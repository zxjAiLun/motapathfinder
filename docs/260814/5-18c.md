## 问题与已有证据

PR-5.18b 已将 primitive variants 聚合为 choice-level `StrategicTransition`，并建立 reachable-POI、机会成本、不可逆成本、lineage novelty 和 terminal blocker progress。

终局 blueKing 在起点为 `attack-blocked`，ATK 缺口 `-1223`；最好 witness 改善到 `-923`，1000 expansions 内有 1025 个 transition 改善 blocker progress，但没有生成终局动作。因此问题不是“完全看不到局部收益”，而是直接 primitive frontier 尚未把这些收益连接成可达终局的合法链。

仍有三类显式未完成工作：

- 407 个非 canonical exact post 只记录未展开；
- 无法由当前 primitive action 直接执行的战略 choice 没有局部连接器；
- floorFly 直接全展开会产生 travel-variant explosion，当前被延期。

## 初始设计

战略层只决定“值得尝试哪个 choice”，局部 DP 只回答“能否从当前 exact state 合法到达并执行它”。局部 DP 不得决定全局路线目标。

计划数据流：

```text
strategic choice
    ↓ direct primitive action available?
yes → aggregate/apply exact posts
no  → bounded local connector
          ↓
      primitive decision chain + exact post states
          ↓
choice-level lazy resolution
    ↓
strategic frontier
```

travel variants、deferred exact posts 和 floorFly 都以同一惰性接口解析：首次只调度 choice；只有该 choice 被抽取或直接分支不足时，才支付连接和 variant 展开成本。

## 范围与非目标

### 本轮范围

- 定义 local connector 请求、结果、预算和失败分类。
- 对 direct-unavailable 终局 strategic choice 调用有界局部 primitive connector；通用 POI target builder 只作为接口，不宣称已接入全局调度。
- 将 connector 产出的 primitive chain 绑定 exact pre/post state。
- 惰性调度 PR-5.18b 的 deferred exact posts。
- 将 floorFly 聚合成战略 choice，按需解析 travel variants。
- 对所有 deferred/failed/resolved 工作提供计数与 witness。
- 使用相同 D2 起点、terminal goal 和 1000 strategic-frontier-expansion 控制与 5.18a/5.18b 比较，并单列 connector 的额外 expansions。

### 不在本轮 / 未授权

- 不读取 known route、人工 milestone、人工事件顺序或资源阈值。
- 不修改 production DP key、dominance 或 simulator mechanics。
- 不通过增加总 expansions、wall timeout 或 queue 权重掩盖 connector 缺口。
- 不进入 5.18d 的 strict dominance/action-order normalization。
- 不宣称 D2 closure，除非完整 primitive chain strict replay 通过。

## 合同与不变量

- 输入仍为 tower、route-free current state 和 terminal goal。
- connector 必须从调用时 exact state 开始，返回可重放 primitive decisions 和 exact post state。
- direct path 与 connector path 到达相同 exact post 时允许合并；不同 exact post 不得静默丢弃。
- deferred work 必须处于 `queued/resolved/rejected-with-reason` 之一，不能只增加计数后消失。
- floorFly 的 choice identity 与 travel variant identity 保持分离。
- 启发式只决定何时解析，不得把未解析分支报告为已穷尽。
- `searchComplete=true` 要求 goal found，或 active frontier、deferred work 和 connector work 全部穷尽。
- 找到目标后必须重建 primitive decision chain、构建 route record 并 strict replay exact final state。
- generated outputs 写入 ignored/generated 目录；不提交一次性 summary 脚本。

## 验收与拒绝门

| Gate | Evidence | Pass condition | Meaning |
| --- | --- | --- | --- |
| Connector legality | synthetic + real local control | 每条 connector chain 可从 exact input 严格执行到 recorded exact post | connector correctness |
| Lazy exact-post recovery | alias/deferred controls | 非 canonical post 可按需进入 frontier，且没有数组顺序依赖 | 关闭 5.18b deferred gap |
| Lazy floorFly | variant-explosion control | choice 级占槽，只有按需解析 variant；不再在根节点生成上千 frontier entries | 控制展开成本 |
| Completeness accounting | outcome contract | unresolved work 时 `searchComplete=false`；穷尽声明包含所有 lazy queues | 诊断可信 |

| Goal closure | route record + strict replay | 若 goal found，完整 primitive chain 与 final exact state 一致 | D2 closure 的必要条件 |

若 connector 只增加 wall/branches、没有使 terminal action 或依赖链更接近可执行，结果仍是有效 `VERIFIED / NOT_PROMOTED`，而不是基础设施失败。

## 最终实现

- `shared-solver/lib/strategic-connector.js`：`runLocalConnector`（有界 FIFO primitive 搜索，目标为 choice 或 goalPredicate），逐边记录 exact pre/post；`verifyConnectorChain` 从当前状态重新枚举并按 exact post 解析每一步。失败分类为 `budget-exhausted`/`frontier-exhausted`/`frontier-trimmed`/`resolved`。
- `shared-solver/lib/strategic-lazy-work.js`：`LazyWorkQueue`，三类工作 `deferred-exact-post`/`floorfly-choice`/`connector-choice`，生命周期严格 `queued → resolved|rejected`，带计数与 rejection reason。
- `shared-solver/lib/strategic-d2-search.js`：deferred exact post 进入 lazy queue；floorFly 按 target-floor choice 聚合并保留非 canonical exact posts；当前只对非直接可枚举的终局 choice 调用 connector；connector chain 经独立 replay 后逐节点完整初始化进入 frontier；输出 connector/lazy 与分作用域预算统计。schema 升到 `strategic-d2-search.v3`。
- `shared-solver/lib/strategic-transition.js`：额外导出 `summarizeResourceDelta`（供 macro transition 复用）。

## 结果与决定

当前状态：`VERIFIED / NOT_PROMOTED`。

connector 与 lazy-work 机制已实现并通过 focused contract，但正式 run 的 1000 strategic expansions 之外又消耗 1979 connector expansions，终局 choice 仍 0 次 resolved（15 budget-exhausted / 1 frontier-exhausted），`goalFound=false`。这是有效的有界 not-found：当前 terminal-directed connector 增加了 1.979 倍额外搜索工作，却没有生成 terminal action，不能晋级为默认 D2 路径。

## 已知限制与不宣称

- connector 是有界局部 primitive 搜索，不是 canonical correctness proof。
- connector 对终局 choice 在本轮预算内 `connectorResolved=0`，未产生 terminal action。
- lazy resolution 是 demand-driven，不是穷尽；`searchComplete=false`。
- 当前仍不宣称 D2 closure；若 goal 出现仍需完整 primitive chain 重建 + strict replay。
- 本机 42.719s 是方向性数字，不是稳定性能承诺；不同预算作用域下不得只比较 wall。
