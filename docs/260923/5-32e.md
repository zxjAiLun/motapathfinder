## Iteration 1 — 2026-09-23：真实代表链与队列接续

### 结果摘要：问题出在哪

**不是 P14 把通路剪没了，而是可继续走的 P16 留在全局队列，后来的局部 slice 没有接上它。** 这里有两个可区分的服务机制，不把它们笼统叫做 dominance bug：

1. **首次生成时被距离排序推后**。P16 `battle:skeleton@TS13:1,9`，node **26836**，parent 26784，HP5245，在 expansion **10547** 入队。它的 goal-relative distance=13；当时 root764 的 slice 尚有12次服务，实际所选距离均为7/9/11，全部排在P16前。P16未被淘汰，但本窗口没轮到它。
2. **再次到达时没有接续旧节点**。root1339 于17967获得slice，P15 node46698于17978弹出；其P16后继与已存在node26836具有相同 exact key、DP key、HP、depth/raw=47/110。新候选被 `dominance-rejected` 后，`enqueue` 直接返回；现有代码只在**新注册节点**时才把节点放入 `continuationSliceHeap`，没有把旧的live代表放入当前局部视图。
3. **这次不是改权重才能接上**。第二窗口还剩20次服务，下一次实际选node46707（distance15）；原生产comparator比较 `selected - P16 = -2`，即若P16在当前local view里，它应先于这个实际所选节点。这里只证明下一次pop的排名关系，**没有跑借用节点后的完整反事实搜索**，不能预报32k必定到TS14。
4. **全局兜底未及时服务**。P16入队之后的1,525次global best-first选择均由更小`nextDistance`胜出；final fairCursor=2694，而P16 fairQueueOrdinal=26836。P16到32000停止时仍active、未pop、未evict，等待了**21,453 expansions**。从完整insert/pop/evict事件独立重建的final active-unexpanded集合=44,885，与solver frontier精确相同。不是无限饥饿证明。

### 实战后缀能力验证

- 以冻结solver/bundle对真实parent链做离线动作枚举重建：**37条不同边**逐条都只有一个canonical action匹配实际子节点exact hash；所有恢复节点的live decisionDepth/rawRouteLength也严格相等。没有依靠分散checkpoint猜parent。
- node26836与从node46698再生成的P16完全相同的是canonical exact key；完整对象的`hero.steps`和是否物化route不同，不能称逐字节对象全等。
- 从恢复的node26836执行剩余**14步**已知后缀，所有exact key逐步匹配5.32d incumbent后缀，抵达**TS14 / HP5703 / ATK12**，受保护绿钥匙始终34。
- 后缀先返回TS12/TS11补资源，再回TS13处理吸血鬼/巨石等。这是为什么“接近出口”不等于“已具备过关资源”的实战例子，但本轮不凭这一例直接发明通用feasibility评分。
- 原始P16 rejection没有捕获incumbent列表；**不声称它的唯一拒绝见证就是26836**。已存在且未被淘汰的26836自身保留后缀能力，足以定位服务断点。

### 代码定位

- `shared-solver/lib/dp-search.js`：`isBetterForSameDpKey`维持HP/depth/raw排序；`enqueue`的dominated分支发observer事件后`return false`。
- 同文件新节点入队分支：仅`nodes.set` / skyline插入成功后的新节点进入`continuationSliceHeap`。这是既有tree-descendant slice语义，不是运行时异常；将其扩展为confluence-aware view属于需要显式fingerprint/test的新调度语义。
- `compareDpAgendaRankForMode`：在同bestFloorRank/finite-distance下，先比较nextDistance，再比较source-action/resources。`popFair`只在global fair service推进cursor；slice的本地服务不等于FIFO队列继续推进。
- 下一最小方向是保留canonical DP权威、借用已存在exact-confluent代表进入local view；不是允许重复state注册、更改dominance或复制route parent。
