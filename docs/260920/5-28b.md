## 初始设计与不变量（结果前冻结）

1. 先做独立进程、固定工作量诊断：三个真实TS13 fixture中的代表入口，先8k展开；对比不显式GC与定点GC的post-GC live set。只存聚合指标、序列hash和必要的局部heap采样工件，不保存无限事件列表。
2. 利用已有observer观察skylineInserted/skylineEvicted/agendaPopped，按楼层统计服务、等待及pending。不得让这些统计反向参与搜索决策。
3. 需要对象归因时先在小语料上使用V8 allocation sampling/heap snapshot；本机只有约4.6GiB空闲，禁止直接生成5GiB进程的大heap snapshot。初始诊断另设不高于2GiB heap/3GiB RSS的安全停止线，语义对照要求两臂均完成同一固定工作量。
4. 只有诊断支持后才实施最小修复。优先内存表示、对象生命周期或透明GC管理；不得修改DP key、dominance、排序、动作集合、flags、protectedItems、skyline容量或回放规则。不能移植历史实验家族的行为变化来掩盖问题。
5. 生产worker继续6144MiB old-space、5222MiB heap stop、8192MiB RSS stop、整个云端进程组9GiB保护。云端只能隔离新release，不热覆盖现有release；旧账本与基线证据保留。
6. 初始态与fixture固定，不加入已知路线、怪物特例或人工属性门槛。Preview仍然不是resume checkpoint。
