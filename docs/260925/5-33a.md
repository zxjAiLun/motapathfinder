## Evidence before implementation

Read-only review reproduced these failures using Node micro examples (no cloud search):

1. `enumerateFloorFlyActions` merges by target floor, although the departure location changes `flags.__leaveLoc__` and future return landings. A two-floor closing-passage example is MISS with current target-only merging; retaining distinct departures finds the two-flight route. Neko enables `flyRecordPosition`, but this is not a causal diagnosis of its live search result.
2. `events.js` treats every `function` as a no-op and unknown actions such as `unloadEquip`/`insert` as notes. A real synthetic `runAttempt` returns `strictReplay: true` despite those unsupported state effects. Neko Boss has those action types; internal replay is not runtime parity.
3. `triggeredAutoEvents` affects one-shot execution but is absent from exact/DP keys. Supported actions can produce two stable, equal-key states whose next identical action yields HP250 versus HP200. Neko TS11–TS15 auto-event maps are empty; this is a general contract failure, not a demonstrated Neko blocker.
4. DP catches provider/apply errors; the completion classifier can still report `searchComplete: true`. Normal rejected actions must remain distinct from infrastructure/model errors.
5. The durable coordinator shortens `workerConfig.budgets[tier].runtimeMs` for the remaining total budget but sends the original execution identity. A 1s total / 5s task example fails with `WORKER_IDENTITY_DRIFT` before completing a task.
6. One DP expansion with floor flying performs two walk-reachability builds (primitive plus fly), although the fly API accepts a shared scan.

Existing baseline checks passed individually: manifest, no-tower, core, floor-fly, directional-movement, green-key-budget, search-semantics-identity, durable-search, search-outcome-taxonomy. “174 modules / 236 graded tests” is manifest inventory coverage, **not** evidence that all 236 tests executed.

## Initial design (frozen before implementation)

### Action completeness and safe reuse

- Preserve floor-fly variants with different future state/departure records. Dedup may only merge equivalent action states, not all actions sharing a target floor.
- Reuse the primitive enumeration's walk scan inside the same combined enumeration. Keep the old primitive-only API and custom action providers compatible. Do not add a long-lived state cache.
- Replace the local-Neko-only floor-fly check with a clean-checkout tiny-map contract: positive/negative tool/blocker/visited-floor controls, distinct return landings, real DP closure, and scan-call count. Reuse existing test files.

### Event support and search failures

- Presentation-only actions can remain explicit no-ops. Arbitrary scripts and unsupported state effects must no longer silently certify a route.
- Share support classification between event enumeration and execution; preserve explicit unsupported/model errors through the canonical search and durable boundary. Do not implement arbitrary JavaScript or all H5Mota event types in this round.
- Keep diagnostic observer exceptions non-semantic. Distinguish normal inapplicable successors from actual provider/execution failures; failures cannot produce a complete-search claim or a durable verified terminal.
- Unknown Boss terminal effects may therefore become an explicit blocker instead of a falsely self-consistent result. Full Boss semantics and browser parity require their own follow-up.

### State identity and replay

- Include nonempty one-shot auto-event history in exact and DP identity and preserve it through snapshot/restore and affected state projections.
- Missing/empty history remains the legacy empty state where safe. Nonempty history cannot silently disappear or be inferred from unrelated fields. Do not change HP dominance or introduce a new state abstraction.
- Any nonempty-history identity change is intentional; old incomplete snapshots cannot be silently treated as fully equivalent.

### Runtime budget and identity

- Keep the configured problem/search identity stable; pass the remaining attempt deadline as an execution bound rather than rewriting the fingerprinted configuration.
- Validate deadline bounds and retain rejection of real code/config drift. Add an actual subprocess regression for a shortened final attempt.

### Iteration 2 — 2026-09-25 — events + failure taxonomy (evidence 2 & 4)

- `events.js` is now the single source of truth for `NOOP_EVENT_TYPES` (including `function`, kept as a documented presentation no-op), `STATE_CHANGING_EVENT_TYPES` and `SUPPORTED_EVENT_TYPES`; it exports a new `UnsupportedEventError` (`code = UNSUPPORTED_EVENT_ACTION`, carries `eventType`). `executeAction` throws on unsupported/unknown action types, and the `setValue`/`setBlock`/`autoEvent` loop-limit guards throw instead of pushing advisory notes. `event-resolver.js` imports the shared sets so enumeration and execution cannot drift; its mutually-recursive `isStateChangingAction`/`actionListHasStateChange` helpers stay local.
- `function` stays a no-op deliberately: `event-resolver` classifies it as a supported presentation action, so throwing on it would make enumeration and execution disagree and would break floor-arrival presentation events. Only genuinely unrecognized state-changing types (`unloadEquip`/`insert`/`unfollow`/nested `if`) throw.
- `dp-search.js` counts `providerErrors` and `applyErrors` at all four provider/apply catch sites and threads `modelErrors = providerErrors + applyErrors` into the outcome. `search-outcome.js` adds a fifth outcome dimension `modelErrorsEncountered`: when errors occurred and the search is not complete the class gains a `-model-errors` suffix and `searchComplete` is forced false; the aggregation across attempts propagates it. `solver-doctor.js` sums model errors and prints an explicit "NOT exhaustive no-route evidence" warning on feasible-incomplete and failed lines. `durable-search.js` surfaces `modelErrors`/`modelErrorsEncountered` in stats.
- New `check-unsupported-event-fidelity.js` PASS: `unloadEquip`/`insert`/`unfollow`/nested-`if`/malformed `setBlock` throw `UnsupportedEventError`; `function`/`setText` stay no-ops and `setValue` still applies; an injected apply error yields `modelErrors = 1`, `searchComplete = false`, class `goal-not-found-search-incomplete-model-errors`, and a doctor warning; a clean control still completes. `check-search-outcome-taxonomy.js` updated for the fifth dimension (all expected rows carry `modelErrorsEncountered`, two model-error rows added, `completenessNarrowed: "model-errors"`). `check-dp-observer.js` and `check-core-regressions.js` stay green.
- Consequence: an unknown Boss terminal effect now becomes an explicit blocker/model-error instead of a silently "verified" terminal. Full Boss semantics and browser parity remain out of scope.

### Iteration 4 — 2026-09-25 — operational deadline vs semantic identity (evidence 5)

- The durable coordinator no longer mutates `budgets[tier].runtimeMs` inside the fingerprinted config. `run-durable-search.js` passes the unshrunk `config` (so the worker recomputes a matching execution identity) plus a separate `runtimeDeadlineMs`, and arms the SIGKILL net from the effective (min of budget and remaining) runtime. `durable-search.js` `runAttempt` accepts `options.runtimeDeadlineMs` and runs `searchDP` with `maxRuntimeMs = min(budget.runtimeMs, max(0, deadline))`. The fingerprint formula (`resumeSearchFingerprint`/`identityOf`) is unchanged, so existing journals do not drift.
- `check-durable-search.js` extended with an operational-deadline case: a coordinator-style worker spec carrying the unshrunk config plus a short `runtimeDeadlineMs` runs to completion with no `WORKER_IDENTITY_DRIFT`, identity is invariant to the deadline, and a direct short-deadline `runAttempt` still returns stats. The existing fake-identity drift guard still fails closed, and a genuine budget change still trips `SEARCH_SEMANTICS_DRIFT` on resume.
