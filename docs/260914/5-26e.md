## PR-5.26f review corrections - 2026-09-14

Owner approved `5159cf7`, closed PR-5.26e as `CLOSED_AS_SUCCESSFUL_GUIDED_SERVICE_ORDER_DIAGNOSTIC`, and tightened two interpretations. Neither changes a number in this document.

### 1. Field name

```ini
NON_RESOURCE_TRANSPORT_SIGNATURE_EQUAL = RETRACT_AS_TOO_STRONG
NON_HERO_SCALAR_TRANSPORT_SIGNATURE_EQUAL = FALSE
"NON_RESOURCE" = NON_NORMALIZED_TRANSPORT_COMPONENTS
                  NOT_A_SEMANTIC_CLAIM_THAT_EVERY_COMPONENT_IS_NON_RESOURCE
```

`hatred` and floor mutations are world state that can be read as combat/progress state, so the old name overclaimed. The property actually measured is about the transport components other than the normalized hero scalars.

### 2. The same-score live count includes the node itself

`guidedSameScoreLiveCountAtRegistration` is scanned **after** `heapPush()`, so the admitted node is counted in its own figure. The correct reading is therefore:

```ini
GUIDED_SAME_SCORE_LIVE_COUNT_AT_REGISTRATION = INCLUDES_SELF
CP14_OTHER_SAME_SCORE_LIVE_COMPETITORS_AT_REGISTRATION = 27
CP16_OTHER_SAME_SCORE_LIVE_COMPETITORS_AT_REGISTRATION = 327
```

So cp#16 faced 327 other equally-scored live guided competitors, not 328 in front of it. This matters for the next round: strict oldest-first is **not** predicted to rescue cp#16.

### 3. Result of the authorized follow-up

PR-5.26f implemented the pre-authorized `score DESC THEN pendingSeq ASC` tie-break as opt-in and ran the A/B, MT3 gate, MT4 run and survival audit. Headline: first oracle loss moved 16 → 29 and the wait-age tail (max 6397 → 1441) disappeared, while guided admissions at fixed work rose 8916 → 15792 because skyline admission is order-dependent, and the MT4 run terminated on RSS rather than wall time.
