## 问题与已有证据

PR-5.19e 已 `MECHANISM POSITIVE / NOT PROMOTED` + `APPROVED / CLOSED`。当前 frozen evidence：


因此 generic `make-viable` 目标过粗。本轮把它分解为：

```text
attack-blocked
→ make-damageable
```

## 第一版冻结语义

新增 discrete prerequisite：

```text
kind: battle-stage-prerequisite
stageGoal: damageable
boundary: exact battle B
parentDependency: 原来的 T

completionPredicate(state):
  battle stage analyzer 返回
  lethal 或 viable

等价于:
  supported
  AND damage != null
```

注意：

- completion 不是 `ATK >= enemy DEF`
- completion 不是 `attackMargin >= 0`
- `attackMargin` 只用于 attribution
- `unsupported / unresolved-no-damage` 不算完成

## 本轮只改 continuation-derived child

- root-level 5.19b generic battle-access 行为保持原样。
- 只在 continuation resume 后编译下一层时，若 child boundary 是 `attack-blocked`，编译 `battle-stage-prerequisite` 而不是 generic battle-access。
- 不顺手把 root-level battle-unsurvivable 全部改 stage decomposition。

## Identity 必须与 generic battle-access 分开

```text
battle-stage-prerequisite|
parentDependencyId|
floorId,x,y|
enemyId|
stageGoal=damageable
```

不能复用 `battle-access-prerequisite|...`，否则 dedupe 会把 make-viable 与 make-damageable alias。

## 满足后不得宣称 B 已解决

若 `make-damageable` satisfied：

```text
attack-blocked → lethal
```

那么 5.19f 到此为止；不顺手编译 `make-survivable`。

正确链仍为：

```text
T
→ B attack-blocked
→ make-damageable
→ satisfied + strict replay
→ preserve parent T intent
→ resume / re-evaluate world
```
