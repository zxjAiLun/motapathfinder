## 问题与已有证据

PR-5.18e 已关闭为 `VERIFIED / NOT_PROMOTED`。当前最强的可观察事实是：

```text
1000 total search work
8 feedback-aware dependency attempts
semantic dependency 只有 1 个
8 个 distinct source exact states
satisfied 0 / stateCreated 0 / globalBlockerAdvanced 0
```

因此 5.18e 排除的是“更努力地连接 T”这条支线在当前条件下的价值，而不是数学证明 T 不可达。现在需要回答的问题不是：

> 怎么更努力地连到 T？

而是：

> 为什么 dependency discovery 反复坍缩到同一个 T？  
> 从不同 source state 到 T 的第一个可解释 access boundary 是什么？

当前这仍是一个 **strong hypothesis**，不是已归因事实：

```text
T 的可达性依赖于当前 dependency model 没有显式表达的 access prerequisite。
```

5.19a 的任务就是把该假设变成可复核的 per-attempt evidence，或证伪它。

## 初始设计

只做观察器，不做 planner：

```text
runDependencyConnector
        ↓ 每个 expansion 只读采样
bestApproachStates（最接近完成 dependency 的 state）
        ↓ connector 停止后，仅对这些 state 做一次 reachability/battle/door/event 分析
firstUnresolvedAccessBoundary
        ↓
per-attempt attribution
```

目标 T 的接近度只用纯观察 distance，不参与搜索排序：

```text
same floor?
floor distance（project.floorOrder）
Manhattan distance（同 floor）
target POI visible?
target adjacent?
target action currently enumerable?
primitive chain depth
```

停止后对 top-K bestApproachStates 输出：

```text
attempt
source exact state
target T

best observed approach:
  floor / position
  primitive depth
  remaining distance if known

first unresolved access boundary:
  kind
  target
  evidence

classification:
  battle-unsurvivable
  missing-key
  closed-door
  event-condition
  flag-condition
  topology/changeFloor
  no-path-under-current-action-scope
  budget-incomplete
  unknown

proof strength:
  proven
  observed
  hypothesis
```

`budget-exhausted` 的尝试最多只能给 `observed` 或 `hypothesis`，不得写成根因；只有 frontier-exhausted 且边界证据完整时才能考虑 `proven`。

## 合同与不变量

- observation-only：attribution 必须对 `runStrategicD2Search` 的搜索图、统计、verdict 完全无影响。
- 所有 distance 是诊断量，不得进入 agenda、frontier 排序或 completionPredicate。
- attribution 必须逐 attempt 绑定 `attemptId / sourceExactStateFingerprint / semanticDependencyId / target`。
- `proof strength` 必须诚实：`budget-exhausted` 不能升级成 access root cause。
- 生成物默认 ignored；tracked 只放 checker、schema 与 milestone 文档。

| Blind contract | inputContract | knownRouteUsed=false，无 milestone/order/threshold | 不泄露 oracle |
