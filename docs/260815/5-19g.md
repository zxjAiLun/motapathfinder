## 问题与假设

PR-5.19f 已关闭。当前 strong-positive transition：

```text
make-damageable satisfied
→ attack-blocked → lethal
→ finalCreated = false
→ final floor = MT4
→ 新 parent continuation 创建
```

但 frozen run 中：

```text
calls = 6/8
continuationDerivedCalls = 1
```

强推断：

```text
stage success merged 到已存在的 MT4 canonical exact state
→ continuation anchored 在该 canonical state
→ 其合法 MT5 descendants 可能在 continuation 创建前已经生成
→ 之后没有新的 target-floor descendant
→ continuation 永远 parked
```

必须先用 observation telemetry 证实或否证。

## 第二阶段：deterministic historical descendant re-entry

仅在 `postStateFinalCreated == false` 时扫描 canonical nodes：

```text
isNodeDescendantOf(candidate, anchorNodeId) == true
AND candidate.floorId == parent target floor
AND resumeKey unseen
```

排序：

```text
nodeId / discovery order 升序
```

选择最早 eligible descendant，不按资源/距离/blocker 排序。

这不是 teleport / oracle / 跨 branch transfer：必须证明该 descendant 是 canonical anchor 已经合法生成过的搜索节点。

预算完全不动：

```text
total work = 1000
maxCalls = 8
perCall = 50
lazyDrain unchanged
```

## 真实 mechanism gate

目标链：

```text
T
→ P1 battle viable
→ continuation
→ evilHero attack-blocked
→ P2 make-damageable SATISFIED
→ attack-blocked → lethal
→ finalCreated=false @ MT4
→ new continuation
→ historical legal descendant re-entry
→ back on MT5
→ re-attribution sees evilHero = lethal
→ existing generic battle-access prerequisite compiled/scheduled/executed
```

不新增 make-survivable 类型。

若 generic make-viable 在 lethal state 成功 → 完整 `attack-blocked → damageable → lethal → viable` ladder。
若 generic make-viable 真实 50-expansion 失败 → 下一轮才归因 survival resource。
若没有 historical descendant → hypothesis 否证，本轮停止。
