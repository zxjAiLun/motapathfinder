## 问题与已有证据

PR-5.18d 已正式关闭为 `VERIFIED / NOT_PROMOTED`。它证明了：

- blocker-derived local optimizer 机制正确：每次 connector 调用都能提高局部 `progressScore`，1000-work A/B 中 `blockerConnectorImproved=8/8`。
- 但它默认优化的 `progressScore` 与 strategic agenda 的 terminal-blocker 队列是同一个量，实际只是在重复战略 frontier 已经会做的 hill-climb。
- 1000-total-work A/B 中全局 best attackMargin 仍为 `-903`，terminal action 仍为 0；wall 反而更慢。

因此 5.18d 的 negative result 不是“connector 不够努力”，而是它缺少 strategic frontier 没有的能力：**从 terminal blocker 反推一个离散 prerequisite，并让 connector 以“合法完成该 prerequisite”为成功条件，而不是以 scalar 更高为成功条件。**

## 初始设计

数据流严格为：

```text
terminal blocker
      ↓ analyze
capability gap（combat-power / survival）
      ↓ dependency compiler
named prerequisite（离散、可验证）
      ↓ bounded dependency connector
prerequisite satisfied
      ↓ re-evaluate terminal blocker
```

connector 的终止条件是 **completionPredicate 成立**，不是 metric 最大。`progressScore` 只用于对候选排序，不替代“prerequisite 是否完成”的判断。

第一轮只允许两个 dependency vocabulary：

1. `equipment-acquisition`
   - 当前 inventory 中存在可 equip 的 item，或可合法到达并获得的 equip item。
   - 执行 `pickup/interactPickup + equip` 后，`terminalBattleProjection` 的 stage 或 stage-metric 真改善。
   - `completionPredicate`：target item 已被装备到正确 slot，且 re-evaluate 后的 terminal projection 比调用前改善。
2. `resource/power-opportunity-acquisition`
   - 当前 reachable item POI 通过 simulator 实际枚举的 `pickup/interactPickup` 动作可消费。
   - 对该动作做 counterfactual one-step apply 后，`terminalBattleProjection` 的 stage 或 stage-metric 真改善。
   - `completionPredicate`：target POI 已从当前 state 的 option map 中消失，且 re-evaluate 后的 terminal projection 比调用前改善。

候选证据必须来自 simulator 的真实枚举与真实 apply，不读已知路线、不写死任何 item id / 坐标 / 阈值。每个 dependency 带 provenance：

```text
blocker stage
capability
expected terminal projection delta
candidate evidence（reachable POI / inventory equip action）
one-step counterfactual post-state projection
```

依赖连接器在每个 source state 上只接受上述编译出的 dependency；失败分类仍为 `budget-exhausted / frontier-exhausted / frontier-trimmed / satisfied`。

## 范围与非目标

### 本轮范围

- 新增 dependency compiler：`analyzeTerminalBlocker → capability gap → 离散 prerequisite`。
- 新增 dependency connector：以 `completionPredicate` 为唯一成功条件的有界 primitive 搜索。
- 接入 `strategic-d2-search`：新增 `dependency-connector-choice` lazy work，与 strategic expansion 共享 `maxTotalSearchExpansions` hard cap。
- 记录 `terminalPrerequisiteSatisfiedCount`、`newTerminalRelevantDependencyReached`、每个 satisfied dependency 的 before/after terminal projection 与 exact chain。
- same-total-work A/B：strategic-only vs dependency-connector candidate。
- 若 goal found：完整 route record + strict replay。

### 不在本轮 / 未授权

- 不做万能 dependency planner；只有 `equipment-acquisition` 与 `resource/power-opportunity-acquisition`。
- 不读 known route、route fixture、人工 milestone、人工事件顺序或资源阈值。
- 不写死 I621/I894/坐标/装备名。
- 不改 DP key、dominance、production segment solver 或 replay 语义。
- 不靠增加 total search work、wall timeout 或 queue 权重掩盖缺口。
- 不进入 D3；D3 = NOT AUTHORIZED。
- 不把“dependency connector resolved N/N 但全局 best 仍 -903”宣称为进步。

## 合同与不变量

- 输入仍为 tower、route-free current state、terminal goal；输出仍必须保留四元组 `goalFound / frontierExhausted / budgetExhausted / searchComplete`。
- dependency 的 `completionPredicate` 必须在 search state 上可判定，不得依赖 connector 内部实现细节。
- connector 的 chain 必须逐边记录 exact pre/post，并经 `verifyConnectorChain` 严格重放。
- dependency candidate 的证据必须是真实 `enumerate*Actions + applyAction + terminalBattleProjection` 的 counterfactual 结果；不得用 item id 字典。
- total-search-work = strategic + terminal-connector + blocker-connector + dependency-connector expansions；`maxTotalSearchExpansions` 继续是 strict hard cap。
- 只有 satisfied dependency 且 after projection 真改善才计入 `terminalPrerequisiteSatisfied`；无改善或 chain 非法不得计入。
- 若 connector 只重复 5.18d 的 progressScore hill-climb，或只在 local 上 resolved 但全局 best 不前进，结果必须是有效 `VERIFIED / NOT_PROMOTED`，不允许转成 success。
