## 问题

PR-5.19c 已 `APPROVED / CLOSED`。5.19b 证明 P(B) 可以真实 satisfied，并产生新 exact state，但 hierarchy 在 P(B) 完成后立即结束：

```text
T
→ B
→ P(B)
→ satisfied
→ materialize
→ resolve lazy work
→ return
```

parent dependency T 没有被显式继续。真实 success 甚至停在 MT4，而 parent target 在 MT5；普通 strategic frontier 是否回来、何时回来、是否仍记得 T，完全不受保证。

## 本轮目标

最小化 parent intent preservation：

```text
T
→ B
→ P(B)
→ satisfied
→ parent-dependency-continuation
→ 当前 floor != target floor
   → waiting-for-parent-floor（只 wait，不 teleport，不 oracle path）
→ 合法 strategic descendant 回到 target floor
   → resume parent dependency
   → buildFullStructuralAccessAttribution(...)
   → 有 unresolved boundary 则编译下一层（仍 one-layer）
   → 无 unresolved boundary 则检查 parent completionPredicate
```

## 冻结范围

- 新增 lazy kind `parent-dependency-continuation`。
- continuation 不是 game state，不进入 DP key。
- continuation dedupe 使用 `(parentDependencyId, exactStateKey)`：
  - same exact state + same parent → merge
  - same exact state + different parent → 仍允许不同 intent
- exact merge（`finalCreated=false`）不得丢失 continuation。
- 跨楼层只 `waiting-for-parent-floor`；禁止 solver-side teleport 或 hardcoded 回 MT5 path。
- 回到 target floor 后只重新观察 / 重新 attribution，并沿用现有 feedback-aware battle-access scheduling 和 strict call/budget cap。
- 不新增 make-damageable / make-survivable connector。
- 不调整 connector per-call budget、maxCalls、total work、lazyDrainEvery。
- 不改 DP key / dominance / replay semantics。
- D3 仍 NOT AUTHORIZED。
