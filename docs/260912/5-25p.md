## Diagnostic 1 - terminal-goal-dependent frontier differential (static, no search)

Authorized follow-up after review observed that changing the terminal goal rebuilds the dependency frontier by construction, so admission ordering is not held constant across the two runs.

```ini
SEARCH_RUN = NONE
BUDGET_CHANGE = NONE
CAP_CHANGE = NONE
POLICY_CHANGE = NONE
REPRODUCE = node shared-solver/audit-pr525p-frontier-differential.js
```

The differential builds F3 = frontier(goal MT3) and F4 = frontier(goal MT4) from the same project and the same canonical CHAOS MT1 state, then classifies every legal successor along the replayed PR-5.25o winner trajectory by `frontierSet` membership, which is exactly what sets `frontierGuided` and therefore the bounded-candidate retention rank.

```ini
F3_GOAL = MT3
F3_ENVELOPE = MT1->MT2->MT3
F3_PRE_GOAL_FLOORS = MT1,MT2
F3_FRONTIER_COUNT = 63

F4_GOAL = MT4
F4_ENVELOPE = MT1->MT2->MT3->MT4
F4_PRE_GOAL_FLOORS = MT1,MT2,MT3
F4_FRONTIER_COUNT = 117

F3_SUBSET_OF_F4 = TRUE
OVERALL_F3_ONLY = 0
OVERALL_F4_ONLY = 54        # MT3:53, MT2:1
PRE_MT3_F3_ONLY = 0
PRE_MT3_F4_ONLY = 1
```

The single pre-MT3 addition is `changeFloor:MT2:6,12->MT3` - exactly F3's own target transition, which in F4 is re-derived as a return edge.

Effective admission delta:

```ini
EFFECTIVE_DELTA_ACTION_MATCHABLE_F3_ONLY = 0
EFFECTIVE_DELTA_ACTION_MATCHABLE_F4_ONLY = 0
WINNER_ACTION_MEMBERSHIP = BOTH_GUIDED 20, F3_ONLY 0, F4_ONLY 0, NEITHER 10
LEGAL_SUCCESSOR_GUIDED_FLIPS = F3_TO_F4_NEUTRAL 0, F4_TO_F3_GUIDED 0
LEGAL_SUCCESSOR_BOTH_GUIDED = 71 (all battle)
LEGAL_SUCCESSOR_NEITHER = 61 (23 changeFloor, 11 event, 27 battle)
```

Additional structural finding, which explains why even the target-transition difference has no admission effect:

```ini
CHANGEFLOOR_IDENTITY_CONTRACT = MISMATCHED_ENUMERATED_VS_FRONTIER
  frontier changeFloor identities use the stair tile (e.g. MT2:6,12)
  actionToSemanticIdentity falls back to action.stance when target is unset
  every enumerated changeFloor action along the winner trajectory has target unset
ENUMERATED_CHANGEFLOOR_ALONG_WINNER = 23
ENUMERATED_CHANGEFLOOR_WITH_TARGET = 0
FRONTIER_CHANGEFLOOR_ENTRIES = F3 5, F4 9
=> all frontier changeFloor entries are inert for frontierGuided admission
```

Conclusion:

```ini
FRONTIER_ORDERING_PERTURBATION_ON_MT1_MT2 = NOT_OBSERVED_STATICALLY
MT3_WINNER_GUIDED_STRUCTURE_LOST_UNDER_MT4_GOAL = FALSE
PURE_PER_EXPANSION_COST_EXPLANATION = STILL_NOT_ESTABLISHED
CAUSE_OF_MT4_MISS = UNRESOLVED
```

The owner's hypothesis that the MT4 goal breaks the early priority structure the MT3 winner depended on is **not supported** by this static evidence: F3 is a strict subset of F4, no guided identity is lost anywhere, and zero guided-class flips occur on the winner's own trajectory or on any of its legal successors. The MT4 goal does not, on this evidence, perturb MT1/MT2 admission.

This diagnostic measures guided-set membership only. It does not measure path-dependent Pareto/skyline admission dynamics, actual visited state mix, or per-expansion cost; those remain unmeasured and the miss cause remains unresolved. Isolating throughput would require a fixed-work profile, which is **not** authorized here.

The changeFloor identity mismatch is reported as an observation, not repaired: fixing it would change which actions become `frontierGuided` and therefore change search behaviour, which is explicitly out of scope.

## Known limitations and non-claims

- One run only. No repeatability evidence for the MT4 task.
- A miss is `UNKNOWN_UNDER_THIS_BUDGET_AND_PRUNING_POLICY`, not proof that MT4 is unreachable.
- The result does not show that the MT1-to-MT3 winner generalizes, nor that it fails to generalize; it shows only that this frozen configuration did not find MT4 in one 180-second run.
- The oracle uses a tracked executable MT4 route fixture whose stored `stateKey` strings use an older projected key format (hero `hp`/`hpmax`/`manamax` nulled). It is therefore `TRACKED_EXECUTABLE_MT4_ORACLE = VERIFIED` (every step resolves, executes, and the end state cross-checks against the recorded hero), not a full re-verification under the current `postExactStateKey` equality contract. This does not weaken the solvability conclusion.
- `CAPABILITY_BREAKTHROUGH` remains scoped to PR-5.25o: `CONFIRMED_AT_PREDECLARED_CAP_1024` for MT1-to-MT3.
