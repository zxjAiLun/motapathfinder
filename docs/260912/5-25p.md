Binding resource on this run was **wall time** (12,929 of 120,000 expansions; peak RSS 1,857.7 of 2,048 MB), not the candidate cap, the expansion cap, or memory. Widening the region from MT1..MT3 to MT1..MT4 increased per-expansion work so the same 180-second wall clock bought fewer expansions than the PR-5.25o MT3 winner (10,212 expansions reaching MT3 in 91.6s), and this run never reached MT3 at all.

Per the authorized protocol (`IF_FAIL = STOP_AND_RETURN_FOR_REVIEW`), no further attempt was made: no cap increase, no ordering or priority change, no planner, no backtracking, no repeat run.

## Known limitations and non-claims

- One run only. No repeatability evidence for the MT4 task.
- A miss is `UNKNOWN_UNDER_THIS_BUDGET_AND_PRUNING_POLICY`, not proof that MT4 is unreachable.
- The result does not show that the MT1-to-MT3 winner generalizes, nor that it fails to generalize; it shows only that this frozen configuration did not find MT4 in one 180-second run.
- `CAPABILITY_BREAKTHROUGH` remains scoped to PR-5.25o: `CONFIRMED_AT_PREDECLARED_CAP_1024` for MT1-to-MT3.
