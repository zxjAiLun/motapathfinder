## Confirmed remaining drift (owner code inspection, verified statically this round)

- `event` enumerated actions: `stance` = hero position, `x/y` = event tile, no `target`. `actionToSemanticIdentity` used the stance, while the macro graph event POI (`classifyTilePoi`) sits on the event tile. Measured pre-repair: event legal successors along the winner trajectory 11/11 NEITHER.
- ordinary `pickup` enumerated actions: same shape and additionally no `itemId`. Identity would be `item:<floor>:<hero stance>:` while the frontier POI is `item:<floor>:<item tile>:<tileId>` - both coordinate and entity id mismatched. route-store already expects the complete schema (`normalizeAction` parses itemId out of the summary as a fallback; `hasStructuredActionFields` requires `target` + `itemId` for pickup), so the enum side is the incomplete half.
- `interactPickup` already carries `target: {x,y}` + `itemId` and is NOT touched.
- Mechanism note (measured): in `searchGraphMode: "primitive"` with `autoPickupEnabled: true`, plain pickup actions are not enumerated along the sampled states (items sit on standable tiles and are consumed by the AutoActionResolver stabilization layer; `flags.shiqu = 1`), and no tracked fixture contains a pickup decision. Item frontier POIs (28 in F3) are therefore not directly matchable by any enumerated action today; completing the pickup contract removes the schema-level defect and aligns pickup with `interactPickup`, but does not by itself wire items into the primitive action stream.

## Contract

```text
For every action that interacts with a map POI, the semantic identity uses
the POI tile, not the hero stance; and if the POI identity carries an entity
id, the action must carry that id.
```
