# PR-5.25c — Learned Action Prior for Long-Horizon Rollouts

```ini
MILESTONE = PR-5.25c
STATUS = DESIGN / AWAITING_REVIEW
DATE = 2026-09-08
PREVIOUS_MILESTONE = PR-5.25b (CLOSED: uniform rollout cannot produce terminal feedback)
SCOPE = 从已存在的合法 route / search trajectories 中学出一个轻量 state-action
        prior，使 rollout 至少能产生跨层有效行为，而不是随机乱走。
```

## 0. 方向来源

5.25a 和 5.25b 连续两条 hypothesis line 的共同发现：

- 5.25a: 静态手工 evaluation → 能排名状态 → 不能发现路线；
- 5.25b: 更长真实 rollout + UCT feedback → rollout distribution 太弱 → 连 terminal signal 都无法产生。

**共同指向**：当前真正缺的不是"再换一个 global scheduler"，而是一个能产生有意义动作序列的 **behavioral prior**。

**核心假设（一级，唯一）**：

> 从合法 solver trajectories 学到的轻量 state-action policy 能把 rollout sampling 偏移到足以产生 uniform rollout 无法产生的有意义的跨层 outcomes。

## 1. 候选架构（Phase 1: Policy-Only Reachability Probe）

**不上 MCGS、不上 value network、不上 PPO、不上 self-play、不上手工路线规则。**

最小学到的组件：

```text
输入: current exact state features + candidate action features
输出: action score / probability
```

训练目标：

```text
在一条 known valid trajectory 的 state 上
chosen action > other legal actions
```

就是最普通的 pairwise ranking / behavior cloning。

不预测最终胜率、不预测 value。

## 3. 数据泄漏边界（提前冻结）

**关键 contract**：

```text
TRAIN routes ≠ TEST route/task
```

- 不把目标 qualification route 的 action sequence 直接用于训练；
- 按 region / route source 留出 held-out；
- model 输入不包含 future route hints；
- 推理只拿 current state + legal actions。

如果数据量不足以做 held-out real task，第一轮先作为 **behavioral reachability probe**，不声称 autonomous capability。

## 4. Phase 1 实验（先不接 MCGS）

**问题**：learned policy 能否在不看 route prefix 的情况下，从 chaos MT1 自己采样出更深的合法 trajectory？

```text
CONTROL:   uniform rollout
TREATMENT: learned action-prior rollout

相同: 96 decisions / same simulator / same seeds / same chaos start / same terminal goal

报告:
  MT4 reach rate
  MT5 reach rate
  terminal rollout rate
```

**Gate**：

- 如果 learned policy 连 MT4 都明显到不了 → 停止，不接 MCGS；
- 如果 terminalRollouts > 0 → Phase 2（接入 MCGS backbone + UCT feedback）。

## 9. Phase 1 实现边界

- **只做**：small MLP + pairwise ranking + softmax rollout sampling
- **不做**：behavior cloning + CE，temperature sweep，hard-negative mining，value head，PPO，self-play，MCTS 参数调优，手工路线规则
- **数据**：仅用上列两个显式 allowlist fixture；其余一切 route（含全部 MT4/MT5 reach 与 blueKing witness）严格排除
- **训练**：valid trajectory states 上 chosen action > other legal actions
- **rollout**：softmax(score / T) 固定 T
- **sanity**：held-out chosen-action rank > uniform baseline，否则直接 BLOCK_REAL_ROLLOUT
- **gate**：MT4/MT5 reach 改善不进 Phase 2；只有 terminalRollouts > 0 才接 MCGS

### 11.2 严格回放契约（关键发现，已固化）

这两个 fixture 是**早期版本**写出的，其 `start.stateKey` / `decision.preStateKey` /
`decision.postStateKey` / `final.stateKey` 与当前 `buildStateKey(state)` **不相等**。
差异是确定性的、可完全复现的序列化差异，`legacyRouteStateKey()` 逐字节复现旧键：

```text
1. hero.hp -> null         （历史 dominance key 忽略 HP，但保留 hpmax/manamax）
2. 删除 flags.__leaveLoc__ （历史键早于该运行时字段；仅用于键比较，实时 state 仍保留）
3. 为 snapshot.floors 中每个 floor 补空的 mutation 条目（历史 serializer 保留空 floor）
```

严格回放断言：每条 decision 的 pre-state 与 post-state、以及 final state 的上述键
**逐字节相等**，否则 fail-closed。实测：

```text
route                                   decisions  最终 floor  最终键匹配  歧义指纹（由 post-state 唯一解出）
mt1-mt2-hp3834.route.json               23         MT2         true        1
mt1-mt3-i893-hp8425.route.json          33         MT3         true        3
```

- 指纹匹配使用 `route-store.normalizeAction(...).fingerprint`（**不**使用
  `simulator.getActionFingerprint`，其格式不同）。
- 当多个 primitive travel variant 共享同一指纹时，记录中的 `postStateKey` 是唯一判别依据；
  必须**恰好一个**候选复现 post-state，否则 fail-closed。

### 11.4 离线 sanity gate（2-fold leave-one-route-out）

```text
aggregate mean normalized rank = 0.1119   vs uniform 0.5000  => GATE PASS
fold mt1-mt2 : train mt1-mt3, test mt1-mt2 : mnr 0.0000, top1 1.000   (退化：mt1-mt2 整条是 mt1-mt3 的前缀)
fold mt1-mt3 : train mt1-mt2, test mt1-mt3 : mnr 0.1899, top1 0.667
```

**重要 caveat（诚实记录）**：两条 fixture 共享 23 条 decision 的完全相同的 chaos MT1 前缀
（`sharedPrefixDecisions = 23`），因此 fold `mt1-mt2` 的“held-out”集合实际是训练集的子集，
其 mnr=0 是退化结果，aggregate 由它主导。

仅统计**训练集中不存在**的 10 条真正未见 decision（transparency 指标，非 gate）：

```text
unseen mean normalized rank = 0.5533  (uniform = 0.5000)  => 未优于 uniform，无泛化证据
```

即：**冻结的 aggregate gate 通过，但真正未见的 held-out 上模型不优于 uniform**。
该 gate 结论按契约仍允许启动 rollout（已启动），但不得据此声称离线已学到可泛化信号。

### 11.5 matched CONTROL / TREATMENT rollouts

```text
horizon = 96 decisions, temperature = 1.0 (frozen), chaos MT1 start, stopFloorId = MT11
seed schedule = 52501 + i*7919，两臂 matched，每臂 32 次
```

| arm | rollouts | terminal | MT4 reach | MT5 reach | max floor 分布 | meanSteps |
| --- | --- | --- | --- | --- | --- | --- |
| CONTROL (uniform) | 32 | 0 | 0 | 0 | MT2:23, MT1:9 | 96.0 |
| TREATMENT (learned) | 32 | 0 | 0 | 0 | MT2:27, MT3:5 | 96.0 |

- 学习到的 prior 产生一个**弱 secondary 信号**：treatment 有 5/32 到达 MT3，control 0/32。
- 但两臂 MT4/MT5 reach 均为 0，`terminalRollouts` 均为 0。
- **Phase 1 primary gate（terminalRollouts > 0）未通过** → 不接 MCGS，Phase 2 未授权。
- MT4/MT5 reach 按契约仅为 secondary behavioral signal，不作为能力声明。

### 11.7 解释边界（licensed interpretation）

- 本条是**有界负结果**，不是“学习型 prior 不可行”的一般性结论。
- 已证否的窄命题：在这 2 条 fixture、冻结特征/目标/超参下，pairwise ranking 学到的
  prior 不能在 96 步内把 rollout 推到 terminal，也不能产生 MT4/MT5 进展。
- 离线 sanity 的 aggregate 通过主要由共享前缀泄漏造成；真正未见集合上不优于 uniform。
- 未做也禁止：MCGS/UCT 接入、value head、PPO、self-play、CE/BC、temperature sweep、
  hard-negative mining、手工路线规则、segment/DP 改动。

### P2-1：aggregate sanity ≠ generalization sanity（本轮最有价值的发现）

```ini
FORMAL_FROZEN_SANITY_GATE = PASSED        # 按当时字面 LORO 契约
GENERALIZATION_SANITY      = NOT_PASSED   # 真正未见 decisions 上未优于 uniform
```

- 两条 route 的 23 + 33 个 decision 中前 **23 个完全共享**，aggregate `0.1119` 被训练中已见过的
  exact decision 主导，因此**不能**再称为真正的 held-out sanity。
- 真正未见集合：10 个 decision，mean normalized rank `0.5533` vs uniform `0.5000` → 无泛化证据。
- 口径要求：不得无定语地写 `OFFLINE_SANITY = PASSED`；应写成
  `FORMAL_FROZEN_SANITY_GATE = PASSED / GENERALIZATION_SANITY = NOT_PASSED`。

### P2-2：terminal predicate 与设计不完全一致（非阻塞）

- 设计写的是 `same terminal goal`（延续 MT5 blueKing qualification）。
- 实现使用的是 `stopFloorId = MT11` + `simulator.isTerminal(state)`，
  并非 `blueKing@MT5:6,7 removed`。这是 contract mismatch。
- **非阻塞、无需返工**：两臂 `MT4 reach = 0`、`MT5 reach = 0`，一次都没进 MT5，
  自然不可能满足 blueKing terminal predicate，因此不改变 Phase-1 的负结果。
- 仅作诚实记录；若后续复用该 rollout 框架，应重新冻结 terminal predicate。

### 12.3 允许的结论尺度

可以声明（正述）：

> 在严格排除 MT4/MT5 qualification family、仅使用 MT1→MT2 与 MT1→MT3 两条高度重叠训练 route
> 的条件下，冻结的 lightweight pairwise action prior 没有在真正未见 decisions 上表现出优于 uniform
> 的 ranking generalization，也没有在 96-step rollout 中产生 MT4/MT5 reach 或 terminal feedback。

不得扩大为：`learned action prior 不适合魔塔` / `behavior cloning 不可行` / `神经网络 prior 无效`。
证据远未到该尺度：本条只否证了一个很窄的命题（特定 2-route 语料 + 特定特征/目标/超参）。

`treatment MT3 5/32 vs control 0/32` 保留为 **weak behavioral shift observed**，
但明确**不是** generalization evidence——训练语料本身即包含 MT1→MT3 route。
