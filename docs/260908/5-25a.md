## 0. 方向来源与一级研究假设

Cloud Review（与方向制定 agent 对齐后）正式撤回上一轮 "Goal-Causal Strategic Search"
主线安排，改为本方向（`APPROVED AS THE NEXT RESEARCH HYPOTHESIS`）。PR-5.24k two-step
CF **不再作为主线**（CF/dependency planner/battle thresholds 降级为纯计算组件，禁止重新
成为控制循环）。

**一级研究假设（唯一）**：

> 有限多步资源推演（multi-step resource lookahead），能否在不改变合法性、去重与状态
> 保留语义的情况下，提高真实事件级前向搜索找到可行路线的能力？

## 1. 架构边界（三条，Cloud Review 已接受）

### 1.1 搜索节点必须是真实 exact state

```text
节点 = hero / inventory / flags / map mutations / floor / location /
       其他决定未来行为的真实状态
边   = 一次有决策意义的 simulator action
```

普通无意义移动由 reachability 折叠（现有 simulator 已提供）。搜索器结构：

```text
search core → existing simulator
```

**不是** `new planner → segment DP → repair → simulator`。不修改 segment-dp 主循环。

### 1.2 评价器只影响优先级（correctness boundary）

评价器可以输出：estimated terminal feasibility / resource plans considered /
estimated acquisition cost / useful thresholds / recommended action ranking /
uncertainty。

评价器**绝对不能**：宣布真实状态非法 / 合并两个 exact state / 证明状态无解 /
删除没看懂的 action / 替 simulator 计算最终状态。

"这个状态看起来没希望" = **晚点展开**，不是删除。因预算/cap 未展开 → incomplete search。

### 1.3 第一版不做跨状态 failure learning

真实结果 → 重新评价当前 state，仅此而已。failure abstraction / backjump learning 后置。

## 2. 探索契约（exploration contract，实现前写死）

```text
EVALUATOR_CAN_PRIORITIZE = TRUE
EVALUATOR_CAN_PERMANENTLY_STARVE_ACCEPTED_STATE = FALSE
```

实现选择（Iteration 1 冻结）：**age-term 双队列**——guided frontier（评价器排序）+
neutral frontier（FIFO），每 N 次 guided expansion 至少允许一次 neutral expansion
（N=8 冻结起始值；不 sweep）。低分动作随等待时间获得 age bonus，永不永久饥饿；
唯一允许的未展开原因是整体 budget/cap 截断（→ incomplete search 分类）。

## 3. 评价器（multi-step future evaluation）最低表达力

必须能表达：

```text
当前状态 → 候选资源取得序列 → 资源变化 → 后续关键战斗成本变化 → 终点通路
在简化模型中是否变得可行
```

例：打怪 X（-600 HP, +EXP → 升级 +3 ATK）→ enemy C damage -900 → predicted terminal
path feasible。这区别于 `HP 多=好 / ATK 高=好` 的普通 heuristic。

### 3.1 简化推演模型必须保留（首轮 review contract）

| 必须保留 | 原因 |
|---|---|
| 一次性资源消费 | 否则凭空重复吃宝石/经验/钥匙 |
| prerequisite | 否则假设拿得到被怪挡住的资源 |
| ATK/DEF/HP/MDEF/EXP/LV 关键变化 | 魔塔投资顺序核心 |
| 多步战斗成本重新计算 | 看到"先加攻、后面省血" |
| alternative route isolation | 不能把互斥路线资源全加 |

未知事件 → `UNKNOWN`（不是 `BLOCKED`）。

### 3.2 允许复用的旧模块（克制）

```text
允许 reuse（纯计算组件）:
  battle-thresholds.js（estimateBattleSurvivability）
  automatic-macro-graph.js（path topology / blocker extraction）
  battle resolver / reachability / resource calculations

禁止 reuse:
  automatic-dependency-planner 整体（其 topology alternatives/prerequisites
  是 bounded-topology-alternatives-not-proof）
  任何"选 subgoal → 执行 → repair → backtrack"控制循环
```

## 4. A/B 实验设计（同核因果对照）

```text
CONTROL:   future evaluator OFF（同 core）
TREATMENT: future evaluator ON（同 core）

严格相同: initial state / terminal goal / allowed region / simulator /
         action enumeration / exact state key / duplicate handling /
         frontier retention / termination / total resource budget
唯一变量: evaluator 开关
evaluator 的时间与内存计入 TREATMENT 预算
```

### 4.1 三方 reference

```text
old blind discovery（blind-discovery-baseline）= 整体位置 reference
new core / evaluator OFF                       = causal control
new core / evaluator ON                        = experiment
```

因果判断只以后二者为准。

## 5. 测试层级

| Level | 内容 | 作用 |
|---|---|---|
| **L1** | 4 个 strategic micro（ordering / threshold / synergy / irreversible investment） | 确认 evaluator 真在做 multi-step future reasoning（非 test coverage） |
| **L2** | controlled MT2→MT4（G32 fixture 起点） | diagnostic：one-step CF 已知不足的状态上 multi-step 是否改变行为 |
| **L3** | terminal-only real region（canonical start + region + terminal goal，无 milestone/threshold/route prefix） | **主结果**；成功标准 = FOUND + STRICT_REPLAY_VALID |

## 6. Progress 彻底降级

`deepest floor +1 / more states / better HP / better projection` 全部只是 diagnostic。
capability ranking：

```text
1. route found + strict replay
2. 若两组都找到：成本
3. 若两组都没找到：没有 capability winner（只能 PROMISING_SIGNAL，
   不能 CAPABILITY_GAIN_PROVEN）
```

## 7. 资源预算（第一轮）

```text
wall:        180 sec / arm / real case（micro 可以小得多）
RSS:         2 GB hard ceiling
expansions:  足够高但共同的 ceiling（wall/memory 进入实际竞争）
A/B 完全相同预算（evaluator 开销计入 TREATMENT）
```

## 8. 停止条件（严格）

最多 **3 个能力 iteration**：
- Iteration 1：实现 + micro 排序差异 + real case 可观察能力信号；
- Iteration 2：只根据 Iteration 1 的一个主要失败原因改 evaluator（禁止 repair framework）；
- Iteration 3：最后一次真实路线 qualification。

三轮后若 control/treatment 都 not found 且收益始终只有 projection/novelty/depth →
**停止此 heuristic 方向**（无 Repair 4/5/6）。

## 10. 与旧体系的区别（防止滑回 D2）

旧体系（禁止回归）：

```text
识别 blocker → 选 subgoal → 调局部 solver → 失败 → repair/backtrack → 再生成 subgoal
```

本方向（必须保持）：

```text
真实状态 S 在 open frontier 中
evaluate(S) → 给 S / outgoing actions 排序
expand(S) → simulator 得到真实 S1/S2/S3
S1/S2/S3 都成为普通搜索节点 → exact dedup → frontier 继续
失败分支没有特殊身份，只是没走到终点的普通搜索分支
```

repair admission / continuation / rollback anchor / counterfactual wave / segment
recovery 全部从主控制结构中拿掉。
