## 0. 核心假设（一级，唯一）

```text
Given the same exact simulator, rollout policy, rollout horizon,
random seeds, terminal goal and real-work budget:

does trajectory-outcome feedback used to allocate future sampling
find a valid route more effectively than sampling allocation
that does not use outcome feedback?
```

**Causal A/B**:

```text
CONTROL   = NO-FEEDBACK graph sampling (uniform existing-edge selection)
TREATMENT = UCT-FEEDBACK graph sampling (edge-local UCT selection)
```

5.25a 只作历史 reference（其手写 heuristic 在同等预算下 NOT_FOUND）。

**Product gate**: `FOUND + STRICT_REPLAY_VALID`。

## 1. Graph contract

全局 exact registry: `exactKey → StateNode`（identity + expansion metadata）。
统计放在 **edges** 上：`(parentExactKey, actionIdentity) → EdgeStats`。

```text
EdgeStats: { N_edge, W_goal, W_aux, Q_goal, Q_aux, childExactKey }
```

**Selection 不使用 child node 的总访问数替代 incoming edge visits**——
防止不同前史因共享 child 而互相污染探索项。

父节点 denominator: `N_parent = sum(outgoing edge visits)`。

## 2. CONTROL isolation

两臂完全共享：exact graph / transposition lookup / legal action enumeration /
expansion rules / rollout policy / rollout horizon / cycle handling / random seed /
terminal predicate / budgets。

唯一不同：

```text
if node has untried legal actions:
    select one untried action using the same seeded rule
else:
    CONTROL   → uniform existing edge
    TREATMENT → UCT existing edge
```

## 3. Selection formula (TREATMENT)

```text
score(edge) = Q_goal(edge)
            + λ × Q_aux(edge)
            + c × sqrt(log(1 + N_parent) / (1 + N_edge))
```

Iteration 1 固定: `λ = 0.10`, `c = 1.0`。不 sweep。

`Q_goal` 与 `Q_aux` 分开保存、分开报告，不写 "success probability"。

## 4. Trajectory-only backup

每次 simulation 保存实际访问序列 `(node0, edge0, ..., nodeK, edgeK)`。
回传只沿 **reverse(trajectory)** 每条实际经过的 edge 更新一次。

不允许因 transposition 顺便更新所有指向同一 child 的 incoming edges。

单人确定性环境：same rollout outcome → same sign backed up。

## 5. Cycles: 全局 graph 可有环；单次 trajectory 不允许有环

```text
GLOBAL_SEARCH_STRUCTURE = directed graph (NOT DAG — MT2→MT1→MT2 合法)
```

每次 simulation 维护 `pathExactKeys`。若 next exact key 已在当前 trajectory：
`termination = CYCLE_TRUNCATED`。非 DEAD_END / UNSOLVABLE / FAILURE_PROVEN。

同理 `ROLLOUT_HORIZON_REACHED` → `TRUNCATED`。

## 6. Rollout & reward

```text
ROLLOUT_HORIZON = 32 decisions (frozen, no sweep)
```

每次 rollout 返回双通道：

```text
goalReward  = 1 if terminal goal reached, 0 otherwise
auxProgress = normalized deepest actual floor progress (MT1=0.0 .. MT5=1.0)
```

Selection: `Q_goal + λ × Q_aux`（λ=0.10——辅助信号最多贡献 terminal reward 十分之一量级）。

日志永远分别报告 `goalHitRate` / `meanAuxProgress`，不写混合 "win probability"。

## 7. L1 micros（4 个）

```text
A. delayed-benefit:
   immediate-good branch → dead; temporary-loss branch → terminal.

B. irreversible recovery:
   wrong key/resource spend vs delayed correct branch.

C. transposition:
   A→B and B→A converge to same exact state;
   one StateNode, separate incoming edge stats.

D. deep-dead-vs-shallow-solvable:
   branch 1 quickly reaches deeper floor but cannot terminal;
   branch 2 stays shallower longer but eventually reaches terminal.
```

通过条件（bounded stochastic evidence, fixed seed）：

```text
after sufficient fixed simulations:
  solvable branch visit share / Q_goal overtakes deep-dead branch
```

## 8. Real benchmark solvability witness（L3 前必须具备）

在相同 chaos initial state / simulator / MT1..MT5 region / blueKing@MT5 terminal
goal 下，必须已有一条 `STRICT_REPLAY_VALID` known witness route。该 route：

```text
MUST NOT be passed to search
MUST NOT influence action ordering
MUST NOT be used as milestone / prefix / threshold
```

它只是 qualification oracle（证明 benchmark 在当前精确规则模型下确实可解）。

**若无此证据，先补 witness 再跑 MCGS。**

## 11. ROLLOUT_RETURN_DIVERSITY（Iteration 1 首要诊断）

```text

aux reward distribution
unique return buckets
percentage all-zero
deepest floor distribution
```

若 99.9% rollout 都是 goal=0 / aux=0.25 → UCT 无信息可学，失败原因在
sampling horizon / rollout reachability，不在 c。
