## Phase 1 - causality

cp#14 = decision 14 = `changeFloor@MT2:6,0`, a **floor transition from MT2 to MT1**. Immediate delta: `hp 3582 -> 5982 (+2400)`, `exp 9 -> 12`.

The oracle does an unusual thing here - it goes **MT2 -> MT1 -> MT2**, a round trip:

```text
 11 changeFloor  MT1->MT2  hp=1601   strategic
 12 battle       MT2->MT2  hp=4506   strategic
 13 battle       MT2->MT2  hp=3582   strategic
 14 changeFloor  MT2->MT1  hp=5982   strategic    <- cp#14
 15 changeFloor  MT1->MT2  hp=5982   transport-only
 16 battle       MT2->MT2  hp=5595   strategic
```

### Probe A - skip cp#14 alone (the owner-specified counterfactual)

```ini
CP14_SUFFIX_CRITICAL = TRUE
first suffix failure at step 15 (recorded-action-not-matched) changeFloor@MT1:6,0
CRITICALITY_KIND = PATH_CONTINUITY (wrong floor/world) - NOT a resource-investment criticality
```

This is `TRUE`, but it is **confounded**: skipping a floor transition leaves the hero on MT2 while the very next oracle action is a MT1 changeFloor. *Any* floor transition on the path would fail this way, so probe A cannot distinguish "the transition mattered" from "you are now in the wrong world".

### Probe B - skip the whole MT2 -> MT1 -> MT2 round trip (decisions 14 and 15)

Added because cp#14 is a floor **round trip**. Skipping both legs puts the hero back on MT2, so the floor aligns and the suffix can actually resolve; what is removed is the detour's net effect.

```ini
ROUND_TRIP_SUFFIX_CRITICAL = TRUE
start: MT2 hp=3582
first failure at step 23 (recorded-action-not-matched) battle:bluePriest@MT2:2,8
world deficit vs oracle: floorProbe=MT2 floorOracle=MT2     <- SAME FLOOR
  hp:  {probe: 1434, oracle: 3834}     <- exactly -2400
  atk: {probe: 67,   oracle: 72}
  def: {probe: 30,   oracle: 35}
  exp: {probe: 23,   oracle: 1}
  lv:  {probe: 3,    oracle: 4}        <- one level lower
```

With the floor identical, this is an **un-confounded resource isolation**, and the deficit is exactly the round trip's grant: `-2400` HP, `-5` ATK, `-5` DEF and one missing **level**. The suffix then survives 8 further steps and dies at a battle.

```ini
CP14_IS_SUFFIX_CRITICAL = TRUE
CP14_CRITICALITY_KIND = RESOURCE_INVESTMENT (isolated by the round-trip probe)
```

The MT1 detour is a **level-up trip**: it is what carries the hero from lv 3 to lv 4 and grants the ATK/DEF that follow. cp#14 is therefore a genuine causal investment breakpoint of the same family as cp#8 and cp#9 - but only probe B establishes that, and probe A alone would have been misleading.

**cp#14 is rank 10 / guided-admitted, not a rank-20 neutral.** This lands on the owner's third branch, and the conclusion is direct:

Building anything for it would be a **new mechanism class** (guided-heap priority), which this round is explicitly not authorized to add.

### The first-loss identity is throughput-dependent

Two mechanism-on survival runs at the same frozen configuration did not agree, because the audit is wall-limited and the machine was faster on the second:

```ini
run 1: stopped=rss-limit  10245 expansions  lastExpanded=13  firstNotSurviving=14
run 2: stopped=time-limit 11547 expansions  lastExpanded=14  firstNotSurviving=16
```

cp#14 was `expanded=false` in run 1 and `expanded=true` in run 2. The new first loss, cp#16 (`battle:zombie@MT2:8,3`), is also **rank 10 / guided (`guidedAdmitted=true`)**.

```ini
FIRST_LOSS_IDENTITY_IS_THROUGHPUT_DEPENDENT = TRUE
SURVIVING_FIRST_LOSS_CLASS = GUIDED_ADMITTED_RANK10
```

So "cp#14" is not a stable target: it is one instance of a **class** - guided-admitted rank-10 nodes that are registered, retained, never dropped, and never win a guided expansion within budget.

## What this establishes, and what it does not

Established:

- cp#14 is suffix-critical by **resource** isolation, not merely by world continuity - probe B holds the floor fixed and shows a deficit of exactly the round trip's grant, including a lost level.
- cp#14 is rank 10 / guided-admitted, therefore outside the rank-20 neutral scheduler entirely.
- The first-loss identity drifts with throughput; the surviving class is guided-admitted rank 10.

**Not** established:

- **No mechanism was built and none is proposed here.** The natural follow-up - guided-heap priority - is a new mechanism class and is not authorized.
- No claim that cp#14 or cp#16 is "the" MT4 blocker. They are the first *unexpanded oracle checkpoint*, which is a different statement from a capability blocker, and the identity is not stable.
- Probe A's `TRUE` must not be quoted alone: it is confounded, and only probe B supports the resource claim.
- MT4 remains a MISS.
- 5.26c is unchanged and stays opt-in: `NEUTRAL_PARETO_SUBSTITUTION = KEEP_AS_OPT_IN_CANDIDATE`, `DEFAULT_ENABLE = NO_FOR_NOW`.

## Owner review correction - 2026-09-14

### Correction 1 - Probe B is strong evidence, not yet full isolation

Probe B aligns the current floor, but `worldDeficit()` compared only the floor and six hero scalars. It did **not** compare inventory, flags, visited floors, floor mutations, triggered auto events, equipment, or followers. The source comment itself notes that skipping the round trip also skips its MT1 mutations. Therefore "same floor" must not be promoted to "same world" yet.

```ini
CP14_ROUND_TRIP_SUFFIX_CRITICAL = TRUE
CP14_RESOURCE_CAUSALITY = STRONGLY_SUPPORTED
FULL_WORLD_EQUIVALENCE_AFTER_SKIPPING_ROUND_TRIP = NOT_YET_ESTABLISHED
"UNCONFOUNDED_RESOURCE_ISOLATION" = RETRACT_AS_TOO_STRONG
```

The `exp 23` probe versus `exp 1` oracle state is consistent with the observed level-up/EXP-consumption chain; it is not evidence that every resource is simply lower by the immediate round-trip delta. PR-5.26e Phase 1 will compare every component remembered by `transportSignature()` after normalizing known hero scalar fields.

### Correction 2 - the current issue is equal-score service order, not value priority

The MT4 capability harness does not pass `priorityMap`. Guided insertion therefore assigns every admitted node the fallback score `100`:

```js
const score = (priorityMap && priorityMap.get(identity)) || 100;
```

The evidence establishes the lane and fate, but it does **not** establish a guided value-priority failure:

```ini
CP14 = REAL_TRACKED_SUFFIX_DEPENDENCY / RANK10_GUIDED_ADMITTED / OUTSIDE_5_26C_RANK20_REMIT
CP16 = ALSO_GUIDED_ADMITTED_RANK10
SURVIVING_FIRST_LOSS_CLASS = GUIDED_ADMITTED_RANK10
GUIDED_FAILURE_SUBCLASS = NOT_YET_ISOLATED
"CP14_PROBLEM_CLASS = GUIDED_HEAP_PRIORITY" = RETRACT_AS_TOO_STRONG
CURRENT_CAPABILITY_HARNESS_PRIORITY_MAP = ABSENT
CURRENT_GUIDED_SCORE_POLICY = UNIFORM_DEFAULT_100
CANDIDATE_MECHANISM_GAP = EQUAL_SCORE_GUIDED_SERVICE_ORDER
```

The existing max-heap has no stable equal-score tie-break: insertion does not bubble an equal score upward, while pop moves the last entry to the root and does not sink it past equal children. This suggests array/heap-order service rather than a low cp#14 value score, but that contract still requires a pure micro and real telemetry. PR-5.26e is authorized to audit exactly that; no guided value function is authorized.
