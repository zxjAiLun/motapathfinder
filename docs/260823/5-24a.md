## 1. 目标与方法学

在 PR-5.23 全系列证实了独立调度（5.23c）与单意图修复能力（5.23d）之后，**PR-5.24a 彻底停止在 checker 中手写 repair 编排逻辑**，回归 solver 原生架构：
1. **Generic Milestone Spec（`milestones/onlyup-chaos-mt1-mt3.json`）**：
   - 绝不手工指定路线、坐标或怪物打法；
   - 零人工楼梯坐标（不硬编码 `allowChangeFloors: ["MT1:6,0"]`），仅定义抽象目标 `floorId: "MT2"` 与 `floorId: "MT3"` 以及信封 `allowedFloors`；
2. **Canonical Segment DP Engine 修复**：
   - 修复了 `segment-dp.js` 中 `isAllowedChangeFloor` 对相对楼层别名（`:next` / `:before`）未解析至目标物理楼层的缺陷；
3. **原生自适应回滚触发与验证（`runMilestoneGraph(... searchIntent: "adaptive-feasible")`）**：
   - 当下游 `mt2-to-mt3` 在初始候选上失败时，自动触发原生 `tryAdaptiveCheckpointRepair()`；
   - 自动回退至上游 `mt1-to-mt2`，扩展多样性前史候选集，并按失败传播标签（`preferredCandidateTags: ["shortest", "best-combat"]`）对候选重排；
   - 依次向前重放，直接攻克 MT2 前沿，成功打通至 MT3；
4. **全链路严格检验（Fail-Closed Gate & Strict Replay）**：
   - 严密受控于 30s / 50k / 256MB 父预算；
   - 最终到达 MT3 的候选状态在全新仿真器上从真实 MT1 起点（Chaos 难度）执行 100% Strict Replay，验证状态机一致性（0 决策漂移、0 难度漂移、100% stateKey 精确匹配）。
