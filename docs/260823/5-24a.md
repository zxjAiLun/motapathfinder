## 1. 目标与方法学

在 PR-5.23 验证了独立调度（5.23c）与单意图修复能力（5.23d）之后，**PR-5.24a 彻底停止在 checker 中手写 repair 编排逻辑**，回归 solver 原生架构：
1. **Generic Milestone Spec（`milestones/onlyup-chaos-mt1-mt3.json`）**：
   - 绝不手工指定路线、坐标或怪物打法；
   - 零人工楼梯坐标（不硬编码 `allowChangeFloors: ["MT1:6,0"]`），仅定义抽象目标 `floorId: "MT2"` 与 `floorId: "MT3"` 以及信封 `allowedFloors`；
2. **Canonical Segment DP Engine 统一相对楼层解析**：
   - 在 `segment-dp.js` 中抽象统一的 `resolveActionTargetFloorId(project, action, state)`，将相对楼层别名（`:next` / `:before`）解析为物理楼层 ID；
   - 统一 `isAllowedChangeFloor` 动作白名单判定与 `goalActionScore` 目标导向评分，并配套绝对楼层、`:next`、`:before` 以及越界信封拦截（out-of-envelope reject）的回归单元契约；
3. **原生自适应回滚触发与验证（`runMilestoneGraph(... searchIntent: "adaptive-feasible")`）**：
   - 初始首个可行 MT2 状态在下游 `mt2-to-mt3` 搜索中数值不足而失败，全自动触发原生 `tryAdaptiveCheckpointRepair(depth=1)`；
   - 自动回退至上游 `mt1-to-mt2`，扩展出 10 个 rollback start candidates，并按失败传播标签（`preferredCandidateTags: ["shortest", "best-combat"]`）对候选重排；
   - 依次向前重放，成功在第 3 与第 4 个前史候选分支上攻克 MT2 前沿，成功打通至 MT3；
4. **全链路严格检验（Fail-Closed Gate & Strict Replay）**：
   - 严密受控于 30s / 50k 全局预算，明确 `256MB` 实时停止阈值与 `4MB` 采样有界超调上限（硬上限 260MB）；
   - 最终到达 MT3 的候选状态在全新仿真器上从真实 MT1 起点（Chaos 难度）执行 100% Strict Replay，验证状态机一致性（29 步决策全部 1:1 精确匹配、0 决策未决、0 难度漂移、100% stateKey 精确一致）。
