## 1. 目标与背景

在 PR-5.22 性能优化线中，我们依次完成了：
- **PR-5.22b**: `stabilizeState` 结构化等价优化（单步耗时降低约 38%）。
- **PR-5.22e**: `autoBattle` 安全快速驳回生产快路径（中位数吞吐提速 +9.41%）。
- **PR-5.22g**: `hazardBuild` 方块物化按需遍历快路径（中位数吞吐提速 +8.78%，Hazard 耗时降低 ~38%）。

本轮 **PR-5.23a** 不再进行任何微观热点分析与代码微调，而是作为**决定项目方向的终验检查**：在完全启用上述所有已晋升生产优化的配置下，使用未修改的严格固定预算（50,000 expansions, 30s wall, 256 MB RSS, Chaos difficulty, 无任何 route prefix 或中间拼接），直接评估从真实 MT1 起点到 MT6 目标的大区域求解能力。

## 2. 生产重测配置与测试实现

### A. 权威配置参数
- `autoBattleFastRejectEnabled: true`（PR-5.22e 晋升产物）
- `enableFastHazardBlockIndex: true`（PR-5.22g 晋升产物）
- `enableCompiledEffectCache: false`（PR-5.22f 否决产物，保持 Fail-Closed 原生 VM）
- 严禁启用任何 Expansion Profiler 或调试插桩，确保 100% 纯生产执行。

### B. 验证文件与硬性契约
- `shared-solver/check-onlyup-first-region-production-requalification.js`：新建独立的生产终验契约。
- **失败结果硬约束**：
  - 必须断言初始 `decisionDepth === 0`，初始 `rawRouteLength === autoStepCount`，`searchChoiceUnresolved === 0`。
  - 预期失败时，严格断言 `verdict === "REAL_FIRST_REGION_GATE_FAILED"`，`failureReason === "RESOURCE_LIMIT"`，`bindingConstraint` 必为 `"rss"` 或 `"wall"`。
  - 断言 `expansions < 5000`（证明 expansion 预算远未成为瓶颈），`bestProgress.floorId === "MT2"`，`searchFinal === undefined`。
  - 若 `bindingConstraint === "rss"`，严格断言 `peakRssMb * 1048576 >= RSS_LIMIT_BYTES`。

## 4. 核心结论与战略决策

1. **性能优化的真实收益**：
   - 相比 PR-5.21a 时期，当前生产引擎单步吞吐提升显著（单步平均耗时大幅缩减至 4.6ms 左右）。
2. **瓶颈根本性质转移确认**：
   - 当前在单一大图状态空间下，直接 canonical DP 从 MT1 盲目向 MT6 展开时，限制瓶颈已经从单步 CPU 耗时转移为 **跨状态搜索的 RSS / retention / 状态空间发散压力**。
   - 继续在 `stabilizeState` 中压榨微小的 2%~3% 单步优化已无法解决状态空间膨胀与内存保留的维度瓶颈。
3. **正式战略转移**：
   - **PR-5.22 性能优化线正式关账闭环**。
   - 项目重心明确转向 **PR-5.23b Search Retention Shape + First Structured Planning Slice**：
     - 在 `dp-search.js` 添加 retention counters 观察内存保留分布。
     - 结合现有 `floor-checkpoints` / checkpoint pool 基础设施，实现楼层边界处的小型 Pareto checkpoint set（涵盖 HP 生存、攻防投资、经验等级、关键资源、装备等代表），实现结构化跨层规划推进。
