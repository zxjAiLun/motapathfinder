## 背景与测量目标

PR-5.21b / PR-5.21b1 彻底移除了 stateful exact caches，确立了第一区域在 50000 展开 / 30s 预算下的表现（约 4800 次展开，wallMs 30001ms，peak RSS 219MB，内存触顶解除，核心瓶颈为 wall time）。

PR-5.22a 是**纯测量与归因（Measurement / Attribution）**轮次，严格遵守：
- 不改动任何搜索算法、剪枝策略、DP key、状态键、缓存语义、预算、worker 或磁盘 frontier。
- 不引入任何提前优化代码（`OPTIMIZATION_AUTHORIZED = false`）。
- 测量每次 expansion 的 CPU 与 Wall 成本分布，明确回答各个子系统在展开中的耗时占比与调用频次，为 PR-5.22b 的单一热点优化提供精确度量依据。

## 测量体系设计与实现

### 1. Opt-in Expansion Profiler 与零开销设计
- 在 `shared-solver/lib/perf.js` 中新增 `profileExpansionCost` 模式（默认关闭）。
- 当 Profiler 关闭时，生产代码仅执行单次布尔检查，不创建任何 timer 对象、不分配数组、不产生任何额外内存或性能开销。
- Profiler 数据与搜索决策、剪枝、状态键完全解耦。

### 2. 互斥顶层 Self-Time 划分（8 大 Buckets，无 Double Counting）
每次展开划分至互斥的顶层 self-time buckets，满足 `attributedSelfMs + unattributedMs === expansionWallMs`（100% 覆盖，无重复加总）：
1. `walkReachability`: 可达性 BFS 计算、骨架缓存重构与节点物化自耗时。
2. `primitiveEnumeration`: 动作枚举（物品、门、装备、事件、战斗）自耗时。
3. `actionEvaluation`: 动作过滤与排序（`sortDpActions`）自耗时。
4. `applyAction`: 状态转移应用自耗时（严格扣除其子阶段 `stabilization`）。
5. `stabilization`: 自动事件、自动拾取与自动战斗循环（`autoResolver.stabilizeState`）自耗时。
6. `stateKeyAndDominance`: DP 状态键构建、状态键构建与 Skyline 支配评估自耗时。
7. `frontierQueue`: 节点打分排名、队列 pop/push 自耗时。
8. `otherExpansionOverhead`: 展开循环外围调度与内存采样等未归因残差。

### 3. 嵌套 Inclusive 指标显式分离
独立记录子系统的全量参与度（调用次数、缓存命中/未命中、物化数等），不与 self-time 混淆。

### 4. 结构计数与环境耗时严格分离
JSON 报告划分为确定性结构计数（`deterministic`）与环境耗时（`timingDirectional`）。

### 5. 有界慢展开采样（Bounded Slow-Expansion Sampling）
维护 Top 20 慢展开轻量标量快照（`expansionIndex`、`floorId`、`decisionDepth`、`totalSelfMs`、`dominantPhase`、`actionsGenerated`、`reachableNodes`、`battleEstimateMisses`、`stabilizationIterations`、`frontierBefore/After`），不记录完整 state/route。

### 2. 第一区域 Direct Gate 展开耗时归因（`check-expansion-cost-attribution.js`）

在标准预算（50000 展开 / 30s / 256MB RSS）下单次直接搜索：
- **总展开数**: 4794
- **生成动作数**: 16084
- **注册状态数**: 5198
- **总墙钟耗时**: 30011ms (binding constraint = wall, stoppedReason = "time-limit")
- **峰值内存**: 219.0MB
- **单步展开均耗**: **6.22ms / expansion** (160.78 expansions/sec)
- **单步生成动作均耗**: **1.85ms / action** (539.41 actions/sec)
- **Attributed Self-Time 解释率**: **98.73%** (27856.16ms / 28215.07ms)

#### 关键归因洞察：
1. **第一主热点（PRIMARY HOTSPOT）**：`stabilization` 占用了 **85.34%** 的总展开耗时。
   - 在 4794 次展开中，生成 16084 个候选动作并在应用时触发了 **22,031 次 `stabilizeState`** 调用（平均每次展开触发约 4.6 次）。
   - 每次 `stabilizeState` 耗时约 1.09ms，直接消耗了 24.08 秒（占 30s 墙钟的 80%+）。
2. **为什么可达性不是当前瓶颈**：`walkReachability` 仅占 **3.30%**。骨架缓存（`reachabilitySkeletonCache`）发挥了极高效率（4396 命中 / 398 未命中，命中率 91.7%），将可达性计算压制到了 0.93 秒。
3. **状态键与支配不是瓶颈**：`stateKeyAndDominance` 仅占 **0.98%**，`frontierQueue` 仅占 **0.36%**。

## 结论与 PR-5.22b 决策建议

```ini
PARITY_VERDICT = EXPANSION_PROFILER_PARITY_VERIFIED
ATTRIBUTION_VERDICT = EXPANSION_COST_ATTRIBUTED
PRIMARY_HOTSPOT = stabilization (85.34%)
SECONDARY_HOTSPOT = primitiveEnumeration (5.24%)
OPTIMIZATION_AUTHORIZED = false
```

**PR-5.22b 优化方向明确结论**：
- **PR-5.22b 应且仅应优化 `stabilization`（自动事件/拾取/战斗的快速路径或增量稳定机制）**。
- 只要将单次 `stabilizeState` 的平均耗时从 1.09ms 降低到 0.2ms，第一区域的 `expansionsPerSec` 即可直接提升 3~4 倍（从 ~160 exp/s 提升至 500~600 exp/s），使 30s 内的展开数突破 15,000~20,000 次，无需提高 expansion cap。
- 本 PR（PR-5.22a）已完成全部测量与归因闭环，未修改任何生产搜索与求解逻辑。
