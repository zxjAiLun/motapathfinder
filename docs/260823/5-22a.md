## 背景与测量目标

PR-5.21b / PR-5.21b1 彻底移除了 stateful exact caches，确立了第一区域在 50000 展开 / 30s 预算下的表现（peak RSS 212~219MB，内存触顶解除，核心瓶颈为 wall time）。

PR-5.22a 是**纯测量与归因（Measurement / Attribution）**轮次，严格遵守：
- 不改动任何搜索算法、剪枝策略、DP key、状态键、缓存语义、预算、worker 或磁盘 frontier。
- 不引入任何提前优化代码（`OPTIMIZATION_AUTHORIZED = false`）。
- 测量每次 expansion 的 CPU 与 Wall 成本分布，明确回答各个子系统在展开中的耗时占比与调用频次，为 PR-5.22b 的单一热点优化提供精确度量依据。

## 测量体系设计与实现

### 1. Opt-in Expansion Profiler 与零开销生产路径（Zero-Overhead OFF Path）
- 在 `shared-solver/lib/perf.js` 中新增 `profileExpansionCost` 模式（默认关闭）。
- 当 Profiler 关闭时，生产代码（`searchDP` / `StaticSimulator` / `AutoActionResolver`）完全直通执行，不创建任何 closure 回调，不分配包装对象，保持与 `548a635` 基线完全一致的零开销。
- 语义计数器（`expansions`、`generated`、`registered`、`duplicates`、`primitiveEnumerationCalls`、`applyActionCalls`、`stabilizeStateCalls`、`stabilizationPasses`、`dpKeyBuildCalls`、`dominanceLookupCalls`、`dominanceRejects`、`frontierRankCalls`、`frontierPushCalls`、`frontierPopCalls`）与计时器完全解耦，杜绝调用计数的 Double Counting。

### 2. 互斥顶层 Self-Time 栈与真覆盖率（Top-Level Self-Time Stack）
- 引入 `beginTopLevelPhase` / `endTopLevelPhase` 独立顶层时钟栈，确保嵌套通用阶段（如 `cloneState`、`battleEstimate`）的耗时自洽累加于当前活动顶层 bucket 中，避免通用 phase 扣减导致顶层时间消失。
- 覆盖率直接对照实测 expansion 真实耗时：`coverageRatio = attributedSelfMs / expansionWallMs`（实测 98.3%）。
- 增加 `unmappedPhaseSelfMs` fail-closed 闭环校验（`|sum(topLevelSelfMs) - expansionWallMs| <= 50ms`）。

8 大互斥顶层 Buckets：
1. `walkReachability`: 可达性 BFS 计算、骨架缓存重构与节点物化自耗时。
2. `primitiveEnumeration`: 动作枚举（物品、门、装备、事件、战斗）自耗时。
3. `actionEvaluation`: 动作排序（`sortDpActions`）自耗时。
4. `applyAction`: 状态转移应用外围自耗时（不含内部 stabilization）。
5. `stabilization`: 自动事件、自动拾取与自动战斗循环（`autoResolver.stabilizeState`）自耗时。
6. `stateKeyAndDominance`: DP 状态键构建与 Skyline 支配评估自耗时。
7. `frontierQueue`: 节点打分排名、队列 pop/push 自耗时。
8. `otherExpansionOverhead`: 展开循环外围调度与内存采样等未归因残差。

### 3. Read-Only 稳定化子阶段拆解（Stabilization Subphases Decomposition）
在不改变任何稳定化逻辑的前提下，只读度量 `stabilization` 内部 6 大子阶段耗时：
- `hazardBuildMs`: 移动危害图构建耗时
- `pickupScanMs`: 自动拾取目标扫描与 BFS 收集耗时
- `battleScanMs`: 自动战斗目标扫描与评估耗时
- `applyStepMs`: 自动动作步进应用（拾取 / 战斗）耗时
- `autoEventMs`: 自动事件触发耗时
- `otherMs`: 稳定化循环调度与外围开销

### 4. 慢展开差值采样（Bounded Slow-Expansion Delta Sampling）
慢展开采样字段（`reachableNodes`、`battleEstimateMisses`、`stabilizationPasses`）严格记录每次展开的 begin/end 差值，反映单次展开的真实增量负载。

### 5. 静态测试集准入
`shared-solver/check-expansion-profiler-parity.js` 已被提升为 manifest 的第 60 个 static required check，两次 `manifest:refresh` 无 diff，并通过 `npm run check:static:clean`。

#### 关键归因洞察：
1. **第一主热点（PRIMARY HOTSPOT）**：`stabilization` 占用了 **79.93%**（~23.6s）的总展开耗时。
   - 内部由 `battleScan` (36.5%)、`hazardBuild` (26.2%) 和 `applyStep` (24.1%) 主导，三者合计占 stabilization 的 86.8%。
2. **第二热点（SECONDARY HOTSPOT）**：`primitiveEnumeration` 占 **7.14%**（~2.1s）。
3. **为什么可达性与支配不是当前瓶颈**：
   - `walkReachability` 仅占 **4.25%**（骨架缓存命中率 80.9%）。
   - `stateKeyAndDominance` 仅占 **0.95%**，`frontierQueue` 仅占 **0.33%**。
