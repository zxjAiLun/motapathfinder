## 1. 背景与缺陷根因分析

在 PR-5.22d 中，Shadow 探针初步验证了预判拒绝的高性价比与覆盖率（单次 0.55 µs，覆盖率 ~30.6%）。然而在 Agent 深度代码审查中，发现了以下核心安全隐患：

1. **Denylist 安全模型缺陷（黑名单漏洞）**：
   - 旧实现维护 `KNOWN_COMBAT_ITEMS` 黑名单。但 OnlyUp 的 `getDamageInfo()` 存在未在黑名单中的战斗道具（如 `I602`、`I755-757`、`I581-582`、`I752-754` 等），例如 `I602` 会执行 `damage -= (mon_atk + mon_def) * 1.6; Math.max(0, damage)`，可将原本有伤的战斗直接减为 0 伤。
   - 在黑名单未覆盖 `I602` 时，Rule 2 预判 `definitelyReject`，而权威解析器返回 `0 damage`，构成真正的 **False Reject**。
2. **测试未调用 Authoritative Oracle**：
   - 旧 17 维测试仅比对人工手写的 `expectedBoolean`，未实例化 `FunctionBackedBattleResolver` 执行真正的权威 `evaluateBattle()`，无法检验真实公式潜在的反例。
3. **Shadow 探针口径混入 Reverify**：
   - 探针同时在 scan 与 reverify 运行，导致 `shadowChecks (151,685) != scanBattleResolverEvaluateCalls (150,946)`。
   - reverify 本身仅占总耗时 0.23%，生产优化不应涉及 reverify，探针必须严格限定于 scan 路径。

## 2. PR-5.22d1 安全闭环设计原则

### A. 安全模型逆转：Closed-World Whitelist（全封闭白名单）
从“已知危险道具黑名单”彻底逆转为“已知纯安全非战斗道具白名单”：
- **Safe Non-Combat Items Whitelist**：仅允许标准钥匙（`yellowKey`, `blueKey`, `redKey`, `greenKey`, `steelKey`, `specialKey`）及无战斗副作用的标准非战斗道具（`book`, `fly`, `I600`）。
- **Fail-Open 规则**：一旦 `state.inventory` 拥有任何非白名单道具（如 `I602`, `I821` 等任意特殊道具），**立即返回 `"unknown"`，100% fail-open 交由权威解析器**。
- **Safe Flags Whitelist**：`state.flags` 仅允许系统安全标志（`autoBattle`, `shiqu`, `level0`, `floor`, `floorId`, `hero`, `debug`, `hatred`, `__leaveLoc__`）。若出现任何非白名单标志或数值，立即 fail-open。
- **Safe Equipment**：`state.equipment` 必须为空，否则立即 fail-open。
- **Safe Enemy**：`enemy.special` 必须严格为空/0，且无 `guards`、无 `zone`/`repulse`/`laser`/`ambush`/`betweenAttack` 等任何非标准属性，否则立即 fail-open。

### B. Resolver 拥有判定能力（Battle Semantics Owner）
- 将 `classifyAutoBattleFastReject` 的调用归属于 `battleResolver`。若解析器未实现或未经过该塔的战斗语义资质认定，默认全量返回 `"unknown"`。

### C. Scan-Only 探针隔离
- Shadow 探针仅在 `!isReverification`（纯 scan 收集阶段）执行。
- 确立硬守恒方程：`scanShadowChecks === scanBattleResolverEvaluateCalls`。

### D. Authoritative Adversarial Oracle 验证
- 矩阵测试实例化真实的 `FunctionBackedBattleResolver`（加载真实 `Only upV2.1` 工程），所有测试用例的权威真值一律由 `evaluateBattle()` 实算得出，禁止人工指定。
- 包含显式 `I602` 减伤反例：持有 `I602` 时 fast reject 必须返回 `unknown`，权威计算为 0 战损，绝不发生 false reject。

## 4. PR-5.22d1 Repair 1 — Capability Fail-Closed & Hard Contract Locking

根据代码复核反馈，对 Resolver capability 资格所有权与测量契约进行了最终加固：

1. **AutoActionResolver 彻底去战斗语义化**：
   - 删除了 `auto-actions.js` 中直接 import `classifyAutoBattleFastReject` 的依赖。
   - 当 `battleResolver` 未提供 `classifyAutoBattleFastReject` 方法时，**严格直接返回 `"unknown"`，彻底废除 generic classifier fallback**。
2. **FunctionBackedBattleResolver 显式 Opt-In 资格认证**：
   - 构造函数新增显式 `options.fastRejectClassifier` 或 `options.enableFastReject` 判定开关。
   - 未显式授权的 `FunctionBackedBattleResolver` 实例，`classifyAutoBattleFastReject(...)` 严格返回 `"unknown"`，禁止未认证工程/自定义解析器默认继承 vanilla fast-reject。
3. **Adversarial Matrix 负控制反例覆盖**：
   - 增加自定义未授权 resolver 负控制用例（返回 `unknown`）。
   - 增加未 opt-in 的 `FunctionBackedBattleResolver` 负控制用例（即使面对 Rule 1 零破防敌人也必须严格返回 `unknown`）。
4. **Profiler Parity 契约硬断言锁定**：
   - 在 `check-expansion-profiler-parity.js` 中新增硬守恒断言：
     - `scanShadowChecks === scanBattleResolverEvaluateCalls`
     - `scanShadowChecks === scanShadowDefinitelyReject + scanShadowUnknown`
     - `scanShadowDefinitelyReject === scanShadowTrueReject + scanShadowFalseReject`
     - `scanShadowTrueReject === scanShadowRejectedUnsupported + scanShadowRejectedNoDamageInfo + scanShadowRejectedNonZeroDamage`
     - `scanShadowFalseReject === 0`
   - 全套断言随单元套件持续运行并严格保证 0 false reject。
