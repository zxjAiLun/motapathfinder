## 1. 背景与优化目标

PR-5.22a 通过严格的顶层互斥 Self-Time 栈与子阶段只读剖析确立：
- **`stabilization` 是单一首要热点（PRIMARY HOTSPOT）**，在第一区域 30s 搜索中占总展开耗时的 **79.93%**（23.61s / 29.54s）。
- `stabilization` 内部由 3 大子阶段主导：
  1. `battleScan`: **8,629.23 ms**（占 stabilization 36.54%，占总展开耗时 29.21%）
  2. `hazardBuild`: **6,189.61 ms**（占 stabilization 26.21%，占总展开耗时 20.95%）
  3. `applyStep`: **5,683.66 ms**（占 stabilization 24.07%，占总展开耗时 19.24%）

本轮（PR-5.22b）按用户核准：**聚焦且仅聚焦于 `stabilization` 内部的 Scoped Hazard Reuse 与 Zero-Shift BFS Queue 等价优化**。
- **严禁改动**：搜索策略、DP 优先级、budget、剪枝语义、状态键、支配关系、评价契约或 `applyStep` 状态转移逻辑。

## 2. 优化实现细节

在 `shared-solver/lib/auto-actions.js` 中实施以下等价快速路径：

### 优化 1: 单次 Pass 作用域内的危害图按需复用（Scoped Hazard Reuse）
- 在单次稳定化 pass 中，`runAutoPickupPass` 构建一次 hazards。若未发生任何拾取转移（`changed === false`），将原 hazards 实例直接传递给随后的 `runAutoBattlePass` 复用，杜绝同一状态下连续两次全量构建危害图。
- 严格遵循不变式：**任何 pickup / battle / autoEvent 导致状态改变后，立即失效并按需重建危害图**。
- 在 `runAutoBattlePass` 目标循环中，对于首个目标（或状态未改变时的目标），跳过重复的 `evaluateAutoBattleTarget` 重新校验。

### 优化 2: `collectTargets` BFS 队列索引化（Zero-Shift BFS Queue）
- 使用 `head` 游标指针替代 `queue.shift()`，彻底消除频繁 BFS 队列带来的 O(N) 数组前移与 GC 垃圾对象分配。
- 缓存当前层的 `project.floorsById[floorId]` 与方向遍历常量，避免在热点 BFS 内重复做对象属性解析。
