## 1. 目标与方法学（Iteration 1 Repair 1 核心重构）

在 PR-5.24b Iteration 1 中，虽然引入了波次回滚调度雏形，但评审指出了关键缺陷：在遭遇 `rss-limit` 后缺乏“内存恢复证明”，导致调度器在高内存压力下强行启动后续 wave/depth 制造仅展开 1 步就退出的“假执行”假象，且失败 wave 的完整对象常驻于 `ledgerExecutions` 进一步阻碍了 GC 回收。

**PR-5.24b Iteration 1 Repair 1（Memory-Recovery-Gated Wave Replay + Compact Ledger）核心修正**：
1. **取消 `dp-search.js` 的 RSS 启动豁免**：
   - 彻底移除 `expansion === 0` 的 RSS 豁免逻辑；当检测到 `rssMb >= maxRssMb` 时，强制 GC 后若仍超标，立即设置 `memoryStoppedReason = "rss-limit"` 终止搜索；
2. **构建原生内存恢复门禁（Memory-Recovery Gate）**：
   - 在每个 wave 结束时，清理释放未成功的候选集与中间搜索缓存；
   - 执行权威内存重采样：当且仅当 `postGcRssMb < maxRssMb` 时，方判定 `memoryRecovered = true` 并允许推进后续 wave 或深度；
   - 一旦 `postGcRssMb >= maxRssMb`（内存恢复失败），立即 fail-closed 终止回滚流程并返回真实 `memoryExecution`，杜绝一切伪执行；
3. **压缩账本保留（Compact Ledger Retention）**：
   - 未成功的波次执行仅向 `ledgerExecutions` 提交轻量级诊断摘要（`toCompactLedgerExecution`），彻底解绑全量状态树与候选图引用，便于 V8 GC 回收；
4. **语义断言与多深度执行审计（Semantic Audit & Mechanism Hard Assertions）**：
   - 严格约束 `depthExhausted === true => depthStopReason === null`，禁止将 `resource-limited` 混淆为 `exhausted`；
   - 只有在 `anchorExpandedCandidates > 0` 且 `replaySegmentIds` 包含真实下游段时，才判定该深度完成实质执行。
