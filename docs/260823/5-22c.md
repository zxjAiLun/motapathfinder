## 1. 背景与归因契约修复（PR-5.22c1 Repair）

PR-5.22c 引入了对 `battleScan` 与 `applyStep` 的细粒度拆解。在 Agent 深度代码审查后，PR-5.22c1 修复了以下 4 项度量与归因契约缺陷：

1. **修复 `hazardBuildCalls` 双重计数 Bug**：
   - 旧实现中 `buildHazards()` 内部自身累加 `hazardBuildCalls`，而调用方又传参 `"hazardBuildCalls"` 作为 reason，导致常规构建被计数两次（原报告 ~100k+ 实际为 ~50k）。
   - 修复：仅在 reverification 时传递专有理由 `"hazardRebuildForBattleReverify"`，常规构建不传 reason，消除了双重计数。
2. **严格隔离 `battleScan` 与 `reverify` 计时（消除减法污染）**：
   - 独立拆分子阶段计时器：`scanBattleEvaluationMs`（收集阶段的战斗评估）与 `reverifyBattleEvaluationMs`（应用阶段重新校验）。
   - 严格互斥计算：`battleTraversalMs = battleScanMs - scanBattleEvaluationMs`；`battleEvaluationTotalMs = scanBattleEvaluationMs + reverifyBattleEvaluationMs`。
3. **细化战斗候选拒绝成因（Candidate Rejection Breakdown）**：
   - 拆分统计：`battleCandidateChecks`（进入候选检查总数）、`battleRejectedBlockedSpecial`、`battleRejectedNoResolver`、`battleResolverEvaluateCalls`（真正进入战斗求解器评估总数）、`battleRejectedUnsupported`、`battleRejectedNoDamageInfo`（打不过/无伤害数据）、`battleRejectedNonZeroDamage`（有伤害非0）、`battleAcceptedZeroDamage`（0战损接受）。
4. **收窄 Q3 结论范围（Workload-Scoped Observation）**：
   - 明确 `hazardRebuildWithoutInterveningMutation = 0` 为本次第一区域 workload 的实测观测结果，而非全局实现级杜绝证明（因本轮样本未触发 reverify 拒绝路径）。

## 4. 三大核心研究问题最终明确解答

```ini
PRIMARY_QUESTION_1 = Is battleScan dominated by traversal or battle evaluation?
VERDICT_1 = BATTLE_EVALUATION_DOMINATED (scanBattleEvaluation 8218.57ms vs battleTraversal 2119.81ms, ratio 3.88 : 1).
在 30s 搜索中，真实调用 evaluateBattle 达 17.38 万次，耗时 8.22 秒（占总展开耗时 27.81%）。
其中 95.73%（16.64 万次）最终因非 0 战损或无法战斗被拒绝，消耗了巨额的 cacheKey 构造、JSON.stringify 与 Map 查询开销。
```

## 5. PR-5.22d 建议路线：Safe Reject Probe & Battle Estimate Reuse

根据精确数据，PR-5.22d 建议采取**两阶段谨慎推进**：

### 阶段 1: Auto-Battle Safe Reject Shadow Probe
- 针对 95.73% 的被拒绝调用，设计轻量且证明绝对安全的静态前置判定谓词（例如怪物基础攻防 vs 英雄攻防静态无伤上下界）。
- 在生产环境中以 Shadow 模式运行，记录：
  - `fastRejected`、`truePositive`、`falsePositive`、`missedReject`。
  - 严苛门禁：**`falsePositive === 0`**（严禁误杀任何真实 0 战损目标）。

### 阶段 2: Battle Estimate Key 轻量化与 Accepted Estimate 复用
- 在 `collectAutoBattleTargets` 成功接受 0 战损目标后，直接向下游传递验证结果，消除应用阶段对 `evaluateBattle` 的重复调用或二次序列化。
