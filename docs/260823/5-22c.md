## 1. 目标与测量体系设计

PR-5.22b 实施 Scoped Hazard Reuse 与 Zero-Shift BFS Queue 后，第一区域展开吞吐量提升至 ~165 exp/s，但 `stabilization` 仍占总展开耗时的 **~79.6%**（~23.5s / 29.5s）。

本轮（PR-5.22c）**不做任何生产优化**，专门消除上一轮归因中的 **3 大盲区**：
1. **拆解 `battleScan`**：细分为 `battleTraversalMs`（BFS 遍历与坐标/瓦片扫描）与 `battleEvaluationMs`（`evaluateBattle` 计算与缓存操作），并记录 `battleTilesSeen`、`battleEvaluationCalls`、`battleEvaluationAccepted`、`battleEvaluationRejected`、`battleReverificationCalls`。
2. **拆解 `applyStep`**：细分为 `pickupApplyMs`（物品拾取应用）与 `battleApplyMs`（实际战斗状态应用），保留 `applyStepMs` 作为兼容总和。
3. **量化 Hazard 调用成因与残余重建**：记录 `hazardBuildCalls`、`hazardReuses`、`hazardInvalidationsAfterPickup`、`hazardInvalidationsAfterBattle`、`hazardRebuildForBattleReverify` 以及 `hazardRebuildWithoutInterveningMutation`。
4. **修复 BattleEstimate 归因指标**：补齐 `computeMs`、`estimatedMsSaved`、`stores`，彻底消除未定义的 `totalMs`。

## 4. 三大核心研究问题明确结论

```ini
PRIMARY_QUESTION_1 = Is battleScan dominated by traversal or battle evaluation?
VERDICT_1 = BATTLE_EVALUATION_DOMINATED (battleEvaluation 8332ms vs battleTraversal 2056ms, ratio 4.05:1). 
调用 16.3 万次 evaluateBattle 耗时 8.33 秒，拒绝率达 96.12%，其中大部分开销耗费在 cache-key 序列化、缓存 Map 查询与未命中计算上。

PRIMARY_QUESTION_2 = Is applyStep dominated by pickup or battle application?
VERDICT_2 = PICKUP_APPLY_DOMINATED (pickupApply 6007ms vs battleApply 138ms, ratio 43.3:1).
实际执行无伤战斗仅耗时 138ms，而物品拾取（resolvePickupAt 中的 item effects、status VM、levelUp 触发）消耗了 6.01 秒（占总展开 20.34%）。

PRIMARY_QUESTION_3 = How many hazard rebuilds occur without an intervening state mutation?
VERDICT_3 = ZERO_RESIDUAL_HAZARD_REBUILD (hazardRebuildWithoutInterveningMutation = 0).
5.22b 实施的 Scoped Hazard Reuse 与首目标去重已彻底消除了无 mutation 的重复重建，当前 4.73s 的 hazardBuild 完全来自拾取后（12450次）和战斗后（6336次）的真实状态变更失效。
```

## 5. PR-5.22d 决策树与优化路线明确建议

根据本次精确归因结论，排序优先级明确为：

1. **第一首要优化靶点（PR-5.22d 唯一主攻）：`battleEvaluation` 快速拒绝与轻量化（8.33s，占展开 28.2%）**
   - 16.3 万次调用中有 **96.12%（15.6万次）最终被拒绝**（因为不满足 0 战损）。
   - 当前即使被拒绝，每次调用也要执行昂贵的 `battleEstimateCacheKey`（包含 20+ 个属性的 `JSON.stringify`）和 `cacheGet`。
   - **优化方向**：
     - 极轻量静态 0 战损预判（例如怪物攻击力 vs 英雄防御力、怪物特殊属性静态表）。
     - 避免字符串化序列化的整数/快照 Cache Key。
     - 在 `collectAutoBattleTargets` 验证通过后，直接携带 `estimate` 结果供后续使用。

2. **第二候选优化靶点（后续考虑）：`pickupApply`（6.01s，占展开 20.3%）**
   - 静态纯属性宝石/血瓶的直通快速应用（Fast Path），绕过通用 VM 解释开销。
