## 4. 三大核心研究问题最终定论

```ini
PRIMARY_QUESTION_1 = Is battleScan dominated by traversal or battle evaluation?
VERDICT_1 = BATTLE_EVALUATION_DOMINATED (scanBattleEvaluation 8311.05ms vs battleTraversal 2168.69ms, ratio 3.83 : 1).
在 30s 搜索中，真实调用 evaluateBattle 达 16.80 万次（纯 scan），耗时 8.31 秒（占总展开耗时 28.12%）。
其中 96.14%（16.15 万次）最终因非 0 战损或无法战斗被拒绝，消耗了巨额的 cacheKey 构造、JSON.stringify 与 Map 查询开销。

PRIMARY_QUESTION_2 = Is applyStep dominated by pickup or battle application?
VERDICT_2 = PICKUP_APPLY_DOMINATED (pickupApply 5983.03ms vs battleApply 137.40ms, ratio 43.54 : 1).
完整的 auto-battle 状态应用（包含二次命中 cache 的 evaluateBattle 及状态修改）仅耗时 137.40ms；而 1.33 万次物品拾取（resolvePickupAt 中的物品效果、VM 解释与升级触发）耗时 5.98 秒（占总展开 20.25%）。

PRIMARY_QUESTION_3 = How many hazard rebuilds occur without an intervening state mutation?
VERDICT_3 = ZERO_RESIDUAL_HAZARD_REBUILD_OBSERVED (hazardRebuildWithoutInterveningMutation = 0 in this first-region workload).
实测中未观测到无 mutation 的重复危害图构建（因本批次 821 次 reverify 均未发生 reject）。合成反例测试已证实该计数器在 reverify reject 时能够正确检出非突变重复构建。
```
