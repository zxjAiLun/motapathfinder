## 问题与已有证据

PR-5.24b Final Authority（run `33380984827`）证明：intent-selected anchor wave 及其后续 downstream repair workload 在冻结 30s global wall 下占用足够预算，使后续 legacy waves 未能启动（waves 4→2、pending 18→32）。即：**发现"值得投资"的候选 ≠ 值得立即花一个完整 expensive repair wave 验证它**。PR-5.24b 已按 negative capability result 关闭（failure-intent 默认 OFF）。

本轮不再研究"谁排第一"，而是"给谁多少试错成本"。

## 范围与非目标

本轮范围（`segment-dp.js` 为主）：
- repair hypothesis = 一个 anchor wave + 其 downstream replay chain；
- hypothesis ticket（hypothesisId/depth/anchorSegmentId/anchorInputCandidateIds/nextReplaySegmentIndex/status/consumedWallMs/consumedExpansions/probeCount/lastProgress/stopReason）；
- bounded first probe（`adaptiveHypothesisProbeWallMs` / `adaptiveHypothesisProbeExpansions` 可配置；局部预算严格小于剩余 global；30s/50k/256-260 全局权威不变）；
- 两级状态：PROBE_PENDING / PROBE_COMPLETE_OR_GOAL（无自动追加预算策略）；
- `repairScheduling.events[]`（≤64，无 route/state dump）；
- fairness：Iteration 1 每个 hypothesis 至多一次 probe（合同锁定，不执行第二轮）。

非目标：调 failure-intent score、重新默认开启 failure-intent、OnlyUp hint、扩大全局合同、把 probe timeout 当 EXHAUSTED、新 Linux authority。

## 初始设计

- scheduler 默认 OFF（`enableBudgetedRepairScheduling === true` 显式 opt-in；unset = `9cebf03` 行为）；
- probe 预算经专用字段 `probeDeadlineMs` / `probeExpansionCap` 传递（不与 global `deadlineMs`/`maxExpansions` 合同混淆）；`runCandidateAttempt` 返回新 outcome kind `probe-limited`（候选/尾部队列保持 pending、不 retry、不触碰 globalBudget.stoppedReason）；wave 循环每执行后检查 probe 到期并 yield；
- wave 0（第一个 hypothesis）按生产顺序执行——在启用 scheduler 时它同样获得 bounded probe（order 语义保留：它仍是第一个被 probe 的 hypothesis）；
- `probe-limited` 是独立 waveOutcome（非 time-limited、非 exhausted、非 resource-limited）；depth 分类自然落到 incomplete；
- FOUND 仍优先立即返回；全局 wall/exp/rss stop 拥有最高权威。
