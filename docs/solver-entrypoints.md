# Solver Entrypoints

Hand-maintained overview of canonical solver entrypoints. `docs/js-inventory.md` is generated by `node tools/audit-js-files.js` and should not be edited by hand.

## Policy

- `shared-solver/` is the canonical solver implementation.
- `shared-solver/public.js` is the stable API for external agents; see `docs/public-api.md`.
- Public-layer write boundaries are documented in `docs/development-boundaries.md`.
- Region/segment canonical DP is the correctness path; `linear-main` / beam / macro search is auxiliary exploration. See `docs/solver-architecture.md`.
- Tower `solver/` directories are legacy copies and are frozen.
- Tower project/runtime JavaScript under `project/`, `libs/`, `extensions/`, `_server/`, and `main.js` is not solver code and should remain in place.
- New solver work should land in `shared-solver/`, `tools/`, or documented agent sandboxes, not inside tower `solver/` directories.



Shared solver:

```bash
npm run run:onlyup:segmented --prefix shared-solver
```

Unified region DP:

```bash

```

Public benchmark harness:

```bash
node benchmarks/run-agent.js --agent=agents/.templates/agent.json --suite=benchmarks/public/region-suite.json
```

## Shared-Solver Module Boundaries

These are the intended layers. Current files do not need to move immediately; new code should respect the boundary.

| Layer | Responsibility | Current Examples |
| --- | --- | --- |
| Core | Project loading, state simulation, expressions, battle/door/equipment/tool resolution, reachability, step simulation | `shared-solver/lib/project-loader.js`, `shared-solver/lib/simulator.js`, `shared-solver/lib/battle-resolver.js`, `shared-solver/lib/reachability.js` |
| Search | DP, segment graph, adaptive planning, search profiles, resource intent/lookahead/cluster logic | `shared-solver/lib/dp-search.js`, `shared-solver/lib/segment-dp.js`, `shared-solver/lib/adaptive-segment-planner.js`, `shared-solver/lib/resource-intent-scanner.js` |
| Replay | Route schema, route snapshots, live replay sessions, GUI playback | `shared-solver/lib/route-store.js`, `shared-solver/lib/route-snapshot.js`, `shared-solver/lib/replay-session.js`, `shared-solver/route-gui.js` |
| CLI | Thin command wrappers only; no core search logic should live here | `shared-solver/run-segmented-dp.js`, `shared-solver/run-adaptive-segment-dp.js`, `shared-solver/verify-route-live.js` |

Legacy tower copies of replay/search files, including `solver/route-gui.js` and `solver/lib/replay-session.js`, should be archived in a later phase after shared replay commands cover the same workflows.
