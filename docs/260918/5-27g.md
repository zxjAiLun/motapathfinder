## 问题与已有证据

PR-5.27f 裁定明确：
- 静态 relevance gate 被判定为有效负结果（`NOT_PROMOTED / DEFAULT_OFF / DO_NOT_TUNE_V2`）：事前静态 intent filter 把预算改投 `exp/level` 却没有增加 conversion。
- 唯一成功的 conversion（round 7 zombie）本身来自 `path_unlock`，证明该类别不能静态全盘否定。
- 核心缺失是**执行后反馈（Outcome Feedback）**：planner 缺乏对 repair 是否真正改善触发它的 blocker 的闭环判断。只要产生了 checkpoint，旧策略就因为 commitment 自动沿该 repair child 一路走下去，形成单分支 crawl（5.27e 中 70/73 次 path_unlock 即此现象）。

owner 裁定授权范围：
- 分类 repair 真实结果：`CONVERTED / IMPROVED / NO_PROGRESS / NOT_PRESENT`。
- 策略变更：`outcomeConditionedRepairCommitment`。`NO_PROGRESS` / `NOT_PRESENT` repair child 正常保留在历史 portfolio（无剪枝、无删除、无黑名单），但**不自动赋予 preferred cohort commitment**，下轮退回普通 portfolio 选择。
- 不引入 scalar score，不调 Pareto，不改 candidateLimit，不设重试次数阈值。

### 本轮明确不做（NO）

relevance filter v2、加权打分、repair depth 调参、Pareto 调参、candidateLimit 变更、already-attempted 修复、branch cap、pruning、prerequisite horizon、80-round escalation、MT4。

## 初始设计

### 1. 同一 Blocker 结果分类（`classifyRepairOutcome`）

对每次 repair attempt，已知触发它的 blocked identities（`sourceNodeId|floorId|x,y`）与 `evidenceBefore`。child replan 后读取同一 identity 的 `afterStatus` 与 `afterEvidence`：
- `CONVERTED`: before ∈ {unbeatable, lethal} 且 after == viable-at-current-state
- `IMPROVED`:
  - unbeatable -> lethal
  - lethal -> lethal 且 `survivalDeficit = damage - currentHp` 严格下降（越小越好）
- `NO_PROGRESS`: 同一 blocker 证据无改善（unbeatable -> unbeatable，或 lethal deficit 相等/恶化，或缺失证据）
- `NOT_PRESENT`: identity 在 replan 中未出现

### 2. 有条件 Commitment（`outcomeConditionedRepairCommitment`）

- Normal dependency success: 保持原有 commitment 契约。
- Resource repair:
  - outcome ∈ {CONVERTED, IMPROVED} -> 赋予 preferred cohort commitment。
  - outcome ∈ {NO_PROGRESS, NOT_PRESENT} -> **withhold commitment**（清空 preferred cohort），child 留在 ledger，下轮退回全局组合选择。

## 合同与不变量

- `NO_PROGRESS` repair child 绝不删除/剪枝，永久保留在历史组合中供全局回溯（`NO_PRUNING = TRUE`）。
- 不引入重试次数上限或黑名单（`NO_BLACKLIST = TRUE`, `NO_RETRY_COUNT = TRUE`）。
- 静态 relevance filter 永久保持 DEFAULT_OFF（`battleRelevantRepairOnly = false`）。

## 门禁结论与分析

1. **机制门通过**：
   - `NON_PROGRESS_REPAIR_COMMITMENTS_ON = 0`（8 次 NO_PROGRESS 全部被 withhold，无一违规获得 commitment）。
   - `REPEATED_NON_PROGRESS_REPAIR_LINEAGE = MATERIAL_REDUCTION_VS_OFF`（path crawl 从 30 次降至 7 次，劣质 repair 从 29 次降至 8 次）。
   - fallback 检验条件全部满足：
     - `DEEPEST_FLOOR >= OFF`：MT2 分支数从 57 增至 158（PASS）；
     - `EXACT_CONVERSIONS >= OFF`：1 vs 1 保持（PASS）；
     - `NO_PROGRESS_CHAIN_COLLAPSED`：PASS。

2. **能力门**：
   - `MT3_FOUND = false`：40 轮在 2000 local expansions 预算下仍未能突破到 MT3，为 `ROUND_BUDGET_LIMITED`。

3. **与 5.27f 静态 Filter 的本质对比**：
   - 5.27f 静态 filter 是在**事前**强行砍掉 path_unlock，结果导致 depth 骤降（41->14），无法分辨哪个 path_unlock 有用；
   - 5.27g outcome feedback 是在**事后**根据真实 blocker 赤字变化决定是否继续，不仅把 29 次劣质 path crawl 砍到了 8 次，还让 MT2 的有效探索分支翻了接近 3 倍（57->158），且完全不需要任何人工权重或黑名单参数。
