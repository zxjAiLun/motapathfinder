### 钥匙门与可行性判断

`GenericDoorResolver` 已有钥匙检查、消耗、移除门与 afterOpenDoor 事件入口，且接入 simulator。
用 `loadProject` + `isDoorTile` 检查 Only Up 的 MT1–MT4 **初始 map**：门图块均为 0，id 含 key 的图块均为 0。
这是初始图块检查，不覆盖事件动态生成或自定义名字的物品，不能扩展为整个塔绝无钥匙门机制。

因此：**支持开门语义 ≠ 已通过稀缺钥匙分配的实战**。当前能力结果不能外推到那类问题。
门会引入「现在消耗哪把钥匙、以后留给哪条路」的机会成本；更多资源未必能在不同地图结构间相互支配。
它不必使每个实例都更难，但会检验当前尚未建立的长期资源规划能力。

- 保留模拟/局部 DP/路线验证作为研究工具与人机协作底座，有已有结果支持；不是宣布完整产品已可用。
- 无手工路线、自动处理复杂真实塔并稳定长程推进：**尚未证明，高风险**。
- 「再添一个 heuristic 就能泛化」没有证据；「所有自动求解路线都不可能」也没有证据。
- 重构目标是降低定位和验证成本，**不是消除组合搜索的规模问题**。
