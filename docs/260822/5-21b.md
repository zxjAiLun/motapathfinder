## 背景与授权目标

PR-5.21a 确立了 MT1→MT6 第一区域直接闸门基线。在分析 per-state 内存和展开成本时，发现 `simulator.js` 中的部分 exact cache 存在状态混淆与内存驻留问题：
1. `getWalkReachability()` 按 `buildStateKey(state)` 缓存完整 reachability 对象，但 `buildStateKey` 不包含 route/accounting meta；且缓存完整对象导致大量 DOM/Map 引用驻留。
2. `enumeratePrimitiveActions()` 缓存包含 `travelState` 的完整 actions/battleActions，当不同 accounting 状态具有相同 `buildStateKey` 时，复用 cached actions 会污染后续转移的 accounting 或 travelState。
3. `route-store.js` 的 `resolveRecordedAction` 存在两种 fingerprint 方言差异（历史 `simulator.getActionFingerprint` vs `route-store` normalized fingerprint），且缺乏严格指纹匹配模式。

本轮（PR-5.21b）完成精确状态缓存修复、回归锁定、指纹方言双向对齐与严格模式支持，并单次复测第一区域闸门。

## 任务完成与实现细节

### 任务一：修 exact stateful caches
- `simulator.js`: `getWalkReachability()` 不再按 `buildStateKey` 读写完整 reachability 对象。
- `simulator.js`: `enumeratePrimitiveActions()` 不再缓存包含 `travelState` 的 actions/battleActions。
- 保留 `reachability` 与 `primitiveActions` 的 stats 槽位以兼容外部诊断，其 `hits`、`stores`、`size` 恒为 0。
- 保留并继续生效 `reachabilitySkeleton` cache 与 `battleEstimate` cache。

### 任务二：补锁定 regression
- 新增 `shared-solver/check-action-expansion-cache-correctness.js`：
  1. 构造 A/B 两个 `buildStateKey` 完全相等、但 `decisionDepth`/`rawRouteLength`/`autoStepCount`/`autoPickupCount`/`autoBattleCount` 不同的 state。
  2. 先枚举 A 模拟 warm cache，再枚举 B 并 apply battle/pickup（带 `travelState`）与 `changeFloor`，验证 successor 严格继承 B 的 accounting 增量。
  3. 双全新 simulator 固定 100-expansion 搜索一致性验证：`expansions=100`、`frontierSize=53`、`bestProgressKey` 与 `accounting` 完全一致；exact caches `size=0`/`hits=0`/`stores=0`，`reachabilitySkeleton` 出现真实 hit（57 hits / 43 misses, size=43），`battleEstimate` 正常生效（3241 hits / 1009 misses, size=1009）。

### 任务三：修 fingerprint dialect
- 保留 `simulator.getActionFingerprint` 历史格式不变。
- `route-store.js` 内 `resolveRecordedAction()` 同时计算 `normalizeAction` fingerprint 与 `simulator.getActionFingerprint(action)`，任一命中均计为 `fingerprintMatches=true`。
- 新增 `requireFingerprintMatch: true` 选项，启用时禁止 path/structural fallback 掩盖伪造或不匹配指纹，歧义 fail-closed。
- `check-route-store-exact.js` 新增覆盖 battle / changeFloor 两种方言格式以及伪造指纹严格拒绝用例。
- MT2 闸门启用 `requireFingerprintMatch: true` 严格模式，确认 `fingerprintMatchedDecisionCount=10`、`identityGradedDecisionCount=10`、`fingerprintFormatReconciled=true`。

### 任务四：纠正 5.21a checker 语义
- `check-onlyup-first-region-real-route-gate.js` 统一输出 `bestProgress`，不再将 `bestSeen` 命名为 `deepestReached`。
- `difficultyGuardBlocked` 断言调整为非负整数要求；保留 initial/search/replay 难度严格一致与 `searchChoiceUnresolved=0`。
- 文档明确标明多环境运行数据为环境样本，不再断言 RSS 与 wall 必然同时触顶。

### 关键发现与结论分类

1. **内存滞留修复彻底**：在之前的运行中，由于 exact reachability/actions 缓存了大量的中间状态引用，进程在 849~2706 次展开时即因 RSS 触及 256MB 上限而被强制终止。修复 exact cache 并消除 stateful retention 后，在达到 30s 墙钟时间时共完成了 4,832 次展开，Peak RSS 仅为 215.7 MB（低于 256 MB 上限，留有明显余量）。
2. **瓶颈转移**：当前的约束已由 RSS 内存触顶转为纯时间瓶颈（`bindingConstraint = "wall"`）。
3. **结论分类**：`CACHE_CORRECTNESS_FIXED / FIRST_REGION_STILL_TIME_BLOCKED`。
4. 按授权规则，本轮已完成 exact cache 正确性与 retention 修复，下一轮才允许评估展开成本与分支排序优化。
