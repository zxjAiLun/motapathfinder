## 背景与授权目标

PR-5.21a 确立了 MT1→MT6 第一区域直接闸门基线。在分析 per-state 内存和展开成本时，发现 `simulator.js` 中的部分 exact cache 存在状态混淆与内存驻留问题：
1. `getWalkReachability()` 按 `buildStateKey(state)` 缓存完整 reachability 对象，但 `buildStateKey` 不包含 route/accounting meta；且缓存完整对象导致大量 DOM/Map 引用驻留。
2. `enumeratePrimitiveActions()` 缓存包含 `travelState` 的完整 actions/battleActions，当不同 accounting 状态具有相同 `buildStateKey` 时，复用 cached actions 会污染后续转移的 accounting 或 travelState。
3. `route-store.js` 的 `resolveRecordedAction` 存在两种 fingerprint 方言差异（历史 `simulator.getActionFingerprint` vs `route-store` normalized fingerprint），且缺乏严格指纹匹配模式。

本轮（PR-5.21b）属于实现与 Go/No-Go 验证轮，严格禁止引入新搜索策略、不修改预算（50000 expansions / 30000ms / 256MB）、不使用磁盘/worker、不运行 5.19 checker、不解冻 static core/adapter。

## 任务拆解

### 任务一：修 exact stateful caches
- `getWalkReachability()` 不再按 `buildStateKey` 读取/写入完整 reachability 对象。
- `enumeratePrimitiveActions()` 不再缓存包含 `travelState` 的完整 actions/battleActions。
- 保留 `reachability` 与 `primitiveActions` 的 stats 槽位以兼容现有诊断，但其 `hits`/`stores`/`size` 恒为 0。
- 保留并继续使用 `reachabilitySkeleton` cache 与 `battleEstimate` cache。
- 不尝试浅改或复制 cached travelState。

### 任务二：补锁定 regression
- 新建 `shared-solver/check-action-expansion-cache-correctness.js`。
- 构造 A/B 两个 `buildStateKey` 完全相等、但 `decisionDepth`/`rawRouteLength`/`autoStepCount`/`autoPickupCount`/`autoBattleCount` 不同的 state；先用 A 枚举以模拟 cache warm，再用 B 枚举并 apply 同一可识别 action。
- successor 的 accounting 必须严格继承 B 并增加真实增量，不得回到 A。覆盖至少一个带 `travelState` 的 battle/pickup 和一个 `changeFloor`。旧实现必须能被该 regression 击穿。
- 运行全新 simulator 的固定 100-expansion 搜索，锁定 outcome、generated、registered、frontier、bestProgress exact key 与 route accounting 完全一致；exact cache size=0，skeleton 出现真实 hit，battleEstimate 保留。

### 任务三：修 fingerprint dialect
- 保留 `simulator.getActionFingerprint` 的历史格式不变。
- 在 `route-store.resolveRecordedAction()` 内，同时计算 normalized route-store fingerprint 与 `simulator.getActionFingerprint(candidate)`；recorded fingerprint 命中任一种都算 `fingerprintMatches`。
- 新增可选 `requireFingerprintMatch=true`，启用时禁止 path/structural fallback 掩盖错误 fingerprint，歧义仍 fail-closed。
- MT2 gate 使用 strict 模式。
- `check-route-store-exact.js` 覆盖 battle、changeFloor 两种格式及伪造 fingerprint 拒绝测试。

### 任务四：纠正 5.21a checker 语义
- `first-region` 输出使用 `bestProgress`，不得将 `bestSeen` 命名为 `deepestReached`；`deepestExpandedState` 如需输出独立列出。
- `difficultyGuardBlocked` 只要求非负整数，不冻结为 0；硬合同为 initial/search/replay difficulty snapshot 完全相等，`searchChoiceUnresolved=0`。
- 文档把 5 次数字明确标记为环境样本，不再声称 RSS 与 wall 必然同时触顶。
