## 0. 动机

5.25i 已经把失败形状量出来了：on-policy rollout 的换层里 **98.6% 是立即反向**，
MT2→MT3 前进楼梯只在 **2.0%** 的 MT2 decision 上可用。也就是说搜索预算大量花在
**不改变世界状态的可逆运输动作**上。

5.25a 的节点是 exact state，每个 `changeFloor` 都占用一个正式搜索层。本轮的唯一变化是：
**transport-only 动作不再消耗战略层，只有改变世界状态的动作才分支。**

## 1. 唯一 primary change

```ini
ONLY_PRIMARY_CHANGE =
  EVERY_PRIMITIVE_EVENT_IS_A_SEARCH_BRANCH
  ->
  TRANSPORT_ONLY_ACTIONS_FORM_LOCAL_CLOSURE
  AND_ONLY_STATE_CHANGING_ACTIONS_BRANCH
```

## 2. Transport 判定：由 simulated state delta，绝不按 action kind

```text
transportSignature(before) === transportSignature(after)  =>  transport-only
transportSignature(before) !== transportSignature(after)  =>  strategic
```

**忽略**：当前楼层、`hero.loc`(x/y/direction)、`route`、`notes`、`meta` 计数、派生的 `progress`，
以及导航/缓存类 flag（`__leaveLoc__`、`__frontierFeatures` 与其余 `__*`，但保留 `*_buff__`）。

**保留**：hero stats/equipment/followers、`inventory`、`flags`、**`visitedFloors`**、
`floorStates` 的 removed/replaced mutation、`triggeredAutoEvents`。

因此**第一次进入某楼层**（`visitedFloors` 变化）或换层触发 flag/item/firstArrive **绝不会被吞掉**。
实测：chaos MT1 起点上 `event@MT1:6,5#0:2` 被判定为 transport，逐字段 diff 确认它只改了
`hero.loc` 与 `meta.decisionDepth/rawRouteLength`；而首次到 MT2 的 `changeFloor` 是 strategic。

## 3. Closure 只做 successor generator

```text
expand strategic state S
  -> 沿 transport-only 动作做局部 BFS（per-closure exact-key 去重 + 上限）
  -> 收集通过纯运输可达的全部 exact transport states
  -> 收集这些 state 上的全部 state-changing actions
  -> 每个 state-changing action = 一个真实 search successor
```

```ini
MACRO_SEARCH_IS_CORRECTNESS_SOURCE = FALSE
SIMULATOR = LEGALITY_SOURCE
STRICT_REPLAY = FINAL_AUTHORITY
GLOBAL_STATE_MERGE = NONE      # 无 SCC canonicalization / quotient / dominance merge
HEURISTIC = NONE               # 无 scorer、无 learned policy、无手工子目标、无路线提示
```

单个 successor 的 macro chain 保存**完整 replay 序列**（transport summaries + strategic action），
FOUND 后展开回原始 action summaries 交给 strict replay。one-way 楼梯天然安全：closure 只沿
当前真实可用的方向走，从不假设能回来。

## 6. 解释（为什么没有收益）

- **抽象本身是对的**：4/4 micro 通过；实测吸收 30169 个 transport 动作、注册节点数约为
  control 的一半（26732 vs 54328 registry），内存峰值也更低（1337 vs 2048MB 撞顶）。
- **transport 判定不是瓶颈**：`signatureWallMs = 765ms` / 180000ms ≈ **0.4%**。
  所以“signature 太贵”这个假设被实测否证了。
- **真正的代价在 closure 被重复计算**：每个 strategic expansion 都重新做一次局部运输 BFS，
  于是导航工作被反复支付。TREATMENT 在自己 180s 内做了 14427 次 strategic expansion，
  却在 closure 内做了约 30169(absorbed) + 77400(strategic) 次 `applyAction`；
  CONTROL 在 143.9s 内做了 31879 次 primitive expansion。**在同等墙钟下，两臂都没能更深**，
  两者都只到 MT2。
- 结论（限定于该 contract）：

```ini
TRANSPORT_COLLAPSE_IS_CORRECT = TRUE
TRANSPORT_COLLAPSE_EXTENDS_REACH_AT_EQUAL_BUDGET = NOT_OBSERVED
MT3_WITHIN_180s_2GB_FOR_EITHER_ARM = NOT_REACHED
```

  也就是说：把“不改变世界状态的动作”从战略层里拿掉这件事，**在该预算下没有转化为更深的
  可达性**；它改善了内存/分支结构，但没有改善 reach。

### 6.1 运行可复现性 caveat

同一协议跑了两次：第一次 TREATMENT `strategic 20640 / absorbed 47629`，第二次
`strategic 14427 / absorbed 30169`，CONTROL 也从 `time-limit` 变成 `rss-limit`。
即 **iteration 数依赖机器负载、不可复现**（与 5.25k 的结论一致）；只有
“两臂均 NOT_FOUND、deepest 均 MT2”这个 verdict 稳定。本文表格以带 instrumentation 的
第二次运行为准。
