## 0. 这一轮唯一测试的变量

不再把“不能错删任何候选”当产品要求。

- **路线正确性必须严格保证**：真实状态、真实动作、真实回放。
- **搜索完备性明确放弃**：允许舍弃候选，失败只报告“预算内未找到”。

流水线全部沿用已有组件，没有发明新算法，也没有新建 solver framework：

```text
StaticSimulator
  → transport-collapsed strategic successors
  → autonomous dependency frontier
  → 5.25n existing resource/frontier ordering
```

唯一新增：

```text
PENDING CANDIDATES > CAP
        ↓
保留当前调度规则认为更应先扩的有限候选
        ↓
其余真正 DROP（不进 neutral 保底队列，不再回来）
```


Attempt 1 FOUND 就直接停，不跑 Attempt 2。两次都失败则关闭本候选，
不做第三次“稍微改一下 cap”。

## 2. 保留顺序：不新增 score

候选保留顺序直接继承已有信息：

1. goal / 已进入目标层
2. autonomous dependency-frontier guided candidate
3. 5.25n 已有的 prior-seen Pareto admission
4. 现有插入顺序 / neutral fairness

**没有**新增 `ATK=多少HP`、EXP 权重、钥匙权重、怪物人工阈值。

`resource-abstracted structural signature` 只作为 diversity grouping 或 telemetry，
**不能**写成安全 dominance proof。

## 3. strict replay 门禁加固

本轮开跑前把动作解析从非严格 `find` 改为 fail-closed 唯一解析（`lib/strict-replay.js`）：

```text
exact summary matches:
  1 → use
  >1 → 若所有候选 post-state key 完全相同，视为同一逻辑动作的别名 → use 第一个
       否则 → ambiguous, FAIL
if 0 summary matches:
  exact kind matches:
    1 → use
    >1 → 同上别名检查，否则 ambiguous, FAIL
    0 → diverged, FAIL
```

真正的成功 gate：

```ini
FOUND =
  SEARCH_REPORTED_GOAL
  AND EVERY_REPLAY_STEP_RESOLVES_UNIQUELY
  AND NO_REPLAY_TRANSITION_DIES
  AND REPLAY_FINAL_EXACT_KEY == SEARCH_FINAL_EXACT_KEY
  AND GOAL(REPLAY_FINAL_STATE) == TRUE
```

## 4. 硬门禁与严格回放

```ini
FOUND =
  SEARCH_REPORTED_GOAL
  AND EVERY_REPLAY_STEP_RESOLVES_UNIQUELY
  AND NO_REPLAY_TRANSITION_DIES
  AND REPLAY_FINAL_EXACT_KEY == SEARCH_FINAL_EXACT_KEY
  AND GOAL(REPLAY_FINAL_STATE) == TRUE
```

动作解析已按本轮要求改为 fail-closed 唯一解析（`lib/strict-replay.js` 的 `resolveUniqueAction`）：

- exact summary 匹配 1 个 → 使用；
- 匹配 >1 个 → 若这些动作产生的 **post-state key 完全相同**，视为同一逻辑动作的别名，取第一个；否则 `ambiguous-summary` FAIL；
- 0 个 summary 匹配 → 回退 exact kind，规则同上，>1 且 post-state 不同则 `ambiguous-kind` FAIL；
- 0 个 match → `diverged` FAIL。

## 5. 严格回放为何失败（关键发现）

失败点：`step-25-ambiguous-summary: battle:redPriest@MT2:4,7`。

在 `MT2:4,7` 对 `redPriest` 的动作，仿真器枚举出**两个** `summary` 完全相同的动作：

```text
kind=battle enemyId=redPriest target={"x":4,"y":7} path=["left","left","left","left"]
kind=battle enemyId=redPriest target={"x":4,"y":7} path=[...18 步绕行...]
```

两者是**同一个逻辑战斗**的两条不同走位路径。按新门禁，只有当两者产生**完全相同的后继状态**时才可视为别名。实测：

```text
非 hero 部分完全一致: true
hp / hpmax / atk / def / mdef / money / exp / lv 完全一致 (hp 3898)
唯一差异: hero.loc  x=5,direction=left  vs  x=3,direction=right
```

它们**不是别名**：战斗结束后英雄停在敌人的不同一侧。因此回放无法唯一重建搜索声称的终态，
门禁正确地 fail-closed。

```ini
AMBIGUITY_IS_GENUINE = true
ROUTE_SUMMARY_IS_INSUFFICIENT_TO_DETERMINE_TERMINAL_STATE = true
API_LIMITATION = route stores only action.summary, not the action fingerprint
```

这不是修剪导致的错误，也不是算法失败：**搜索确实找到了一条通往 MT3 的路线**，
但当前 `route` schema 只保存 `action.summary`，不足以在回放时唯一确定动作。

**这是本轮最重要的产物**：严格回放把一个“看起来成功”的结果挡在了门外。
旧门禁（动作可解析 + 存活）会接受它并把 MT3 记为 FOUND。

## 6. 为什么不跑 unbounded CONTROL

这轮是 capability qualification，不是 causal throughput study。
历史 unbounded 搜索在同一 MT1→MT3 task 上反复失败已足够作为上下文；
再耗 180s 跑 control 对产品 gate 不增加信息。
两次预算全部给 bounded candidate。

## 7. 结论

```ini
BOUNDED_CANDIDATE_SEARCH =
  FOUND_BUT_STRICT_REPLAY_INVALID
COMPLETENESS = ABANDONED
CORRECTNESS = STRICT
```

- cap=1024 的搜索确实**首次找到**了一条 30 步、抵达 MT3 的路线；
- 但该路线含一个 summary 不唯一的战斗步骤，严格回放拒绝接受；
- 因此**不能记为本轮能力突破**，只能记为“接近但未通过硬门禁”。

## 8. 诚实评估：这算不算能力突破？

**不算，但比此前任何一轮都更接近。**

已观测事实：

- cap=1024 状态下搜索**首次产出**一条 30 步、终局在 MT3 的完整路线；
- 此前 5.25b~n 的全部尝试在两臂均未产出任何抵达 MT3 的路线记录；
- 该路线的每一步在仿真器中都**可执行**（无致死、无分叉缺失）；

仍然成立的反面事实：

- 严格回放**拒绝**接受，因为第 25 步的动作不是唯一确定的；
- 两个候选动作导向**不同**的终局 hero 位置（x=5 / x=3），是真的不同状态；
- 两个候选除 `hero.loc` 外完全相同（HP/属性/进度/突变全等）；
- 因此路线本身合法，但“动作身份”未闭合 → **不能作为验证过的解**。

```ini
CAPABILITY_BREAKTHROUGH = NOT_ESTABLISHED
SEARCH_FIRST_REACHED_MT3 = OBSERVED_AT_CAP_1024
```

## 9. 需要决策的一件事（不擅自扩大范围）

本轮**没有**修改 `route` schema，也没有为了让这次的路线通过而放宽门禁。
按冻结契约，cap=1024 FOUND 但严格回放失败 → 停在这里，不跑第三次。

要让“动作身份”真正闭合，只有两条互斥的路：

1. **扩大 route 保存内容**：在 `macroChain` 里保存动作的 exact fingerprint，
   回放时优先按 fingerprint 解析（1 个匹配即用，0/>1 则 fail-closed）。
   这是 schema 变更，需要你授权。
2. **保持 schema，接受门禁拒绝**：即本轮结论维持
   `FOUND_BUT_STRICT_REPLAY_INVALID`，并把“summary 不足以唯一确定动作”
   记为已知 API 限制。

我不在未授权的情况下自行选择第 1 条。
