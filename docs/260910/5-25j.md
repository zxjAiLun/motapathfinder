## 0. 动机

5.25i 把失败形状拆清楚了（zero-training telemetry）：

```text
MT2 上 forward(MT2->MT3) 楼梯仅 30/1484 步可用 (2.0%)   <- 前置未解锁
但可用时 treatment 27/30 = 90% 选择 forward 并 landed MT3  <- 楼梯没选错
相邻换层事件互为反向 98.6%，exact-state revisit 69%        <- MT1<->MT2 乒乓
```

即：**缺的不是“在同层同类里选哪个”，而是“走到让前进楼梯解锁的状态”这一多步 prerequisite sequencing。**
这恰好是 graph search 的职责：5.25b 已有 exact-state registry、untried edge、cycle truncation、
transposition 与 UCT feedback；它失败的地方是 **uniform proposal 在 H96 下串不起足够的不可逆前置序列**
（terminal feedback 始终为 0）。

## 2. `lib/mcgs.js` 的最小改动（injectable proposer）

新增 `options.untriedActionProposer`，默认分支**逐字保留**原 uniform 逻辑：

```js
const rng = createSeededRng(seed ^ hashStringToInt(node.exactKey) ^ (simIndex * 2654435761));
if (untriedActionProposer) { ...只接受恰好属于 untried 的返回值，否则 fail-soft 回退 uniform... }
return untried[Math.floor(rng.next() * untried.length) % untried.length];
```

- RNG 仍是**按 (seed, exactKey, simIndex) 隔离的 untried-selection stream**，与 rollout stream 分离（C3）。
- 注入 proposer 只影响“先展开哪个 untried”，**不可能让任何合法动作永久不被展开**。
- 新增 telemetry：`expandedActionKindHistogram`、`deepestFloorId` / `deepestFloorOrdinal`。

**默认行为未变（已实证）**：

```text
1) 注入一个“逐字复刻 uniform”的 proposer → telemetry 与默认路径逐字段相同（bit-identical）
2) node check-mcgs.js 全量重跑 → witness status = STRICT_REPLAY_VALID，
   L3 verdict = NO_CAPABILITY_WINNER（与 5.25b 关闭时一致，无回归）
```

> 顺带观察（非本轮修复）：`auxProgressOf` 实际是 `floorOrder.indexOf(floorId) / indexOf("MT5")`，
> 由于 `floorOrder` 前缀含 `sample0..World`，MT1 得到 0.556 而非注释所写的 0.0。
> 本轮**不依赖** aux bucket 判定楼层，改用新增的 `deepestFloorId` / `deepestFloorOrdinal`。

## 3. Proposer 设计（`lib/learned-prior-mcgs-proposer.js`）

薄适配器，不定义新策略，复用 5.25h/5.25i 的冻结 hierarchical policy：

```text
untriedActions
  -> encodeFeaturesV2(state, action)        # V2 = V1 + changeFloorDestinationDelta
  -> residual model (same-kind supervised, 未重训)
  -> fixed TRAIN kind prior
  -> sampleKindThenAction(..., T = 1.0)     # 显式 two-stage
  -> selected untried action
```

- **只在 `untriedActions` 子集上重新归一化并采样**（不是“在全部 legal 上抽，抽到已试过再重试”）。
- 无 top-k / threshold：每个合法动作概率非零，learned prior 不能成为正确性权威。
- 效果：graph 自动形成 **policy-guided weighted sampling without replacement** ——
  policy 若先偏好反向楼梯，该 edge 被展开并登记为 tried；下次回到同一 exact state 时
  proposer 必须从剩余 untried 中选，graph 于是替 policy 保存 prerequisite alternatives。

### 4.3 单进程 vs 每搜索一进程（执行层修正，未改任何搜索参数）

首轮用“单进程顺序跑 8 次搜索”时，**seed 2 起全部 `iters=0`**：seed 52501 的 CONTROL 跑到
`rss=2051.7MB` 后，后续搜索的起始 RSS 已经是 **2051.9MB**（V8 不把已释放堆归还操作系统），
而 `maxRssMb` 是**进程级**上限 → 后续搜索在第一轮就触发 `rss-limit`。

处理：改为**每次搜索一个独立子进程**（父进程只负责构建冻结策略、用 JSON 传递
`{w1,b1,w2,b2,kindProbability}`，子进程重建模型并跑单次搜索）。
**UCT_C / LAMBDA_AUX / reward / graph identity / backup / cycle handling / H=96 /
rollout=uniform / 4 paired seeds / 180s / 2GB 全部未改**——只是让“2GB 上限”对每次搜索成立。
单进程变体的失败证据（`iters=0`, `rss=2051.9MB`）已如实记录在结果 artifact 与本文档。

## 5. 结论与 caveat

```ini
PR_5_25J = NO_MECHANISM_SIGNAL (STOP_AFTER_ITERATION_1_FOR_REVIEW)
GRAPH_MEMORY_CANNOT_CONVERT_LOCAL_POLICY_SIGNAL_INTO_PREREQUISITE_SEQUENCING = NOT_SUPPORTED
PROPOSER_DOES_CHANGE_EXPLORATION_ALLOCATION = OBSERVED
PROPOSER_IMPROVES_FLOOR_PROGRESS = NOT_OBSERVED
BUDGET_LIMITED = TRUE  (Run A: 8/8 rss-limit; Run B: 6/8 time-limit)
MECHANISM_VERDICT_STABLE_ACROSS_TWO_FULL_RUNS = TRUE  (16/16 searches reached only MT2)
```

- **PRODUCT_GATE / PRIMARY_MECHANISM_GATE 双双 FAIL**，且**连 MT3 都没有改善（0 vs 0）**。
  按 reviewer 预置口径：这不是“弱方向信号”，因此**不建议**继续调 T / H / hidden size 或继续训练。
- **proposer 确实改变了探索分配**（treatment 的 expanded 组合与 control 明显不同：
event 1667 vs 2723、battle 8102 vs 8876），但**没有转化为楼层进展**。
  一个可检验的解释：learned policy 的 kind prior 偏 battle，而 5.25i 已表明
  prerequisite 解锁更可能需要 event/pickup 类探索；即该 policy 对“解锁前置”这一用途是 OOD 的。
  （仅记录为解释候选，本轮不做验证。）
- **Budget caveat（不可省略）**：两轮完整运行的 `stoppedReason`/iterations **不一致**（Run A 8/8 `rss-limit`；
  Run B 6/8 `time-limit`）——即 **2GB 与 180s 两个预算交替生效**，且 180s 墙钟预算使迭代数
  依赖机器负载、**不可复现**。这不是模型/算法信号，**不作为证据**；可作为结论的只有
  “16/16 搜索均停在 MT2”。因此“无机制信号”是在预算受限条件下得到的，
  **不**直接推广为“proposer 在任何预算下都无效”；按协议本轮**不调预算**续杯。
- `cycleTruncatedRollouts` 仍极高（CONTROL 19669 / TREATMENT 16317），与 5.25i 的强循环倾向一致。
