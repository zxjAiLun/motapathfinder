## 2. Step 0：non-overlapping corpus inventory（本轮已完成）

### 2.1 方法

只做只读 inventory，不训练：

1. 扫描 `shared-solver/routes/fixtures` + `routes/latest` 全部 `*.route.json`。
2. 对每条 route 从 chaos MT1 初始状态做严格 replay；decision identity =
   `(buildStateKey(reconstructed state), chosenActionFingerprint)`。
3. 按 final floor 分成 TRAIN family（`final <= MT3`，排除 MT4/MT5 qualification family）
   与 HELD-OUT family（`final >= MT4`）。
4. 统计 held-out decisions 中 signature 不出现在 TRAIN union 的数量。

历史 key 三态（route 由多代 solver 写出，逐 route 自动探测）：

```text
legacy     hero.hp = null（保留 hpmax/manamax）
dominance  hero.hp/hpmax/manamax = null（当前 buildDominanceKey 形状）
canonical  不置空（当前 buildStateKey 形状）
# 三者都额外为 snapshot.floors 中每个 floor 补空 mutation（历史 serializer 行为）
```

复现命令与产物：

```bash
npm run check:learned-prior-corpus-inventory --prefix shared-solver
# -> shared-solver/routes/generated/learned-prior-corpus-inventory.result.json (gitignored)
```

## 3. 与 5.25c 的关系（Step 0 能说什么）

```text
Step 0 rules out insufficient available non-overlapping corpus
as the immediate blocker.

It does not yet prove that corpus diversity caused
the 5.25c negative result.
```

Step 0 只证明**仓库中存在比 5.25c 更多、且与 TRAIN 有大量 non-overlapping decisions 的
可 replay trajectory corpus**：

```text
5.25c 契约: TRAIN = MT2/MT3 only    ->  HELD-OUT 与 TRAIN 高度重叠  ->  max unseen = 10
5.25d 契约: TRAIN maxReached<=MT3   ->  HELD-OUT maxReached>=MT4   ->  max unseen = 78, distinct unseen = 154
```

它**尚未**证明 5.25c 的负结果“原因就是”数据契约——那要靠 Step 1 的训练结果来检验。
因此 `NEXT_BLOCKER = INSUFFICIENT_BEHAVIOR_CORPUS` **不成立**。

## 4. 注册 split 规则（review precondition，已修正）

评审指出原实现 `finalFloor <= MT3` 的推论不严格成立：solver 支持跨层返回 / `floorFly`，
一条 route 可以 `MT1→MT2→MT3→MT4→回到 MT3` 而 `finalFloor = MT3`，训练数据却已含 MT4 行为。
因此资格判定**必须按 replay 过程中实际达到过的最大 floor**，而非最终 floor：

```ini
TRAIN_ELIGIBLE    = start == CHAOS_MT1 AND maxReachedFloorOrdinal <= 3
HELD_OUT_ELIGIBLE = start == CHAOS_MT1 AND maxReachedFloorOrdinal >= 4
                    # near layer: maxReached == 4 (MT4)
                    # deep layer: maxReached >= 5 (MT5/MT7)
MT4_FIXTURES      = HELD_OUT
```

实现：`replayRouteFile` 记录 `maxReachedFloorOrdinal`（start state 与每次 apply 后的 state 取最大）；
driver 对 split 结果做 fail-closed 断言（任何 TRAIN route `maxReached >= 4` 即报错）。

```text
修正前 final-floor split : TRAIN 15 / HELD-OUT 9
修正后 maxReached split  : TRAIN 15 / HELD-OUT 9   <- 本 corpus 上数值不变
TRAIN maxReached 分布    : {MT2/max2: 4, MT3/max3: 9, MT2/max3: 2}
```

即：本 corpus 中**没有**任何原本进入 TRAIN 的 route 实际到达过 MT4+，所以原划分结果恰好相同，
但原推理并不成立；修正后该规则**由构造保证**成立。

### 5.1 P1：uniform-relative 改善不能作为超越 trivial base-rate 的学习证据

加入只依赖 TRAIN action-kind 频率（Laplace 平滑、**不含任何 state 特征**）的 baseline 对照：

```text
kind-prior baseline micro rank : 0.3399   <--- 优于 learned model
learned model micro rank       : 0.3821
uniform                        : 0.5000
```

严谨口径（按评审修正）：

```ini
UNIFORM_RELATIVE_PASS = TRUE
TRIVIAL_KIND_PRIOR_OUTPERFORMS_MODEL = TRUE
EVIDENCE_BEYOND_KIND_BASE_RATE = ABSENT
LEARNED_GENERALIZATION_SIGNAL = NOT_ESTABLISHED
```

即 `MLP < uniform` 且 `MLP > kind-prior` 只能证明：MLP 的 uniform-relative 改善
**不能作为超越简单 base-rate 的学习证据**；它**不能**证明 MLP 的全部行为“完全来自” kind bias
（模型可能同时学到了有用与有害的额外信号——这一点由 PR-5.25e 的 within-kind 诊断进一步检验）。

不得写 `GATE_PASS_IS_BASE_RATE_ARTIFACT = TRUE` / “pass 被 base rate 完全解释”（过强）。

### 5.2 冻结的 corrected gate（评审冻结，无需重训）

```ini
PRIMARY_NULL_BASELINE = TRAIN_ACTION_KIND_PRIOR
CORRECTED_GENERALIZATION_GATE = MODEL_MICRO_MEAN_NORMALIZED_RANK < KIND_PRIOR_MICRO_MEAN_NORMALIZED_RANK
EVALUATION_SET = EXACT_SAME_NON_OVERLAP_HELD_OUT_DECISIONS
```

两边数字已在同一 Step 1 实验中得到，故**不重新训练、不重跑 Step 1**：

```ini
0.3821 < 0.3399 = FALSE
BASELINE_RELATIVE_GATE = FAILED
```

只锁一个 null baseline（`TRAIN_ACTION_KIND_PRIOR`）；不再叠 majority-action / floor-prior /
distance-to-target 等一串 baseline。

### 5.3 因此不进入 rollout

`REAL_ROLLOUT = NOT_AUTHORIZED`、`PHASE_2_MCGS = NOT_AUTHORIZED`。
