## 5. Repair 1 — P1 kind-mass composition bug

### 5.1 缺陷

原实现：

```text
score(a) = log P(k) + r(a) - logsumexp(r in k) + log N_k
```

对某个 kind 求 softmax 前的总 mass：

```text
Σ_{a in k} exp(score(a)) = P(k) * N_k      <-- 错
```

即跨-kind proposal 实际是 `P(k) × 该 kind 的 legal action 数量`，多动作的 kind 得到
multiplicity advantage（例如 10 battle vs 1 changeFloor 时 battle 约 10 倍 mass）。
**因此 pre-Repair rollout 测的不是设计中的 factorized policy。**

driver 旧断言只检查“residual 打平时每个 action score == log P(k)”，会 PASS，
但没有检查真正需要的 **kind probability mass**；且旧 fixture 两个 group 的 `N_k` 相同，掩盖了问题。

### 5.2 修复

```text
score(a) = log P(k) + r(a) - logsumexp(r(b), b in same kind)      # 删除 + log N_k
```

于是：

```text
Σ_{a in k} exp(score(a)) = P(k)                     # 正确 kind mass
residual 打平时: score(a) = log P(k) - log N_k       # 按 prior 选 kind，kind 内均匀
```

rollout 改为**显式 two-stage sampler**（先按归一化 available-kind prior 采 kind，再在 kind 内采样；
control 内均匀 / treatment 内 residual softmax），在 `T=1` 下与修正后的 combined softmax 数学等价，
但语义更难被 group size 搞错。

### 5.3 Repair 的 structural invariant（不等 group size）

用 `battle N=3, changeFloor N=1`、`P(battle)=0.6, P(changeFloor)=0.2` 断言：

```ini
FLAT_RESIDUAL_KIND_MASS      = normalized available-kind prior   -> TRUE
NONFLAT_RESIDUAL_KIND_MASS   = SAME normalized available-kind prior -> TRUE
RESIDUAL_ONLY_REDISTRIBUTES_WITHIN_KIND = TRUE
TWO_STAGE_SAMPLER_MATCHES_SOFTMAX_KIND_MASS = TRUE
```

即 **residual 怎么变都不能改变任何 kind 的总 proposal mass**。这是本轮最重要的 regression。

### 5.6 解释（含对旧结论的撤回）

```ini
OFFLINE_FACTORIZATION_SIGNAL = OBSERVED

```

撤回旧表述：

> ~~“这段 rolling 的瓶颈当前不是 within-kind 选哪一个，而是 proposal distribution / horizon 本身。”~~

改为（Repair 后有依据的版本）：

> pre-Repair rollout 因为 kind-mass composition bug 而**不能**用于评价 factorized policy；
> 修正后 proper kind-prior / hierarchical policy 仍然无法在 96 步内推进到 MT4+。
> 而且 kind histogram 显示 **changeFloor 被大量选中**（control 1732 / treatment 2355）——
> 说明 rollout 卡住**不是**因为楼梯 kind 被 multiplicity 淹没。
> 因此瓶颈在**轨迹内**：要么 96 步 T=1.0 的 proposal 无法串联跨层不可逆进展，
> 要么 within-kind 选楼梯的偏好在 rollout 自身上访问到的 state 上不迁移。
> 现有证据**不足以**在两者之间裁决。

补充：treatment 的 changeFloor 选择远多于 control（2355 vs 1732）而 event 远少（19 vs 847），
说明 residual 确实显著改变了 kind 分配，但**没有**带来楼层进展。
