# PR-5.27b — Persistent Branch Portfolio Contract

Round began 2026-09-15. Baseline at round start: `dev == origin/dev`, `HEAD = bd76793` (PR-5.27a).

Authorized after external review of PR-5.27a. The review's core objection, accepted here: **"having a loop" is not
"having a planner."** PR-5.27a chained a single `previousExecution`, so it could only ever walk forward along one path.
This round replaces that with a persistent branch portfolio and re-tests the same questions.

```ini
ROUND  = PR-5.27b
KIND   = PLANNER_CORRECTNESS_ROUND      (not a capability round)
```

## 1. Four confirmed defects in `bd76793`

Each was verified in the code before being fixed, not taken on faith:

1. **No persistent branch portfolio.** `let previousExecution = null` then `previousExecution = nextExecution` per
   round. Real topology: `Execution0 -> Execution1 -> ...`. There was no older state to return to, so
   "the current portfolio is blocked" could not be distinguished from "the search is exhausted."
2. **The returned route was not a full initial→terminal route.** `local-dependency-executor` deliberately stores each
   checkpoint's `routeRecord` as the increment relative to *that local execution's* initial state
   (`recordFinalState.route = incrementalRoute(initialState, candidate)`), and the loop returned
   `terminalCheckpoint.routeRecord.decisions`. A terminal hit in round N would therefore have returned only the last
   local segment.
3. **The global expansion budget was not hard-clamped.** The round pre-check was
   `if (totalLocalExpansions >= maxTotalLocalExpansions) break;` while the local call still received the full
   `maxExpansions: localMaxExpansions`. With `global = 100`, `used = 90`, `local = 64` the loop could reach 154 before
   noticing. Phase 1 of 5.27a asserted only the accounting identity, never the bound.
4. **"Currently blocked" was reported as "globally exhausted."** `selection == null` only means no alternative in the
   *current* portfolio has a currently-executable leading prerequisite. Writing
   `no-remaining-unattempted-alternative` claimed a property of the whole search tree.

## 2. The contract implemented

```text
root branch (route-free initial state)
   |
   +-- open branch A ---+-- open branch A1 --+-- ... (exhausted when proven dead)
   |
   +-- open branch B  (still selectable after A1 dies)
```

Every round's selection is drawn from **all currently open branches**, not from the newest execution.

```ini
BRANCH_RECORD = {
  branchId, parentBranchId, state, exactStateFingerprint,
  cumulativeDecisions, status, depth, openedByRound, openedVia,
  attemptCount, attemptedExperimentKeys, exhaustedReason
}
STATUS_VALUES = open | exhausted
```

Design decisions that are contract, not incident:

- **Only a PROVEN dead end marks a branch exhausted.** A branch that merely cannot advance right now stays `open`,
  because whether it can advance is a function of the attempted-experiment set, which grows. An
  `attempted-but-inconclusive` outcome (local budget exhausted) also leaves the branch open.
- **`cumulativeDecisions` is explicit lineage**, not a hope that `checkpoint.state.route` happens to contain the
  prefix: `child.cumulativeDecisions = [...parent.cumulativeDecisions, ...checkpoint.routeRecord.decisions]`.
- **The returned route is the winning path**, i.e. the terminal branch's accumulated decisions. An abandoned branch's
  decisions must not leak into it.
- **Termination classes are now separated**:
  `CURRENT_BRANCH_BLOCKED` / `GLOBAL_PORTFOLIO_EXHAUSTED` / `LOCAL_BUDGET_LIMITED` / `ROUND_BUDGET_LIMITED` /
  `TERMINAL_GOAL_REACHED`. `global-portfolio-exhausted` is reserved for the case where no open branch can advance.
- **The hard budget** is `effectiveLocalBudget() = Math.min(localMaxExpansions, maxTotalLocalExpansions - spent)`,
  applied to round 0 as well, with the loop stopping when nothing remains.
- **A test seam** (`buildDependencyContext` / `executeLocalDependency` overrides, defaulting to the real modules) makes
  the loop's contract provable on a synthetic world whose shape is guaranteed. Waiting for the real tower to happen to
  produce a forced backtrack is not a contract test.

## 3. Phase 1 — synthetic forced-backtrack contract

`check-dependency-branch-portfolio.js` (`npm run check:dependency-branch-portfolio`). Scripted world:

```text
root
 |- A   (chosen first: larger survival margin)
 |   \- A1  -> proven dead end
 \- B   (reachable only by returning to root after A1 dies)
     \- B1  -> terminal
```

Observed execution order and outcome:

```text
R0  root        -> alternative-A   3 expansions   1 checkpoint
R1  branch-2(A) -> alternative-A   2 expansions   1 checkpoint
R2  branch-3(A1)-> alternative-A   1 expansion    0 checkpoints  => branch-3 exhausted
R3  branch-1(root) -> alternative-B   <- BACKTRACK to an older branch
R4  branch-4(B) -> alternative-B   2 expansions   1 checkpoint   => TERMINAL
```

```ini
BACKTRACK_TO_OLDER_BRANCH_OBSERVED                = TRUE   (16 backtracks on the real tower, see §4)
SELECTED_BRANCH_PARENT_IS_NOT_PREVIOUS_ROUND      = TRUE
FAILED_BRANCH_NOT_RETRIED                         = TRUE
SIBLING_BRANCH_SELECTED                           = TRUE   (chosen branch does not descend from the dead end)
EXPIRED_DEAD_END_MARKED_EXHAUSTED                 = TRUE
RETURNED_ROUTE_STARTS_AT_ORIGINAL_INITIAL_STATE   = TRUE
RETURNED_ROUTE_INCLUDES_EVERY_LOCAL_SEGMENT       = TRUE
FULL_STRICT_REPLAY                                = TRUE
TERMINAL_GOAL_REACHED_AFTER_FULL_REPLAY           = TRUE
```

The returned route is `[root->B, B->B1]` — the winning path, with the abandoned `A` branch correctly excluded.

**This phase caught a real defect.** The first implementation wrote `Array.isArray(checkpoint.routeRecord)` and read
`checkpoint.routeRecord.decisions`. `routeRecord` is an **object**, so the guard was always false and every branch
silently accumulated `[]` — the stitched route came out empty even though the lineage was correct. Without the
synthetic world this would have surfaced only as "the terminal route looks short", long after a capability claim.

Two fixture-fidelity bugs were also found and fixed in the micro itself, worth recording because they are the same
class of error:

- The synthetic states initially differed only by `floorId`, so `buildStateKey` collapsed them and the dedup under
  test was measuring the fixture. States now vary in hero stats.
- The stub executor initially ignored *which* alternative had been selected and always ran the state's first scripted
  entry, so "backtrack and take a different alternative" could never happen. It now honours the controller's
  reordering, which is what the real executor relies on.

## 4. Phase 2 — hard global budget ceiling

Same file, second scenario: `maxTotalLocalExpansions = 5`, `localMaxExpansions = 4`.

```ini
OBSERVED_TOTAL_LOCAL_EXPANSIONS = 5            (round 0 spent 3, round 1 was granted only 2)
TOTAL_LOCAL_EXPANSIONS_WITHIN_BUDGET = TRUE
TERMINATION_REASON = global-local-expansion-budget-exhausted
GLOBAL_EXPANSION_BUDGET_IS_A_HARD_CEILING = TRUE
```

Before the fix the same configuration could have reached 7. The assertion is the **invariant** (`each round's grant <=
min(localCap, globalRemaining)`), not a magic number, and the accounting identity is still asserted separately so the
bound check is not a substitute for it.

## 5. Phase 3 — real MT1→MT3

```ini
GOAL        = floorReached(MT3)
INITIAL     = fresh CHAOS MT1
MAX_RUNTIME = 0
BUDGETS     = 20 rounds / 2000 global local-expansions / 200 per round / candidateLimit 8
```

```ini
MT3_REACHED        = FALSE
VERDICT            = DEPENDENCY_FEEDBACK_LOOP_UNKNOWN_UNDER_THIS_BUDGET
TERMINATION_REASON = global-round-budget-exhausted
TERMINATION_CLASS  = ROUND_BUDGET_LIMITED
ROUNDS             = 20        (all productive)
TOTAL_LOCAL_EXPANSIONS = 80
ATTEMPTED_KEYS     = 21
EXPERIMENT_KEY_REUSE = 0
BRANCHES           = 130 open, 0 exhausted
BACKTRACKS         = 16
FINAL_FLOOR        = MT1
```

A doubled budget (40 rounds / 4000) changes nothing qualitatively: **40 rounds, 115 expansions, 211 branches, all MT1,
still zero exhausted**, `maxBranchDepth = 5`.

**This is a different and better-localized result than PR-5.27a's.** The retracted 5.27a claim was that the loop stops
because it only ever schedules `prerequisites[0]`. What the corrected loop actually shows:

```ini
LOOP_STOPS_EARLY_DUE_TO_A_BLOCKED_PORTFOLIO = FALSE     (it now runs the full round budget)
ROUNDS_ARE_ALL_PRODUCTIVE                  = TRUE      (every round advances a checkpoint)
PROGRESS_IS_ACCUMULATING                   = TRUE      (cumulative decisions reach depth 10; hero stats improve)
EXHAUSTION_SIGNAL_IS_NEARLY_ABSENT          = TRUE      (1 of 21 attempts proved exhaustion)
BRANCH_PROLIFERATION_WITHOUT_COMMITMENT     = OBSERVED  (130 open branches by round 20; depth histogram {0:1,1:3,2:7,3:60,4:59})
MT1_CONFINEMENT                             = OBSERVED  (211/211 branches on MT1)
```

So the planner now genuinely backtracks and genuinely stitches routes, and the remaining blocker is that it **fans out
instead of committing**: each round spawns ~6 new open branches and almost never disproves one, so the open portfolio
grows without bound while the search stays on MT1. The prerequisite-horizon question is now *testable* — it is no
longer confounded by "the loop cannot backtrack at all" — but it is **not** the measured blocker this round.

```ini
SINGLE_PREREQUISITE_HORIZON                = STILL_AN_OBSERVED_LIMITATION
SINGLE_PREREQUISITE_HORIZON_AS_ROOT_BLOCKER = NOT_ESTABLISHED (unchanged from 5.27a's retraction)
NEW_MEASURED_BLOCKER_CLASS                  = BRANCH_PROLIFERATION_WITHOUT_COMMITMENT_OR_EXHAUSTION
```

## 6. Honest scope and non-claims

```ini
PREREQUISITE_CHAIN_EXECUTION            = NOT_CHANGED
PLANNER_SCORING                         = NOT_CHANGED
FEASIBILITY_HEURISTIC                   = NOT_CHANGED
TRANSPORT_COLLAPSE                      = NOT_TOUCHED
RETENTION / GUIDED SCHEDULER            = NOT_TOUCHED
MT4                                     = NOT_RUN
CAPABILITY_CLAIM                        = NONE
```

- Phase 3 is a **MISS** and is reported as one. No capability claim follows.
- The branch-portfolio growth is **not** presented as acceptable; it is the measured new blocker. No pruning policy was
  added, because adding one now would repeat the 5.26 mistake of tuning a mechanism before the contract is proven.
- `check-dependency-feedback-loop.js` (5.27a's check) was updated where it asserted a field that no longer exists
  (`repeatedCheckpointStateCount`, replaced by branch-level accounting). Its seven properties still pass.
- The `routeProvenance.localSegmentCount` in Phase 1 counts accepted rounds, which includes the abandoned `A` shot;
  `cumulativeDecisionCount` is the winning-path length. The two are deliberately different numbers.
