**同一问题已经在 5.32d 被审过**：旧文档的 P14 是 seed 后第十四个决策，route decision **43**（数组 index 42），即本轮 Control 首个缺失的 P43。不是另一个 skeletonCaptain 点，故不重新跑 32k。5.32d 报告 SHA `9fefbcaddd10a2375acc448861d1d5880bc594ad323e4c827129d2474ca6dde7` 已核对；将原 `audit-suffix.js` 仅改输出文件路径、对冻结 solver/tower/observer capture/witness **重新执行搜索后离线 strict replay**，生成文件与原报告 **SHA 完全一致**。这里没有重新运行 tower search，也没有把 witness 交给搜索。

**I1 当前 Control 对齐**：独立流式扫描 5.32h Control 的 181,653 条事件，raw SHA `5de4c90e0a032a57922958946a7c4f11508e8f92354ed3b9a63b32dba5bf13d2`。每条仅去掉采集器新增的 `continuationOrigin:null` 后得到 `da02e10e4c66ace160b9c9b94306fbc249321b0ca7aa1b5b36d99b6d92a237d7`，与 5.32d 的 targeted-observer Control 原始 events 字节 hash 精确一致。相同 seed/initial/problem、32k/0 goal，故旧 capture 对应当前 Control 的同一条实际事件序列；不同 solver digest 不被偷换为字节级代码等同。

**I2 实际生成/拒绝**：P42 post / P43 pre exact key `927381556431c13c0c0197eb2b39474a502a2f88480709fbcdee5d13ca994e7b`；当前 Control node 81710 (parent 2632) 在 expansion 31,356 pop。离线 canonical simulator 执行 `battle:skeletonCaptain@TS13:5,6`，得到 HP 2,667、P43 post exact `ee902262dd212915db41ad767c8b831853088f51fc1bc7e83537789d1e97b6f0`、DP key SHA `e0b3337ceaa6a4922a27e1dcf528e5c6fc8d37518a9cae38883691fe7bb18edd`。现行事件流中该 exact post **生成并被拒两次**：第一条直接来自 81710（event line 178,473），第二条来自另一源 node 2640（line 179,213）；没有 insertion/pop/accepted-then-replaced。旧 targeted capture 对两次拒绝都指向 **同一 incumbent node 1339**（parent 1333），DP key 相同；HP 2,761，比候选高 94，depth/route-length 同，完整 state diff 仅 HP。1339 于 expansion 399 入队、17,967 已展开。不是“P43 根本未生成”，也不是“上楼时清除了已有候选”。
