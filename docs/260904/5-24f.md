## 问题与已有证据

PR-5.24e 终审（Real Run 2）确立了关键事实与科学瓶颈：
1. **反常识投资历史生成与准入完全成立**：
   - 准入架构成功生效（`REAL_COUNTERFACTUAL_FALLBACK_ADMISSION = PROVEN`），Primary 8 优先试探全部无进展后，CF 顺利打通准入且次级正常分支严格延期；
   - 真实 OnlyUp 地图上成功通过规范 DP 真实物化出扣 295 HP 换 120 MDEF / 1 EXP 等 2 个 intent，产生 16 条全新非保守前史（`CANONICAL_COUNTERFACTUAL_REALIZATION = PROVEN`）；
   - 前 6 条真实 CF 历史实质执行了下游 probe（`COUNTERFACTUAL_HISTORIES_EVALUATED = PROVEN`），均未观察到 measurable progress。
2. **核心瓶颈不是扩展数或内存，而是单位搜索工作的墙钟成本（Wall-Time Amortization）**：
   - 全局扩展仅消耗 3,857 / 50,000（仅约 7.7%）；
   - 内存峰值仅 343.2 MB（远低于 2048 MB 安全熔断器）；
   - 全局墙钟消耗 29,528 / 30,000 ms（近 100% 吃满）；
   - 导致 Intent 1 产出的 16 条真实 CF 历史中，后 10 条因全局墙钟耗尽根本未能获得探测试算（`probeCount = 0`）；
   - 根因定位：当前 `isolated-process` 模式对每个 segment 执行均调用一次独立的 `childProcess.spawnSync("node ...")`，在 Windows 环境下每次 spawn 都伴随高昂的进程创建、V8 初始化、工程文件重复加载与临时文件 IPC 开销（每次 probe 耗时 ~2.5~3.8s，其中实际搜索仅占极小部分）。

## 范围与非目标

本轮范围：
- 在 `shared-solver/lib/isolated-segment-executor.js` 中新增批处理接口：`executeIsolatedSegmentBatch({ simulator, jobs, config, isolatedRuntimeDescriptor })`；
- 第一阶段仅针对**天然独立的一轮首轮探测试算**（Primary Normal Tranche, Counterfactual History First-Probe Tranche, Secondary Normal Tranche）实施批处理调用，摊销子进程创建与工程加载开销；
- 共享全局权威预算（One Batch Global Authority）：批处理内部共享同一个全局预算，各 job 顺序执行并依次扣除消耗；若全局超时或扩展耗尽，剩余未启动 jobs 严格返回未执行，绝不伪装 exhausted；
- 独立局部试探预算（Independent Local Probe Authority）：每个 job 独立享受 200 exp / 2000 ms 的局部上限；
- 严格状态隔离（State Isolation）：工作子进程一次性加载工程定义与不可变结构缓存，每个 job 的输入状态严格重新克隆/反序列化，禁止跨 job 共享可变状态、地图突变、flags 或 DP 缓存；
- 规范等价性与门禁测试：编写 `shared-solver/check-isolated-batch-equivalence.js`。

非目标：
- 严禁重构父进程同步架构为 async；
- 严禁增加全局预算（30s / 50k / 2048MB 保持不变）；
- 严禁修改 200/2000 probe 或 400/4000 continuation 预算；
- 严禁修改 candidateLimit、backtrackCandidateLimit 或准入顺序；
- 严禁引入 multi-step CF；
- 不 batch 跨轮决策、anchor 生成、intent 物化或 continuation。

## 初始设计与门禁 (G25)

| Gate | 测项 | 通过条件 |
| --- | --- | --- |
| **G25-A** | 规范等价性 (Direct Batch Parity) | 相同输入下，批处理结果与单进程逐次执行结果完全一致（`found`、`failureClass`、`searchComplete`、`consumedExpansions`、`buildStateKey` 100% 对齐） |
| **G25-B** | 全局中断权威 (Global Stop) | 批处理中途全局预算耗尽时，已执行 jobs 正常报告，剩余未执行 jobs 严格标记未执行且 `searchComplete = false`，绝不虚假完备 |
| **G25-C** | 跨 Job 状态隔离 (State Isolation) | Job A 大幅修改 HP/flags/mutations 后，Job B 从独立初始状态启动，其输出 stateKey 与单进程全新环境下的 Job B 完全一致，无任何状态污染 |
| **G25-D** | 墙钟性能微基准 (Microbench Wall-Time Amortization) | 在 4 个 50-exp 独立 probe 场景下，批处理子进程数从 4 降至 1，加速比 $\ge 2.0x$，遥测显式标注 `speedupLabel: "MICROBENCH_SPEEDUP"` |
| **G25-E** | 细粒度遥测 (Telemetry Completeness) | 暴露 `isolatedBatch: { jobsRequested, jobsExecuted, processLaunches, processWallMs, searchWallMs, serializationWallMs }` |
| **G25-F** | 生产首轮探测试算接入 (Production Wiring) | 生产路径 `runMilestoneGraph` 中 primary normal 批次执行调用 `executeIsolatedSegmentBatch`，在恰好 1 个子进程中完成全批次试探 (`processLaunches === 1`) |
| **G25-G** | 每 Job 墙钟独立重基 (Per-Job Wall Rebase) | 批处理子进程内每个 job 从自身启动时刻 (`jobStartWallMs`) 重基其局部 `probeWallMs` 截止线，各 job 顺次享有独立且饱满的探测试算时长 |
| **G25-H** | 生产等价性 (Production Equivalence) | 生产 `runMilestoneGraph` 在单进程逐次 Arm A (`disableBatchFirstProbe: true`) 与批处理 Arm B (`disableBatchFirstProbe: false`) 下产出完全一致的工单 ID、状态、停机原因、探测试算数与进展分类 |
| **G25-I** | 生产路径中途全局停机 (Global Stop Mid-Batch Production Path) | 生产路径批处理执行中途耗尽全局扩展数时，已执行 jobs 正常生成结果，未执行 jobs 严格保持 `PROBE_PENDING`，`depthExhausted = false`，最终结果绝不报告 `EXHAUSTED` |
