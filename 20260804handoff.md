## 当前核心合同

### SolverModel

`shared-solver/lib/solver-model.js` 是求解器维护字段的声明入口。模型优先级为手动模型、preset、自动建议、legacy fallback；当前公开 v1 只接受已实现的字段语义。

Only Up 的显式模型关闭 `hpmax`、`mana`、`manamax`、`money`、`followers`，保留 HP dominance 以及战斗、成长、装备相关 key 字段。disabled 字段不能被补零后伪装成已维护字段，也不能作为 objective 引用。

### ObjectiveSpec

实现位于 `shared-solver/lib/objective-spec.js`，schema 为 `motapathfinder.objective-spec.v1`。当前支持：

- `clear`：只要求满足 RegionSpec goal，可使用终局 tie-breaker。
- `max-final-hp`：先满足 goal，再最大化 `hero.hp`。
- `maximize`：在已满足 goal 的终局上最大化受支持的数值字段。
- `maximize-score`：终局专用加权数值项，不能参与中间状态淘汰。
- `lexicographic`：按声明顺序比较多个目标/比较器。

Objective 字段在 RegionSpec normalize/preflight 阶段绑定 SolverModel 验证。disabled、snapshot-only、未知字段、非数字字段、非法 weight 以及搜索不保留的字段必须在搜索前以结构化错误拒绝：

- `hero.<field>` 只有 `key` mode 字段可优化；`value` mode 字段（如 `hpmax`/`manamax`）拒绝优化（`OBJECTIVE_FIELD_NOT_SEARCH_PRESERVED`）。
- `hero.hp` 只能 max（或 score 中非负 weight）；min 方向与 same-key HP dominance 冲突（`OBJECTIVE_CONFLICTS_WITH_DOMINANCE`）。
- `decisionDepth`/`route.length` 只能 min；max 方向被拒绝（`OBJECTIVE_INVALID_DIRECTION`）。
- `inventory.*` 进入 DP identity，两个方向都安全。
- 负 `hero.hp` weight、正 depth/route weight 被拒绝（`OBJECTIVE_NON_MONOTONE_WEIGHT`）。
- score descriptor 的 `direction` 会翻转有效权重符号：校验使用 `effectiveWeight = direction === "min" ? -weight : weight`。`min score + 正 HP weight`、`min score + 负 route/depth weight` 被拒绝；`min score + 负 HP weight`、`min score + 正 route/depth weight` 是安全等价形式并被接受。
- descriptor `direction` 严格限定为 `max`/`min`。

ObjectiveSpec 只决定合法终局候选“哪一个更好”，不决定搜索过程中“删掉谁”。以下语义保持不变：

- DP key；
- 相同 key 内的 HP dominance 和代表状态选择；
- action enumeration / legality；
- state projection；
- milestone planning、adaptive repair、容量和默认策略。

`searchDP` 提供纯终局钩子 `goalStateComparator`，只用于 goal archive 排序、`bestGoalNode`、goal archive audit 和 final goal result；不进入 `bestByKey`、`isBetterForSameDpKey()`、agenda、action ranking 或中间剪枝。`searchSegmentDP` 只在 objective 命中的最后一个 segment 传入 `(left, right) => -objective.compareCandidates(left, right)`，非终局 segment 保持旧 comparator。

由于 production simulator 在搜索时用 `storeRoute:false`（`state.route` 保持为空、只有 `decisionDepth` 增长），`bestGoalNode` 入队时不能按 route-length 判定。搜索结束后会先为 active goal nodes 重建 route，再用 objective comparator 排序，并从归档首位重新确定 `bestGoalNode`，保证 `bestGoalState`、`goalState`、`result.route` 一致指向目标最优状态。

`validateObjectiveSpec()` 走完整 compile 路径，因此直接调用公开 validator 的 SolveTask / Launcher / 第三方调用者也能捕获 Objective-Search 兼容性错误（field mode、dominance 冲突、score direction、direction 合法性），与 compile 路径保持一致。

### Proof claim

- `clear` 找到路线时可报告 `goal-found`。
- 含最大化项的目标只有在 action scope、预算、搜索耗尽条件完整，并且 goal archive / milestone frontier 没有截断时才能报告 `bounded-optimal`。
- goal archive 被 `goalSkylineLimit` 截断、milestone frontier 被 `candidateLimit` 截断、archive 未按 objective comparator 排序、或目标引用了 DP 不保留的字段时，即使 action set 完整也只能报告 `bounded-optimal-within-retained-frontier`。
- first-goal 强停、预算耗尽、action trimming、unsafe stop 或不完整 action scope 时只能报告 `candidate-only`。
- objective claim 现在包含 `goalArchiveObjectiveAware`、`goalArchiveTrimmed`、`milestoneFrontierTrimmed`、`searchPreserving` 字段。
- 这意味着“找到一条路线”不等于“证明目标最优”。
